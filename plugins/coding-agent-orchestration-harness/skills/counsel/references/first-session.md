# First Session in a Repository

Followed once per repository: when the Repository Reference Documents section of `docs/coding-agent/rules/common.md` has no line recording Counsel's seat and that its relays are admitted. Once that line is there, a Counsel session finds it at open and does nothing beyond the open-time steps.

## Setup

- If `docs/coding-agent/rules/common.md` does not exist, setup has not run. Say so and offer it. The owner gives setup to the Orchestrator session directly, as the first request there; it is not relayed.

## The seat

- Counsel's seat on the peer channel, distinct from the Orchestrator's, is taken at open by the step in the skill's open-time steps; `<repository>` in its name is the repository's name.
- A session that finds itself on the Orchestrator's seat moves to its own before it sends anything.
- Without a peer channel there is no seat to take.

## Admission of relays

- Setup's report offers the standing approval that admits Counsel's relays as the owner's, naming Counsel's seat. The owner's yes in the Orchestrator session has it recorded in `common.md`: the Standing Approvals entry, and the line in Repository Reference Documents that records the seat and that relays are admitted.
- Admission is recorded in `common.md` and nowhere else. A note the Orchestrator keeps for itself is not a place the harness reads.
- Where setup has run and no such entry is in effect, ask the owner to make the statement in the Orchestrator session before the first relay, or to accept such an entry once; after either, the owner does not need to type into the Orchestrator session.
