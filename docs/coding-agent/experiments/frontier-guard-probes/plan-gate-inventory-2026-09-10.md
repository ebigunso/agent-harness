## Decision fork (comparison only; no proposed fix wording)

The choice is whether an ordinary request such as “add X” approves the execution plan the agent will subsequently produce, or whether approval must attach to a presented plan (unless the user explicitly waives that approval step). Under the first interpretation, the Orchestrator may research, draft a plan, and begin implementing it in the same session without showing the plan to a human first; the request itself supplies that authorization. Under the second interpretation, the same request authorizes planning, the Orchestrator presents the plan and ends the turn, and implementation waits for explicit approval of that presented plan or an explicit user waiver identifying the approval step. In a headless session or while the user is silent, that second interpretation leaves execution unauthorized in the absence of such prior approval or waiver; elapsed time cannot supply it. This fork concerns plan-mode execution authority, not triviality classification, independent validation/Reviewer gates, or goal-mode envelope ratification.
