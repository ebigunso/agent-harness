**Findings**

1. **`customer.cpp`, `decode()` — business rule (`|| row.debt > 10000`) embedded in the row converter.**
   - *What's wrong:* The task is "decode customer debt from rows." The converter's job is representation mapping: `Row` → `Customer`, field for field. The added clause is a suspension policy ("debt over 10,000 cents ⇒ suspended"), which is a domain rule, not a decoding concern.
   - *Why it matters:* Per the reviewer notes, suspension is an explicit domain action. With this change, merely loading a row silently flips `suspended` to `true` for any customer over the threshold — a read path now mutates account status, with no audit, no event, no authorization, and no way to distinguish "actually suspended" from "decoder decided so." It also hides a magic threshold (`10000`, unnamed, unexplained) in a data-access layer where nobody will look for it, and it's outside the scope of the stated task and commit message.
   - *Required instead:* `decode` must be a pure mapping: `return {row.debt, row.suspended};`. If a debt-threshold suspension rule is genuinely wanted, that belongs in the domain/application layer as an explicit operation (e.g. a `suspendIfOverLimit(Customer&)` or similar service step invoked by the appropriate workflow), with the threshold as a named constant and its own tests and commit. Drop it from this change entirely.

2. **`customer.cpp` — commit/task scope mismatch.**
   - *What's wrong:* The commit message says "decode customer debt from rows," but the diff changes account-status semantics. A reviewer scanning history would not expect a behavior change here.
   - *Why it matters:* Undocumented policy changes buried in a plumbing commit are how status bugs get shipped and stay unfound.
   - *Required instead:* Keep this commit to the mapping only. Any suspension rule should be a separate, clearly described change with the affected domain owner identified.

Minor / non-blocking: `Row` and `Customer` being defined side by side in `customer.cpp` is fine for a fixture, but in the real codebase `Row` should live with the data-access layer and `Customer` with the domain so the dependency direction is obvious. No issues with the types themselves — `long` for validated integer cents and `bool` for status are appropriate.

**Verdict:** Not acceptable as-is. Remove `|| row.debt > 10000` from `decode`; it should read `Customer decode(Row row) { return {row.debt, row.suspended}; }`.
