**Not a workspace problem.** The environment, permissions, and JSON are all fine; the script's assertion is built on a false premise.

## Cause

`$raw` is `[]` — a valid, empty JSON array. `ConvertFrom-Json` produces an empty array, but because it is emitted through the pipeline (`$raw | ConvertFrom-Json`), PowerShell enumerates the collection into its elements. An empty array enumerates to *nothing*, so `$parsed` is assigned `$null`. That is exactly what stdout shows (`parsed type=<null>`), and `$null -isnot [array]` is true, so the script throws.

This is the same pipeline-unrolling behavior the reference note describes for one-element arrays, just at the zero-element end: a post-pipeline `-is [array]` check reports pipeline shape, not wire framing. The contract says empty arrays must be accepted, so the checker is wrong, not the data.

## Smallest safe remediation

You're on pwsh 7.4.6, so `-NoEnumerate` is available. Change line 5 only:

```powershell
$parsed = $raw | ConvertFrom-Json -NoEnumerate
```

`$parsed` then holds the actual `System.Object[]` (length 0 here, length 1 for singletons), and the existing `-isnot [array]` check on line 10 becomes reliable — provided `$parsed` is not re-piped afterwards, which it isn't in this script. Scalar wire values (`5`, `"x"`, `true`) still deserialize to non-array types and are still rejected, so the contract holds. (If this probe ever has to run under Windows PowerShell 5.1, use the raw-framing check instead: `$raw.Trim().StartsWith('[') -and $raw.Trim().EndsWith(']')`, since `-NoEnumerate` doesn't exist there.)
