**Cause:** The probe is working as designed and the input genuinely fails the contract. `$raw` is `{"id":7}` — a single JSON object with `{`/`}` framing, not an array. The raw-string check at line 7 (`StartsWith('[') -and EndsWith(']')`) is the correct, cardinality-safe way to assert framing, and it correctly rejects this value, so line 8 throws.

This is **not** the one-element-array/pipeline-unrolling problem from the reference notes. Nothing here inspects a parsed value with `-is [array]`; the `ConvertFrom-Json` result is discarded to `$null` and the assertion is made on the wire text. `-NoEnumerate` would change nothing, and PowerShell 7.4.6 on Windows 11 is not at fault — this is not an environment/tooling issue. It's a data-contract mismatch between what the probe requires (an array) and what it was given (an object).

