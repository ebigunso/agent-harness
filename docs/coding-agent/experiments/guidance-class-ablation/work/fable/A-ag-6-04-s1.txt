1. **`partner.py`, `while True` — no attempt cap or overall time budget.**
   Each attempt has a 1 s timeout, but there is no limit on attempts, so a partner that is down or persistently returning non-200 pins the caller forever. This is a hang, not a retry policy. Require a bounded number of attempts (e.g. 3–5) and/or a total deadline, then raise a clear exception (e.g. `PartnerError` carrying the last status/body) so the caller can decide what to do.

   Failed attempts are issued back-to-back, so a partner under load gets hammered at whatever rate the timeout allows. Require a sleep between retries with exponential backoff and jitter, honoring `Retry-After` on 429/503 if the partner sends it.
