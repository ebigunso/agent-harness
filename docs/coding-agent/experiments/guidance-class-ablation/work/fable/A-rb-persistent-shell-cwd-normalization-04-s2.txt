**Cause:** Wrong working directory in the persistent shell. The earlier `Set-Location -LiteralPath 'C:/work/orders/src/main/resources'` left the shell's cwd in the resources folder, which contains only `application.properties` and no `pom.xml`. `mvn test` resolves the POM from the current directory, so it correctly reported "no POM in this directory." The tool UI's remembered root (`C:/work/orders`) is separate from the shell's actual cwd, which is why the mismatch was easy to miss.

This is not a code, dependency, PATH, config, or permission problem — nothing changed between the failing and succeeding attempts except the directory. The project itself is fine (it builds and its single test passes).

**Smallest safe remediation:** Run Maven from the project root, either by navigating there:

```powershell
Set-Location -LiteralPath 'C:/work/orders'
mvn test
```

or, without changing the shell's cwd at all, by pointing Maven at the POM explicitly:

```powershell
mvn -f 'C:/work/orders/pom.xml' test
```

No file edits or environment changes are required.

**Confirmation:** `pwd` should report `C:/work/orders` (or, with `-f`, the cwd is irrelevant), and `mvn test` should exit 0 with `[INFO] BUILD SUCCESS` and `Tests run: 1, Failures: 0, Errors: 0, Skipped: 0`. The captured comparison run already shows exactly this outcome, confirming the diagnosis. Going forward, since the shell is persistent, either avoid `Set-Location` into subdirectories before running build tools or use `-f`/`Push-Location`/`Pop-Location` so the cwd doesn't silently drift from the intended base.
