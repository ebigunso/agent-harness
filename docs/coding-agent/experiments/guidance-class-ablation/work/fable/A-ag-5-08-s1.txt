**Findings**

1. **`lib.rs`, `remove` body (lines 3–5): invariant broken on cleanup failure.** The function removes the resource bytes from `resources`, then runs `cleanup()` and early-returns on `Err` via `?`, and only unregisters `id` from `registry` after that. If `cleanup` fails, the function exits with `id` still present in `registry` but no entry in `resources`. That directly violates the stated invariant ("every advertised ID must resolve to a live resource"): any consumer that enumerates the registry and looks up the ID will observe a missing resource. This is the observable "dangling" the reviewer notes warn about, just expressed as a map miss rather than a bad pointer. Because the failure is only reachable when `cleanup` errs, it will not show up in happy-path tests and will surface as a confusing lookup failure elsewhere.

   **Required change:** never leave the ID advertised without its resource. The straightforward fix is to unregister before releasing, so the registry can only ever be a subset of live resources:
   ```rust
   registry.remove(&id);
   resources.remove(&id);
   cleanup()?;
   Ok(())
   ```
   This keeps "cleanup follows release" and makes a cleanup failure leave the maps in a consistent (fully-removed) state. If the intended semantics are instead "cleanup failure means the removal didn't happen," then the removed bytes must be reinserted (`if let Err(e) = cleanup() { resources.insert(id, bytes); return Err(e); }`) *before* touching the registry — but in no ordering may `registry.remove` come after a fallible step that has already emptied `resources`. Add a test that passes a failing `cleanup` and asserts `registry.contains(&id) == resources.contains_key(&id)` afterward.

That is the only issue I would block on. Minor, non-blocking: `remove` on an unknown `id` silently returns `Ok(())` and still runs `cleanup`; if callers can pass stale IDs, consider returning an error (or skipping cleanup) when `resources.remove` yields `None`, but that's a spec question rather than a defect in the diff.
