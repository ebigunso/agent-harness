**Cause:** `report.txt` already exists in `C:\work\py-report` with an ACL that denies this user write access, so `open('report.txt', 'w', encoding='utf-8')` fails at open time with `PermissionError` (Errno 13). This is a filesystem permission problem on that one file — not an encoding, console, or UTF-8-mode issue. The observations about `sys.stdout.encoding=utf-8` and `utf8_mode=0` are red herrings: the script never reached a write, and it explicitly requested UTF-8 anyway. No process lock is involved.

**Smallest safe remediation:** Grant this user write (Modify) access on `report.txt` only — don't touch the directory or other files, and don't run as admin. From PowerShell 7 in `C:\work\py-report`:

```powershell
icacls .\report.txt /grant "$env:USERNAME:(M)"
```

If the deny is an explicit Deny ACE (which overrides grants), remove it first:

```powershell
icacls .\report.txt /remove:d "$env:USERNAME"
```

(Alternative, if the file's previous contents are disposable: delete/rename it so the script creates a fresh one in the writable parent directory — but check that the deny ACE wasn't intentional before doing so.)

