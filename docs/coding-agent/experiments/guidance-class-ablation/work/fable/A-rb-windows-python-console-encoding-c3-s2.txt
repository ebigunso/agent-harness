**Verdict: not a workspace/environment problem.** It's a code defect in `json_report.py`. The encoding facts (stdout utf‑8, `utf8_mode=0`, piped stdout) are red herrings — the traceback dies inside `json.dumps` at `encoder.default`, before `print` ever touches the stream. Nothing about Windows, PowerShell, or the pipe is involved.

**Cause**

`data` contains a `decimal.Decimal("1.25")`. The stdlib `json` encoder has no built‑in handling for `Decimal`, and no `default=` hook or custom `JSONEncoder` is supplied, so `JSONEncoder.default` raises `TypeError: Object of type Decimal is not JSON serializable`.

**Smallest safe remediation**

Give `json.dumps` a `default` that emits the exact decimal string (the stated wire contract) and still rejects anything else:

```python
from decimal import Decimal

def _json_default(o):
    if isinstance(o, Decimal):
        return str(o)          # exact, e.g. "1.25"; never float(o)
    raise TypeError(f"Object of type {o.__class__.__name__} is not JSON serializable")

print(json.dumps(data, ensure_ascii=False, default=_json_default))
```

Why this and not alternatives:
- `float(o)` would silently lose exactness (`Decimal("0.1")` → `0.1` double) and violates the "exact decimal string" requirement.
- Converting `data` in place before dumping mutates the caller's object; `default=` is local and side‑effect free.
- Re‑raising `TypeError` for other types preserves the fail‑loud behavior for any future unsupported object rather than masking it.
