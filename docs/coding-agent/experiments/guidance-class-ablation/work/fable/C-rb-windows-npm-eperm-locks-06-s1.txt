**Cause**

`npm ci` deletes `node_modules` before reinstalling, and the unlink of `node_modules\lmdb\build\Release\lmdb.node` was refused with EPERM (errno -4048). This is not a permissions/ACL, lock-file drift, cache, or registry issue — the probe file beside the module can be created/removed, the lockfile is in sync, and registry calls succeed. The file is held open: `tasklist /m lmdb.node` shows exactly one holder, `node.exe` PID 4106, which is the repository's own Gatsby cache/build watcher (`scripts/gatsby-watch.js`) with the addon loaded and mapped. Windows won't let a mapped native module be unlinked, so the install aborts. It is a workspace problem (a repo-owned dev process), not an npm or OS defect.

**Smallest safe remediation**

1. Stop the Gatsby watcher gracefully — Ctrl+C in the terminal running `scripts/gatsby-watch.js` (or stop it via whatever task runner launched it). Do not kill anything else.
2. Verify the handle is released:
   ```powershell
   tasklist /m lmdb.node
   ```
   Expect "INFO: No tasks are running which match the specified criteria."
3. Re-run the original command:
   ```powershell
   npm ci
   ```
4. Only if the graceful stop fails to release the module (PID 4106 still listed), force it — the PID is confirmed as the repo's watcher, so this is contained:
   ```powershell
   taskkill /PID 4106 /F
   ```
   then repeat steps 2–3.

No retries with `--force`, no manual deletion of `node_modules`, no cache clean — none of those address the open handle.

**Confirmation**

- `tasklist /m lmdb.node` returns no processes before the retry.
- `npm ci` exits 0 with no EPERM/unlink errors, and `node_modules\lmdb\build\Release\lmdb.node` is freshly rebuilt (new timestamp; lmdb is a source build, so expect node-gyp output).
- Restart the Gatsby watcher afterwards and confirm it loads the rebuilt addon (no `MODULE_NOT_FOUND` / ABI errors), and `tasklist /m lmdb.node` again shows PID of the new watcher holding it — which is the expected steady state, just not during installs.

**Record for the log**

- Original command: `npm ci`; error: `EPERM unlink C:\work\npm-lock\node_modules\lmdb\build\Release\lmdb.node` (errno -4048), exit 1.
- Module: lmdb 2.9.4 (source build).
- `tasklist /m lmdb.node`: node.exe PID 4106 (Gatsby watcher, `scripts/gatsby-watch.js`, repo-owned).
- Action: graceful stop of PID 4106; `taskkill /PID 4106 /F` only if needed (record whether it was used).
- Retry: `npm ci` result and exit code.

If after the retry it still fails, inspect the newly named module in the error and run `tasklist | findstr node` to find any other repo process (editor language server, test runner) holding it, and repeat the same procedure.
