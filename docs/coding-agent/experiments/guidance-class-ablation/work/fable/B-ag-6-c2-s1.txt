**Verdict: not acceptable as-is — the structure is right (own child deadline, no retries, no shared pool, degrades to empty), but the failure path discards the information needed to operate it, and the "bound" is only as strong as an undocumented contract.**

### Findings

1. **`optional.go:5` — error is swallowed; root cause is lost.**
   `err` is discarded and every failure collapses into the fixed string `"recommendation_unavailable"`. Deadline exceeded, upstream 5xx, connection refused, and decode errors all look identical to whoever is watching the signal. This is exactly the "broad error suppression that obscures root causes" anti-pattern in Gate 6 — when the recommendation service degrades, operators cannot tell *why* from this code path.
   **Require:** pass the error (or at least a classification of it) to the signal — e.g. `signal func(reason string, err error)` — or branch on `errors.Is(err, context.DeadlineExceeded)` to emit a distinct reason for timeouts vs. other failures.

2. **`optional.go:5` — parent cancellation is misreported as a recommendation failure.**
   If `parent` is already cancelled (client disconnected, checkout aborted), `call` will return `context.Canceled` and this code emits `"recommendation_unavailable"`. That inflates the failure signal with events that have nothing to do with the recommendation dependency, which will make any alert on that signal noisy and untrustworthy — precisely during incidents.
   **Require:** check `parent.Err() != nil` (or `errors.Is(err, context.Canceled)` while the child's own deadline has not fired) and return `""` silently, or signal a separate reason.

3. **`optional.go:3-4` — the 100ms bound is not enforced by this code; it depends entirely on `call` honoring `ctx`.**
   The reviewer note admits this ("downstream implementation must honor context cancellation"), but nothing in the change documents or enforces it. A `call` that ignores `ctx` blocks the required checkout path for as long as it likes, and the commit message's claim ("bound … failures") becomes false. I would *not* require a goroutine+`select` wrapper — that just converts a blocked caller into a leaked goroutine, which is worse under sustained upstream stalls — but the contract must be explicit.
   **Require:** a doc comment on `Recommendation` stating that `call` must return promptly once `ctx` is done and that this function provides no bound otherwise; and the test in (5) should include a `call` that respects `ctx` so the timeout path is actually exercised.

4. **`optional.go:5` — a panic in the optional path propagates into the required checkout.**
   The stated goal is that the optional recommendation is isolated from required checkout. A panic inside `call` (nil deref in a client library, bad decode) currently unwinds through checkout. Whether to `recover` here is a judgment call — many Go codebases treat panics as bugs to crash on — but Gate 6 asks that this be a *deliberate* decision, and the change makes none.
   **Require:** either add `defer func(){ if r := recover(); r != nil { signal(...) ; value = "" } }()` with a comment justifying it, or a comment stating panics are intentionally not contained here. Not a hard blocker if the latter is chosen consciously.

5. **No tests for the fallback behavior.**
   Gate 6's evidence expectation is that review verifies fallback behavior is deliberate; nothing here demonstrates it. At minimum: (a) success returns value and does not signal; (b) error returns `""` and signals once; (c) a `call` that blocks until `ctx.Done()` returns within ~100ms with the timeout reason; (d) a pre-cancelled parent does not emit the dependency-failure signal.
   **Require:** `optional_test.go` covering those four cases.

6. **`optional.go` — not gofmt'd.** Statements joined with `;` and the grouped import on one line will be rewritten by `gofmt`; any CI format check fails. Trivial, but it should not merge in this shape.
   **Require:** run `gofmt`.

### Not raised (deliberately)
- No retries: correct for a 100ms optional budget; adding them would be the anti-pattern.
- Hardcoded 100ms: acceptable as long as the parent's shorter deadline still wins (it does, via `WithTimeout`).
- Empty string as the degraded value: matches the stated design; if a legitimately empty recommendation ever needs to be distinguished from failure, return `(string, bool)`, but that's a product question, not a containment defect.
