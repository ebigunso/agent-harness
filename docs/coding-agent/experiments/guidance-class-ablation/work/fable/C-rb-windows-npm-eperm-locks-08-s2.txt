## Cause

This is a workspace problem, specifically a file-in-use conflict, not an npm/registry/permissions issue.

npm needs to replace `node_modules\onnxruntime-node\bin\napi-v3\win32\x64\onnxruntime_binding.node`, but Windows refuses to unlink a DLL that is mapped into a running process (`EBUSY`, errno -4082). `tasklist /m onnxruntime_binding.node` identifies the holder: **`node.exe` PID 4108**, the model preview server launched from `C:/work/npm-lock/workers/model-preview.js`. It is owned by this repository, so it's safe to stop.

Everything else checks out (lockfile in sync, registry reachable, ACLs fine, probe file beside the module can be created/removed), so nothing beyond the holder needs to change.

## Smallest safe remediation

1. **Stop PID 4108 gracefully** — use whatever launched the preview server (its stop task/script, or Ctrl+C in its terminal). Don't `taskkill /F` as the first move; it can leave the preview worker's state unclean.
2. Confirm the handle is released:
   ```powershell
   tasklist /m onnxruntime_binding.node
   ```
   Expected: `INFO: No tasks are running which match the specified criteria.`
3. Re-run the original command:
   ```powershell
   npm install
   ```
4. **Only if** the graceful stop doesn't release it, and after re-confirming the PID still belongs to the preview server:
   ```powershell
   taskkill /PID 4108 /F
   ```
   then repeat steps 2–3.

Do **not** delete `node_modules`, clear the npm cache, or touch the lockfile — none of those address the cause.

## Confirmation

- `tasklist /m onnxruntime_binding.node` returns no matching process before the retry.
- `npm install` exits 0 with no `EBUSY`/`EPERM` in stderr.
- The addon loads on the fresh runtime: `node -e "require('onnxruntime-node')"` exits 0.
- Restart the preview server and verify it serves again (it will re-map the new binary; that's expected).

If the retry fails with a **different** `.node` path, treat it as a new holder: run `tasklist /m <that-module>.node` and `tasklist | findstr node` to identify it, and repeat the same stop → retry cycle.
