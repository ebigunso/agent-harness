**Verdict: not a project/workspace defect.** The probe, dependencies, and service are fine — the failure is a local host-networking quirk in how `localhost` reaches Docker Desktop's published port.

## Cause

- `localhost` resolves to `::1` before `127.0.0.1`, so the failing channel targets `[::1]:50051`.
- Docker Desktop's published-port proxy on the IPv6 loopback accepts the TCP connection (so grpc-js sees a "connected" transport and doesn't fail fast with UNAVAILABLE), but never delivers HTTP/2 (h2c) response frames. The client waits until the 2 s deadline → `DEADLINE_EXCEEDED`, exit 2.
- The server-side interceptor log has **no entry** for the failed call, confirming the request never reached the container — the stall is in front of the service, not inside it.
- The HTTP/1.1 sibling on 50080 (200 OK, 0.012 s) shows the proxy path works for HTTP/1.1; the address-only comparison to `127.0.0.1:50051` succeeded (`pong`, exit 0, `invoked=true completed=true`), isolating the variable to the loopback address family.

TLS, certificate names, auth, and method mapping are ruled out (plaintext h2c, and PERMISSION_DENIED/UNIMPLEMENTED would exit 3, not 2).

## Smallest safe remediation

Point the local gRPC target at IPv4 explicitly in the local config only:

```
--target 127.0.0.1:50051
```

(or the equivalent `target` value in the project's local config file). Don't change the probe code, the service, or published ports. Avoid `NODE_OPTIONS=--dns-result-order=ipv4first` or editing the hosts file as a first step — those are process- or machine-wide changes with wider blast radius than a one-line target edit.

## Confirmation

1. Re-run the original command with the IPv4 target:
   ```
   node probes/unary.mjs --target 127.0.0.1:50051 --timeout 2
   ```
   Expect exit 0, stdout `pong`, empty stderr, well under the 2 s deadline.
2. Check the service interceptor log shows `probe method="unary application health" transport=h2c invoked=true completed=true` for that call.
3. (Optional negative check) Re-run with `localhost:50051` — if it still returns `DEADLINE_EXCEEDED` with no log entry, that reconfirms the address-family cause rather than a transient.

## Record for the incident

- REST sibling: `http://localhost:50080/health` → 200, 0.012 s.
- IPv4 retry: `127.0.0.1:50051` → exit 0, `pong`, server log `invoked=true completed=true`.
