**Cause**

This is a workspace/environment problem, not a code-logic or data problem. Python 3.12 on Windows still derives the stdout encoding from the console code page when stdout is *not* an interactive console. Because output is captured through a pipe, `sys.stdout.encoding` resolves to `cp1252` (the ANSI code page) and UTF-8 mode is off (`sys.flags.utf8_mode = 0`). `cp1252` has no mapping for `日` (U+65E5), so `csv.writer(sys.stdout).writerow(["date", "日"])` raises `UnicodeEncodeError` at the first non-Latin-1 character. Nothing was written (stdout empty), and the source CSV is untouched since the script only writes to stdout.

**Smallest safe remediation**

Force UTF-8 for the process without editing the script or the data. Pick one, in order of preference:

1. Per-invocation flag (no persistent change):
   ```powershell
   python -X utf8 csv_preview.py
   ```
2. Or environment variable for the session:
   ```powershell
   $env:PYTHONUTF8 = '1'; python csv_preview.py
   ```
   (`$env:PYTHONIOENCODING = 'utf-8'` is the narrower alternative if you only want to change stdio and not filesystem/`open()` defaults.)

Avoid the heavier options for now: changing the system locale to UTF-8, or editing the script to call `sys.stdout.reconfigure(encoding="utf-8")` — the latter is fine if you want the fix to travel with the script, but it's a code change, not the minimal one.

Note for later, unrelated to this failure: writing a CRLF CSV dialect to `sys.stdout` in text mode on Windows will emit `\r\r\n` (newline translation on top of the dialect's `\r\n`). If that matters for consumers, use `sys.stdout.reconfigure(newline="")` or write to a stream opened with `newline=""`.

**Confirmation**

```powershell
python -X utf8 csv_preview.py | Out-String
$LASTEXITCODE
```
Expect exit code `0`, no traceback, and the output containing `date,日`. To verify the encoding change itself in the same piped context:
```powershell
python -X utf8 -c "import sys; print(sys.stdout.encoding, sys.flags.utf8_mode)" | Out-String
```
Expect `utf-8 1` (versus `cp1252 0` before). Optionally confirm the source CSV's hash is unchanged (`Get-FileHash`) to document that no data was modified.
