**Cause**

This is not a workspace, runtime, or script-bug problem. The probe did exactly what it is designed to do: it rejected input that isn't a JSON array.

- Raw JSON: `{"id":7}` (hard-coded on line 3, echoed on stdout as `raw={"id":7}`).
- Parse: `ConvertFrom-Json` on line 4 succeeded — the text is syntactically valid JSON and yields a single `PSCustomObject`. No parse error occurred.
- Element count: 0 array elements — it is one object, not an array of anything.
- Assertion: line 7 trims and checks `StartsWith('[')` / `EndsWith(']')`. First char is `{`, last is `}`, so the condition is false and line 8 throws `'Expected array framing'`. With `$ErrorActionPreference = 'Stop'` that is a terminating error → exit code 1.

The framing check is the correct check here (a post-pipeline `-is [array]` test on the parsed result could not distinguish `[{"id":7}]` from `{"id":7}` because the pipeline unrolls single-element arrays; on 7.4 `-NoEnumerate` would preserve it, but the raw-text check is the authoritative one and is what the script uses). Nothing about the environment (Win11 22631, pwsh 7.4.6, execution policy, cwd, profile suppression) contributed.

**Smallest safe remediation**

Give the probe array-framed input. Since `$raw` is a literal in the script, change line 3 to wrap the object in an array — do not loosen the assertion:

```powershell
$raw = '[{"id":7}]'
```

If the literal is a stand-in for real input, the same rule applies at the source: the producer must emit `[...]`, not a bare object. Don't "fix" it by replacing the framing check with `-is [array]` or by wrapping the parsed object in `@()` — both would hide the actual wire framing.

**Confirmation**

Rerun `pwsh -NoProfile -File probes/require-array.ps1` and check:

- `$LASTEXITCODE` is 0
- stdout is `raw=[{"id":7}]`
- stderr is empty (no `Expected array framing`)

Optionally, as a one-off sanity check of the parse on 7.4.6: `('[{"id":7}]' | ConvertFrom-Json -NoEnumerate) -is [array]` → `True` (and `.Count` → 1), versus `('{"id":7}' | ConvertFrom-Json -NoEnumerate) -is [array]` → `False`, which agrees with the raw framing check.
