**Cause:** Not a workspace or data problem — the JSON is valid and correctly framed as an array. The failure is a bug in the checker's assertion. `$raw | ConvertFrom-Json` pushes the parsed result through the pipeline, and PowerShell unrolls the one-element array, so `$parsed` receives the bare element (`PSCustomObject`, as the stdout shows). The subsequent `-isnot [array]` check is therefore testing pipeline enumeration, not wire framing, and throws spuriously for any singleton array. (It would also misfire on an empty array `[]`, which unrolls to nothing/`$null`.)

**Smallest safe remediation:** You're on pwsh 7.4.6, so `-NoEnumerate` is available. Change line 5 only:

```powershell
$parsed = $raw | ConvertFrom-Json -NoEnumerate
```

This keeps `[...]` payloads as `System.Object[]` regardless of element count (including `[]` → empty array), while a scalar wire value like `7` still parses to a non-array and correctly trips the throw. Don't re-pipe `$parsed` afterwards or it will unroll again.

If this script ever has to run under Windows PowerShell 5.1 (no `-NoEnumerate`), assert framing on the raw string instead: `if ($raw.Trim()[0] -ne '[' -or $raw.Trim()[-1] -ne ']') { throw ... }`. Not needed for the stated environment.
