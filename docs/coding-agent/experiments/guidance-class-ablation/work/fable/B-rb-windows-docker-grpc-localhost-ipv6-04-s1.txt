**Cause**

This is a workspace/host-networking problem, not a service or code fault. `localhost` resolves to `::1` first, so the grpc-java channel connects to `[::1]:50051`. Docker Desktop's IPv6 port proxy accepts the TCP connect but never returns HTTP/2 response headers, so the call sits at the transport layer until the 2s deadline fires (`DEADLINE_EXCEEDED`, exit 2). The service never sees the request — the interceptor log has no entry for the failed call. The REST sibling on `localhost:50080` works because HTTP/1.1 doesn't stall on that proxy path, and the address-only comparison (`127.0.0.1:50051` → `pong`, exit 0, `invoked=true completed=true`) confirms the service is healthy and the only variable is the loopback address.

**Smallest safe remediation**

Change the gRPC target from `localhost:50051` to `127.0.0.1:50051` for local Docker Desktop connections on this Windows host:

```powershell
java -jar probes/grpc-probe.jar --target 127.0.0.1:50051 --timeout 2
```

Apply the same substitution wherever the client's local connection string is defined (config/env/launch script). Do not touch the service, port publishing, or the container — they are already shown working. Avoid broader changes like disabling IPv6 on the host or forcing `-Djava.net.preferIPv4Stack=true` JVM-wide; the address change is narrower and reversible.

**Confirmation**

1. Rerun the original probe with the new target and check: exit code 0, stdout `pong`, empty stderr, total time well under the 2s deadline.
2. Check the service interceptor log shows a new line `probe method="unary Echo" transport=h2c invoked=true completed=true` for that call.
3. Optionally rerun the `localhost:50051` variant once to confirm it still hangs, proving the fix is the address and not an incidental change in service state.

**Note:** the `localhost` deadline failure is expected to persist as an environmental quirk of Docker Desktop's IPv6 proxy; it isn't something to "fix" in the service. If `127.0.0.1` ever starts failing too, only then investigate port publishing and container health.
