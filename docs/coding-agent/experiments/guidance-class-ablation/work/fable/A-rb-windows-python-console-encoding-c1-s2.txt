**Cause**

`input.txt` is UTF-16LE with a byte-order mark (first bytes `FF FE`), but `read_input.py` line 9 hard-codes `encoding='utf-8'`. `0xFF` is never a valid UTF-8 start byte, so the decoder fails on the first byte. The stack trace confirms it's the `read_text` call, not output: no write to stdout has happened, so `sys.stdout.encoding`, the pipe capture, and `utf8_mode = 0` are irrelevant here. Nothing was modified.

This is a code/data mismatch in the workspace, not an environment or shell problem.

**Smallest safe remediation**

Change the decode to match the producer's declared format. `utf-16` (no `LE` suffix) honors and strips the BOM, so it's the robust choice:

```python
text = Path('input.txt').read_text(encoding='utf-16')
```

Don't convert the input file — the producer declares UTF-16LE with BOM, so future files will arrive the same way; fixing the file would just reintroduce the failure next run. Don't use `errors='ignore'`/`'replace'` — that would silently mangle every other byte of a UTF-16 stream.
