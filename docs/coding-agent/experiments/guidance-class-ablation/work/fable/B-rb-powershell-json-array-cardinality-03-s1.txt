## Cause

Not a workspace or environment problem — the probe's own assertion is wrong for how PowerShell returns JSON arrays.

`$raw | ConvertFrom-Json` writes the parsed array to the pipeline, and the pipeline enumerates it. With exactly one element, `$parsed` receives the bare element (`"north"`), so `parsed type=System.String` and `-isnot [array]` throws. The stdout confirms the wire value was correctly framed (`raw=["north"]`); only the post-pipeline type check is misleading. The same script would pass with `["north","south"]` and fail with any singleton — exactly the cardinality-dependent flake described in the reference note.

## Smallest safe remediation

You're on pwsh 7.4.6, so `-NoEnumerate` is available. Change line 5 only:

```powershell
$parsed = ConvertFrom-Json -InputObject $raw -NoEnumerate
```

(Don't pipe the result anywhere afterwards, or it will be unrolled again.) The rest of the script is unchanged; `-isnot [array]` is now a valid check because the parser hands back the array object intact.

If this probe must also run under Windows PowerShell 5.1 (where `-NoEnumerate` doesn't exist), assert on the wire format instead, which is what the contract is actually about:

```powershell
$t = $raw.Trim()
if (-not ($t.StartsWith('[') -and $t.EndsWith(']'))) { throw 'Expected JSON array' }
```

Either form satisfies the stated contract: empty `[]`, singleton, and multi-element arrays pass; a scalar wire value such as `"north"` or `42` is rejected.
