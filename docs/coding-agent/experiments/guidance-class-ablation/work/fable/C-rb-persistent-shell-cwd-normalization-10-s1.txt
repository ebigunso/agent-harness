**Cause:** Stale shell working directory, not a repository or tooling fault. The persistent shell had previously been moved to `C:/work/notes` (`Set-Location -LiteralPath 'C:/work/notes'`, status 0), and it stayed there. `git status --porcelain` was then run from `C:/work/notes`, which contains only `today.txt` and has no `.git` anywhere up its parent chain (`C:/work` is not a repo either). Git correctly reported `fatal: not a git repository` with exit 128. The tool UI's remembered root of `C:/work/repo` is not the shell's cwd; the two diverged after the earlier `cd`.

Evidence that rules out other causes: the repo is intact (`C:/work/repo/.git` and `README.md` exist and are readable), no code/branch/PATH/config/permission change occurred, and the identical command succeeded once the cwd was corrected.

**Smallest safe remediation:** one explicit, absolute navigation to the intended base, then rerun the original command unchanged:

```powershell
Set-Location -LiteralPath 'C:/work/repo'
git status --porcelain
```

No relative `cd ..` chains, no reconfiguration of Git, no changes to the workspace. Alternatively, avoid the cwd dependency entirely for one-off invocations: `git -C 'C:/work/repo' status --porcelain`.
