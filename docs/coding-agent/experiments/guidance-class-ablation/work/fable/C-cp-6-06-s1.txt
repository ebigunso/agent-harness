This is a silent semantic drift between producer and consumer in the same file, and it corrupts financial records rather than raising an error.

This is exactly the kind of coercion/shape drift that should be made explicit.
   Required: either rename the field to make the unit unambiguous (e.g. `amount_major` / `amount_dollars`, or keep `amount_cents` alongside during a migration window), or version the serializer/API and document the cutover. At minimum, audit all readers of `:amount` before merging.
