**Verdict: block.**

**1. `delete.go`, `Delete` — wrong operation order leaves a deleted account with live billable jobs.**

`MarkDeleted` commits first. If `CancelJobs` then fails, the error is returned but the account is already persisted as deleted while its recurring jobs are still active and billable. That directly violates the stated invariant ("Deleted accounts must not retain billable jobs") and is not self-healing: a caller seeing the error will likely retry, but many `MarkDeleted` implementations reject or no-op on an already-deleted account, and the UI will show the account as gone, so nobody looks at it again. The jobs keep billing.

Because the store methods persist independently (no shared transaction), the safe ordering is the one where the *partial-failure state is the harmless one*:

```go
func Delete(store Store, id string) error {
	if err := store.CancelJobs(id); err != nil {
		return fmt.Errorf("cancel jobs for account %s: %w", id, err)
	}
	if err := store.MarkDeleted(id); err != nil {
		return fmt.Errorf("mark account %s deleted: %w", id, err)
	}
	return nil
}
```

Now: if `CancelJobs` fails, nothing has changed — account is still active, jobs still active, caller retries. If `MarkDeleted` fails after `CancelJobs` succeeded, the account is still visible but has no billable jobs — no one is charged, and a retry completes the deletion. Neither partial state bills a deleted account.

Required along with the reorder: document on the `Store` interface that both methods must be idempotent (calling `CancelJobs` on an account with no jobs, or `MarkDeleted` on an already-deleted account, must succeed), otherwise retry after the second failure mode breaks. If the real store can offer a transaction, that's strictly better than ordering, but ordering is the minimum acceptable fix given the "persist independently" constraint.

**2. No test for the partial-failure path.**

The commit adds behavior with a known failure mode and no test. Require a fake `Store` test that makes `CancelJobs` fail and asserts `MarkDeleted` was *not* called, plus one where `MarkDeleted` fails and asserts jobs were cancelled. That's the test that would have caught finding 1.

**3. Minor: file isn't gofmt'd and errors are returned bare.**

Semicolon-joined statements on one line will fail `gofmt`/`go vet` gating in most CI setups; run `gofmt`. Bare `return err` loses which of the two independent stores failed — with two persistence calls that fail differently, callers/operators need to know which one. Wrapping shown above. Not blocking on its own, but fix while you're in here.
