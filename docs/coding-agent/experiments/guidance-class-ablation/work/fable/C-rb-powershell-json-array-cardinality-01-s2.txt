## Cause

This is a **script bug, not a workspace problem**. The raw JSON `[7]` is a valid single-element array, but the assertion logic can't see that.

The line `$parsed = $raw | ConvertFrom-Json` pipes the converted result **through the pipeline**, which unrolls the array. A single-element array unrolls to its lone element, so `$parsed` is the scalar `Int64` `7` (confirmed by `parsed type=System.Int64`). The test `$parsed -isnot [array]` is therefore true and the `throw` fires.

The check is trying to prove *wire framing* (was the JSON an array on the wire?) using a *post-pipeline type test*, which cannot do that — pipeline enumeration has already destroyed the array shape.

## Smallest safe remediation

You are on PowerShell 7.4.6, which has `-NoEnumerate`. Stop piping and use it so the array shape survives:

```powershell
$parsed = ConvertFrom-Json -InputObject $raw -NoEnumerate
```

(Leave the rest unchanged. Do **not** re-pipe `$parsed` afterward, or it will re-enumerate.)

If you want the check to be truly robust to enumeration and independent of runtime (e.g., Windows PowerShell 5.1, which lacks `-NoEnumerate`), assert on trimmed raw framing instead:

```powershell
$t = $raw.Trim()
if (-not ($t.StartsWith('[') -and $t.EndsWith(']'))) { throw 'Expected JSON array' }
```

Note this framing check is a shape guard, not a full JSON syntax validator — but the observations state the raw JSON is already valid, so it is sufficient here.
