**Cause:** This is a workspace problem, and it's a file lock, not permissions. `npm ci` deletes `node_modules` before reinstalling, and it hit `EPERM unlink` (errno -4048) on `better_sqlite3.node`. Windows won't allow unlinking a DLL/native addon that is mapped into a running process. `tasklist /m better_sqlite3.node` shows exactly one holder: `node.exe` PID 4101, which is this repo's own Express/TypeScript dev server (launched from `C:/work/npm-lock/src/server.ts`) and still has the addon loaded. Everything else checks out — lockfile is in sync, cache/project are writable, a probe file beside the module can be created/removed, no ACL denial, registry reachable — so nothing about the install itself is broken.

**Smallest safe remediation:**

1. Stop the dev server gracefully: go to the terminal it's running in and press `Ctrl+C` (let it shut down and release the SQLite handle). Do not kill it while it may be mid-write.
2. Verify the lock is gone:
   ```powershell
   tasklist /m better_sqlite3.node
   ```
   Expected: `INFO: No tasks are running which match the specified criteria.`
3. Re-run the original command from `C:/work/npm-lock`:
   ```powershell
   npm ci
   ```
4. Only if the process didn't exit on Ctrl+C, and only after confirming PID 4101 is still the repo's dev server (e.g. `Get-Process -Id 4101 | Select-Object Path, CommandLine` or `tasklist /fi "PID eq 4101"`):
   ```powershell
   taskkill /PID 4101 /F
   ```
   then repeat steps 2–3. Don't kill by image name (`node.exe`) — that would take out unrelated Node processes.

Do not delete `node_modules` manually, run as admin, or fiddle with ACLs/antivirus — none of that addresses a mapped-module lock and it adds risk.

**Confirmation:**

- `npm ci` exits 0 with no `EPERM`/`unlink` errors.
- `node_modules\better-sqlite3\build\Release\better_sqlite3.node` exists after the install.
- `node -e "require('better-sqlite3')"` from the repo root loads without error (better-sqlite3 9.6.0 has prebuilds for Node 20, so it should not need a rebuild; if you see an ABI mismatch, run `npm rebuild better-sqlite3`).
- Restart the dev server and hit an endpoint that touches the database to confirm it still works.

If the retry fails again with the same error, run `tasklist /m better_sqlite3.node` and `tasklist | findstr node` to find any new holder (a second dev process, test watcher, or an editor with a Node-based extension) and repeat.
