**Cause**

`npm ci` removes the existing `node_modules` before reinstalling. On Windows, a native addon (`lmdb.node`) that is currently loaded by a running process cannot be unlinked — the OS holds the mapped image and refuses the delete with `EPERM` (errno -4048). `tasklist /m lmdb.node` shows exactly one holder: `node.exe` PID 4106, the Gatsby cache/build watcher launched from this repo's `scripts/gatsby-watch.js`. This is not a permissions, ACL, lockfile-sync, or npm-cache problem — the probe file beside the module can be created/removed fine, and the lock/registry checks pass. It's a file-in-use conflict caused by a process this repository owns.

**Smallest safe remediation**

Stop the watcher that holds the addon, then rerun the install. Since the process is the repo's own dev watcher (not a system or unrelated service), terminating it is safe; it can be restarted afterward.

```powershell
# confirm it's the expected process before killing it
Get-Process -Id 4106 | Select-Object Id, ProcessName, Path, CommandLine
Stop-Process -Id 4106
npm ci
```

Prefer a graceful stop (Ctrl+C in the terminal running `gatsby-watch.js`, or `Stop-Process -Id 4106` which sends a normal terminate) over `-Force`, so Gatsby's cache flushes cleanly. Do not fall back to `rm -rf node_modules` while the process is alive — it will hit the same lock — and do not run the install elevated; privilege is not the issue.

**Confirmation**

1. `tasklist /m lmdb.node` returns "INFO: No tasks are running which match the specified criteria." — no process has the addon mapped.
2. `npm ci` exits 0 and `node_modules\lmdb\build\Release\lmdb.node` is freshly written (check `(Get-Item .\node_modules\lmdb\build\Release\lmdb.node).LastWriteTime`).
3. Optionally `node -e "require('lmdb')"` exits 0 to verify the rebuilt addon loads on Node 20.18.0.
4. Restart the watcher (`node scripts/gatsby-watch.js`) once the install is done.

**Preventive note:** to avoid recurrence, have the dev workflow stop the Gatsby watcher before `npm ci`/`npm install` (e.g. a `preinstall` hint or a wrapper script), since any native addon it loads will be locked for the duration.

__ABLATION_DONE__ exit=0
