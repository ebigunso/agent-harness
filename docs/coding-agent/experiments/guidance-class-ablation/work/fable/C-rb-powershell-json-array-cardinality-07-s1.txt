## Cause

This is a bug in the script, not an environment problem. PowerShell 7.4.6 has `-NoEnumerate` and it works as documented.

The failure comes from the trailing `| Write-Output` on line 5:

```powershell
$parsed = ($raw | ConvertFrom-Json -NoEnumerate) | Write-Output
```

`ConvertFrom-Json -NoEnumerate` correctly emits the one-element array as a **single** object. But you then re-pipe that object into `Write-Output`. Any pipeline unrolls (enumerates) an array, so the single-element array `["north"]` is flattened to its one member, the string `"north"`. The assignment therefore captures a `System.String`, exactly as the output shows:

```
parsed type=System.String
```

The `-isnot [array]` test is then correct to fail — but it's testing the re-enumerated scalar, not the wire shape. The reference note names this precisely: `-NoEnumerate` preserves arrays *unless re-piped*, and here it was re-piped.

## Smallest safe remediation

Delete the redundant `| Write-Output` so the un-enumerated array is bound directly to the variable:

```powershell
$parsed = $raw | ConvertFrom-Json -NoEnumerate
```

(The `$raw | ConvertFrom-Json` pipe is fine; `-NoEnumerate` governs the cmdlet's own output. It is only the *second* pipe segment that unrolls it.)

Nothing else needs to change; the checker writes no files, so there is no state to clean up.

## Confirmation

Re-run the same command:

```
pwsh -NoProfile -File probes/cardinality.ps1
```

Expect:
- Exit code `0` (no thrown exception).
- `parsed type=System.Object[]` instead of `System.String`.

Strengthen the check against regressions across the contract's stated cases:
- Empty array `'[]'` → should also report `System.Object[]` and pass (this is the case `-NoEnumerate` most needs to protect, since an empty result would otherwise vanish).
- Multi-element `'["north","south"]'` → `System.Object[]`, passes.
- A scalar wire value, e.g. `'"north"'` → `System.String`, and the `throw` should fire (exit 1), confirming the assertion still rejects non-arrays.

One caveat worth noting: `-is [array]` after the fix proves the *parsed .NET type*, not the wire framing. If you want to assert framing directly (and to stay portable to Windows PowerShell 5.1, which lacks `-NoEnumerate`), additionally check the trimmed raw string starts with `[` and ends with `]` rather than relying on post-parse type alone.
