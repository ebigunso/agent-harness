**Finding 1 — `invoice.rb`, `audit`: consumer not updated for the new unit; persisted amounts will be off by 100×**

`serialize` now emits `amount` in major units (dollars), but `audit` still does `wire.fetch(:amount) * 0.01` — i.e. it still assumes the wire value is cents and converts to dollars. With the example amount:

- Before: serialize → `{ amount: 1250 }`; audit → `1250 * 0.01 = 12.5` dollars ✔
- After: serialize → `{ amount: 12.5 }`; audit → `12.5 * 0.01 = 0.125` dollars ✘

The audit function persists that number as dollars, so every audited invoice will be recorded at 1% of its real value. This is exactly the silent shape/semantics drift the contract-fidelity rule is about: the producer and consumer of the same `amount` field no longer agree on its unit, and nothing in the code or types catches it. It won't raise, it won't look malformed — it will just be wrong in the audit store.

Required instead: update `audit` in the same change so it consumes the new unit, e.g.

```ruby
def audit(wire)
  wire.fetch(:amount)   # already in major units
end
```

(or, if the audit store is meant to keep cents, `(wire.fetch(:amount) * 100).round`). Any other consumers of the serialized `amount` — clients, other services, stored payloads — need the same treatment; the diff doesn't show them, so the author should enumerate them. Ideally the unit should also be made explicit in the contract (field name like `amount_major` / documented schema) or the serializer/audit pair covered by a round-trip test (`audit(serialize(1250)) == 12.5`) so this class of drift fails CI rather than corrupting data.

**Not raising (noting only):** `cents / 100.0` uses a Float for a monetary value. For 1250 it's exact, and the notes say rounding isn't in scope, so I won't block on it — but if this serializer ever handles arbitrary amounts, a `BigDecimal`/`Rational` or a Money object would be the safer representation.

**Verdict:** block until `audit` (and any other `amount` consumers) are aligned with the new unit; as written, the change breaks the serialize→audit contract and persists incorrect dollar values.
