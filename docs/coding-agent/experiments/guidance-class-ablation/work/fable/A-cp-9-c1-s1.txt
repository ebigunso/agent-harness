**Verdict:** Close, but not mergeable as-is. Two things I'd require before approval, one I'd push on, one nit.

1. **`catalog/fetch.go`, `Timeout: errors.Is(err, context.DeadlineExceeded)` — timeout detection is too narrow for the stated task.**
   The task is to preserve typed timeout context. This only recognizes a deadline that propagated through `ctx`. Timeouts that originate inside the store (DB driver, HTTP client, socket deadline) commonly surface as `os.ErrDeadlineExceeded` or a `net.Error` with `Timeout() == true`, and do *not* wrap `context.DeadlineExceeded`. For those, `Timeout` will be `false` and the HTTP layer / callers that branch on it will misclassify a timeout as a generic failure — the exact information loss this change is meant to prevent.
   Require: broaden the check, e.g. `errors.Is(err, context.DeadlineExceeded) || errors.Is(err, os.ErrDeadlineExceeded) || isNetTimeout(err)` (via `errors.As(err, &netErr) && netErr.Timeout()`), or document why the `Store` contract guarantees timeouts are always context-derived — and add a test that pins that contract.

2. **No test.** For a change whose whole point is "typed context survives wrapping," I'd expect a unit test with a stub `Store` returning (a) a `context.DeadlineExceeded`-wrapped error, (b) a non-timeout error, asserting `errors.As(err, *FetchFailure)`, `Timeout` true/false, and `errors.Is(err, context.DeadlineExceeded)` through `Unwrap`. Without it, the next refactor of `Error()`/`Unwrap()` can silently break the 503 mapping.

3. **`Error()` discards the cause and the timeout flag from the message.** `"fetch catalog failed"` is what every `%v`/`%s` log line and `err.Error()` sink will print. The notes say store errors are already sanitized at source, so the redaction isn't buying safety — it's just removing diagnostics from logs and making a timeout indistinguishable from any other failure unless the logger does `errors.As`. Suggest `Operation + " failed: " + Cause.Error()` (and/or "(timeout)" when `Timeout`). If the intent really is that this string is user-facing and must stay opaque, say so in a comment on `Error()` so nobody "fixes" it later.

4. **Nit — gofmt.** Struct field alignment and indentation aren't gofmt'd (`Timeout   bool`, `Cause     error`, tabs). CI will likely reject it anyway.

Not raising: nil-handling (pointer is only returned when `err != nil`), `Unwrap` semantics (correct), success path (unchanged), and `context.Canceled → 503` — that's an HTTP-layer policy question, not a defect in this diff.
