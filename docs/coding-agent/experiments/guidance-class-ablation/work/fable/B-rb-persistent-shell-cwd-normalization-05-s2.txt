## Cause

The relative argument `Tests/Tests.csproj` therefore resolved to `C:/work/inventory/src/Tests/Tests.csproj`, which does not exist — hence `MSB1009: Project file does not exist`. The tool UI's remembered root (`C:/work/inventory`) is independent of the shell's actual cwd, which is what made the drift easy to miss.

No file, config, or environment changes. Going forward, avoid relying on carried-over cwd in this shell; if you want a cwd-independent form, `dotnet test C:/work/inventory/Tests/Tests.csproj` also works, but the fix above is the minimal one.
