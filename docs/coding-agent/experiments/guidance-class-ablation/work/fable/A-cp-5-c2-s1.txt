**Verdict: the core change is correct and I would not block it.** The validation matches the stated contract (nonempty *bytes*, so whitespace-only is correctly accepted), the private field enforces the invariant, and `len()` reading the inner byte length without re-validating is fine. The findings below are things I'd flag, not block on.

1. **`lib.rs`, `impl AccountId` — `len()` without `is_empty()`.**
   Clippy's `len_without_is_empty` fires on a public type exposing `len()` with no `is_empty()`. If CI runs clippy with `-D warnings`, this will fail. Since the invariant guarantees the ID is never empty, either add `#[allow(clippy::len_without_is_empty)]` with a one-line comment stating why, or provide `pub fn is_empty(&self) -> bool { false }` (the former is clearer about intent).

2. **`lib.rs`, `pub struct AccountId(String);` — no derives.**
   An identifier type with no `Debug`, `Clone`, `PartialEq`, `Eq`, or `Hash` can't be printed in assertions, compared, or used as a map key. The test already works around the missing `Debug` by comparing `len()` instead of the value. Require at minimum `#[derive(Debug, Clone, PartialEq, Eq, Hash)]`; none of these can violate the invariant since they don't construct from raw input. (Deliberately omit `Default`, which would.)

3. **`lib.rs` — no way to read the ID back out.**
   The only accessor is `len()`. A validated ID that can't be turned back into a `&str` (for logging, serialization, DB keys) is not usable by callers. If the intent is a minimal first commit, that's fine as a follow-up, but I'd want `pub fn as_str(&self) -> &str` (and/or `AsRef<str>` / `Display`) either here or explicitly noted as next. Not a correctness bug, just a scope question — please confirm which.

4. **`lib.rs`, test `boundary` — `.ok().unwrap()` discards the error.**
   `&'static str` is `Debug`, so `.unwrap()` works directly and, on failure, prints the actual error message instead of "called `Option::unwrap()` on a `None` value". Replace with `.unwrap()` (or `.expect("single-byte id is valid")`). Nit.

5. **`lib.rs`, test `boundary` — bytes-vs-chars contract not pinned.**
   Since the reviewer notes stress that the contract is about bytes, a one-line assertion like `assert_eq!(AccountId::new("é".into()).unwrap().len(), 2)` would lock that in and prevent a future "helpful" change to `chars().count()`. Optional.

Nothing else: `#[test]` at crate root compiles only under test, so no `#[cfg(test)]` wrapper is needed; the `&'static str` error type is acceptable for this scope.
