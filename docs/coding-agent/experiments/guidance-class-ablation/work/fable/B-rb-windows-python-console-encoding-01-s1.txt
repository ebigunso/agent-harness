**Verdict:** This is an environment/encoding-default problem, not a workspace or data problem. The report was computed correctly; it failed only at `print`.

**Cause**

`sys.stdout.encoding` is `cp932` and `utf8_mode = 0`. Because stdout is a pipe rather than an interactive console, CPython on Windows picks the encoding from the process's ANSI code page (`locale.getpreferredencoding()` → CP932 on a Japanese-locale system), not from the console code page — the reference note's "inherits the console code page" wording is slightly off for a piped stdout, but the mechanism and fix are the same. CP932 has no mapping for U+2014 EM DASH (its `0x815C` maps to U+2015 in Python's codec), so encoding `'Summary — complete'` raises `UnicodeEncodeError` at position 8, the dash. `report.py` line 18 is the only failure point.

**Smallest safe remediation**

Rerun with the I/O encoding override, scoped to the command so it doesn't leak into the rest of the PowerShell session:

```powershell
$env:PYTHONIOENCODING = 'utf-8'; python report.py; Remove-Item Env:PYTHONIOENCODING
```

Equivalent, and no env-var bookkeeping: `python -X utf8 report.py`.

No cleanup is needed for the failed attempt: the observations confirm the script is read-only (no files written), so there are no partial side effects.

For a durable fix in a script you own, add near the top of `report.py`:

```python
import sys
sys.stdout.reconfigure(encoding="utf-8")
```

That is the correct fix for both console and piped stdout, and it removes the dependency on the caller's environment.

**Confirmation**

1. Rerun exits 0 and the traceback is gone.
2. Captured stdout contains `Summary — complete` (bytes `53 75 6d 6d 61 72 79 20 e2 80 94 ...`, i.e. `E2 80 94` for the dash) — note the consumer of the pipe must decode as UTF-8; if PowerShell itself is reading the output, check `[Console]::OutputEncoding`, otherwise you'll get mojibake rather than a crash.
3. Optional sanity check in the same environment: `python -c "import sys; print(sys.stdout.encoding)"` prints `utf-8` with the override and `cp932` without it, matching the diagnosis.

Evidence to keep: the original `UnicodeEncodeError ... '\u2014' in position 8` line and the successful rerun command.
