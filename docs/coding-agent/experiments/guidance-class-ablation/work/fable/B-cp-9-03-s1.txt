- **What's wrong:** A gateway timeout means the outcome of the remote capture is *unknown* — the reviewer notes say it can occur before or after the charge landed. The new branch resolves that ambiguity by asserting the most optimistic outcome: it persists `markPaid` and returns `ChargeStatus.PAID` regardless of whether money moved.
- **Why it matters:** This is exactly the misreporting the task was meant to prevent. If the timeout happened before capture, the order ships/completes with no payment collected, the customer is never charged, and there's no signal anywhere that anything went wrong. If the timeout happened after capture, it happens to be correct — but only by luck. The failure is also silent: the exception is swallowed with no log, no metric, no stored marker, so reconciliation has nothing to find and support cannot diagnose "paid" orders with no gateway record. The commit message ("complete checkout on gateway timeout") describes the bug as the feature.
