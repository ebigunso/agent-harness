## Cause

This is a **script (workspace) bug**, not a runtime or environment problem.

The line

```powershell
$parsed = ($raw | ConvertFrom-Json -NoEnumerate) | ForEach-Object { $_ }
```

correctly asks `ConvertFrom-Json -NoEnumerate` to emit the parsed array as a single object — but then immediately **re-pipes it into `ForEach-Object`**. That pipeline stage unrolls the array again, exactly the behavior `-NoEnumerate` was meant to suppress. With a singleton array the unroll yields one `PSCustomObject`, which is assigned to `$parsed`.

So at the assertion, `$parsed` is the element, not the container:
- `parsed type=System.Management.Automation.PSCustomObject` (confirming the unroll)
- `$parsed -isnot [array]` is true → `throw 'Expected JSON array'` → exit 1

The `-NoEnumerate` guarantee holds only until the value is re-piped; the `ForEach-Object` defeats it.

## Smallest safe remediation

Remove the re-piping so the array survives to the assignment:

```powershell
$parsed = $raw | ConvertFrom-Json -NoEnumerate
```

(Drop `| ForEach-Object { $_ }`.) This is one-line, behavior-preserving for the intended contract, and touches nothing else.

## How to confirm

Re-run:

```
pwsh -NoProfile -File probes/cardinality.ps1
```

Expected: exit code `0`, no stderr, and stdout showing `parsed type=System.Object[]` instead of `PSCustomObject`.

Then verify the contract cases still behave (the assertion should pass for arrays and only fail for scalars):
- `$raw = '[]'` → parsed type `System.Object[]`, count 0, passes.
- `$raw = '[{"id":9}]'` → `System.Object[]`, count 1, passes.
- `$raw = '[{"id":1},{"id":2}]'` → `System.Object[]`, count 2, passes.
- `$raw = '{"id":9}'` (scalar/object wire value) → not an array, throws `Expected JSON array` as intended.

Optional hardening, per the wire-framing note: since `-isnot [array]` on a re-piped value can't prove wire shape, also assert on the trimmed raw JSON (`$raw.Trim()` starts with `[` and ends with `]`) and record the element count. That makes the probe robust even if the value is later re-enumerated, and works identically on 5.1 where `-NoEnumerate` is unavailable.
