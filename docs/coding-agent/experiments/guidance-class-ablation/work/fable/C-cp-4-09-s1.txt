**Verdict: block.**

**1. `permission.php`, `checkPermission` — a permission *check* now performs an export *submission* (hidden side effect).**
The function is named and typed as a predicate (`bool` in, `bool` out), but it now mutates the global outbox. Per the reviewer notes, `$queue` is the process-local outbox and export submission is a separate user action. With this change, every call to `checkPermission(true)` enqueues an export. Since the check runs on every render, an admin simply viewing a page will fire one export per render — duplicated, unrequested submissions with no user action behind them. No caller reading `checkPermission(...)` would expect that. This is exactly the hidden coupling/effect the review criteria call out: the function's name says "check", its body says "submit".
Require: `checkPermission` stays pure. Enqueueing to `$queue` belongs only in the handler for the explicit export action, after that handler has confirmed permission.

**2. `permission.php` — the change does not do what the task asks.**
"Expose export permission to toolbar" means the toolbar needs a way to *ask* whether export is allowed (to show/enable the button). Nothing here gives the toolbar that: the signature is unchanged, there's no export-specific predicate, and the only new behavior is an unrelated write. The commit message describes an intent the diff doesn't implement.
Require: add an explicit, named capability the toolbar can query — e.g. `function canExport(bool $admin): bool { return $admin; }` (or have `checkPermission` take an action name, e.g. `checkPermission(bool $admin, string $action): bool`) — and have the toolbar call that to decide whether to render the control. No queue involvement at all on the read path.

**3. `permission.php` — `global $queue` introduces hidden coupling to process state.**
Even setting aside the semantics, reaching into a global from inside a permission helper makes the function's behavior depend on invisible context and makes it untestable in isolation. This shouldn't be added; once finding 1 is fixed it goes away naturally.

Summary of what I'd accept: revert the body of `checkPermission` to its original one-liner (or extend it purely with an action parameter), add a pure `canExport`-style entry point the toolbar uses for display, and keep all `$queue[] = "export"` writes in the export-submission handler where the user actually clicked.
