**Cause**

This is a file lock, not a permissions or dependency problem. `npm install` needs to unlink `node_modules\onnxruntime-node\bin\napi-v3\win32\x64\onnxruntime_binding.node`, but that native addon is mapped into a running process: `node.exe` PID 4108, the model preview server launched from `C:/work/npm-lock/workers/model-preview.js`. Windows won't allow unlinking a loaded `.node`/DLL image, so npm gets `EBUSY` (errno -4082). Everything else checks out — lockfile in sync, registry reachable, directory writable, probe file create/delete works, no ACL denial — so there's nothing to fix in the workspace itself.

**Smallest safe remediation**

1. Stop the preview server gracefully (Ctrl+C in its terminal / its normal stop path). It's owned by this repo, so stopping it is in scope. Only if it won't exit: `taskkill /PID 4108 /F`.
2. Re-run `npm install`.

Don't run as admin, delete `node_modules`, or clear the npm cache — none of those address a lock and they add risk/time.

**Confirmation**

- `tasklist /m onnxruntime_binding.node` → "No tasks are running which match the specified criteria" before retrying.
- `npm install` exits 0 with no EBUSY/EPERM.
- `node -e "require('onnxruntime-node')"` from `C:/work/npm-lock` loads without error (the binary is intact and matches the runtime).
- Restart the preview server and verify it serves again.

If the retry fails on a *different* `.node` file, repeat the `tasklist /m <that file>` step; if it fails on the same file, check `tasklist | findstr node` for another holder (e.g. an editor extension that re-launched the worker).
