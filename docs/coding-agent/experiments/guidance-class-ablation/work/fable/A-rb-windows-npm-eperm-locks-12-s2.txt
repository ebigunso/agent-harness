**Cause**

`npm ci` deletes `node_modules` before reinstalling. On Windows a loaded native addon (`.node` DLL) cannot be unlinked while a process has it mapped, so the unlink of `sharp-win32-x64.node` fails with `EPERM`/errno `-4048`. The fresh `tasklist /m` output shows exactly one holder: `node.exe` PID 4114, the repository's own thumbnail watcher (`workers/thumbnails.js`), which has `C:\work\npm-lock\node_modules\sharp\build\Release\sharp-win32-x64.node` loaded.

This is not a permissions, ACL, cache, registry, or lockfile problem — the probe file beside the module can be created/removed, and package.json/package-lock.json are in sync. It is a file-in-use lock held by a process this repo controls. The earlier `better_sqlite3.node` / PID 4113 entry is history only; that worker is already gone and is not the current blocker.

**Smallest safe remediation**

Stop the thumbnail watcher (PID 4114), then re-run the install. Since it's a repo-owned background worker, use its normal stop path if one exists (e.g. the script/task that launched it); otherwise terminate it directly:

```powershell
Stop-Process -Id 4114
npm ci
```

Don't reach for `taskkill /F /IM node.exe` (would kill unrelated Node processes, including editors/language servers), don't run elevated, don't `rm -rf node_modules` with force while the file is still mapped (same lock, same failure), and don't add antivirus exclusions — nothing points at AV here.

If the watcher is expected to run continuously, it should be started after `npm ci` completes (or the dev workflow should stop it before dependency changes).

**Confirmation**

1. Before re-running, verify the lock is released:
   ```powershell
   tasklist /m sharp-win32-x64.node
   ```
   Expected: `INFO: No tasks are running which match the specified criteria.` (and `Get-Process -Id 4114` errors with "Cannot find a process").
2. `npm ci` exits 0 with no `EPERM`/`unlink` errors.
3. The addon was reinstalled cleanly and loads:
   ```powershell
   Test-Path .\node_modules\sharp\build\Release\sharp-win32-x64.node
   node -e "console.log(require('sharp').versions)"
   ```
4. Restart the thumbnail watcher (`node workers/thumbnails.js` or its usual launcher) and confirm it comes up, so the dev environment is back to its prior state.
