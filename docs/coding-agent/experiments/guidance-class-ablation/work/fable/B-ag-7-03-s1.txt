**Findings**

1. **`poller.py`, `logger.debug("poll payload: %r", payload)` — unbounded debug volume evicts the fatal signals from a shared bounded sink.**
   - *What's wrong:* `poll` runs every 10 ms and emits the full ~64 KiB payload each time (~6.4 MB/s, ~100 records/s) into the same bounded-retention sink that receives the rare ERROR records for fatal outcomes. Retention will be saturated by debug traffic within seconds; by the time anyone looks for the fatal record, it has been rotated out.
   - *Why it matters:* This directly triggers the Gate 7 anti-pattern "overly noisy instrumentation that hides actionable indicators." The change makes the critical, already-instrumented failure path *less* diagnosable than before, which is the opposite of the observability goal. Emitting at DEBUG doesn't help when the sink admits DEBUG.
   - *Require instead:* One of: (a) log a bounded summary instead of the payload — length, hash/checksum, sequence/timestamp, or a truncated head — so per-record cost is tens of bytes not 64 KiB; and/or (b) rate-limit/sample the debug emission (e.g., every Nth poll or at most once per second, plus on change); and/or (c) route debug output to a separate sink/logger name so it cannot displace ERROR retention. Any of these must be accompanied by a note in the change on the expected volume and its effect on ERROR retention.

2. **`poller.py` — the change is not gated off in production or documented as debug-only.**
   - *What's wrong:* Even with the fix above, `%r` of a 64 KiB payload at 10 ms cadence is a non-trivial cost (formatting the repr on every tick, regardless of whether the record is retained). There's no `logger.isEnabledFor(DEBUG)` guard or configuration hook, and the commit message/task give no indication of who consumes this or when it should be turned off.
   - *Why it matters:* Observability should be actionable. "Payload every 10 ms" is a firehose, not a signal; without a stated diagnostic question it answers, this is instrumentation for its own sake and will likely be left on.
   - *Require instead:* State what failure/behavior the output is meant to diagnose (e.g., stale reads, malformed payloads) and instrument for that specifically; guard the repr with `isEnabledFor` if the formatting cost is real at this cadence.

**Not a finding (assessed, cleared):**
- Sensitive-data exposure: reviewer notes confirm payloads are synthetic, non-sensitive measurements. No PII/secret risk in the logged content. Style (`payload=read()` missing spaces) is trivial and not worth blocking; mention only if the repo runs a formatter.

**Verdict:** Block. Finding 1 is a regression in observability of the fatal path, not an additive debug aid.
