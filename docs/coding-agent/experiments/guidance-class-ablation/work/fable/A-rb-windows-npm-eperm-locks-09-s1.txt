**Cause**

`npm ci` wipes `node_modules` before reinstalling, and it failed on `unlink` of `node_modules\node-pty\build\Release\pty.node` with `EPERM` (errno -4048). This is not a permissions, ACL, cache, lockfile, or registry problem — the probe file beside the module can be created/removed fine and the lockfile is in sync. The file is simply held open: `tasklist /m pty.node` shows the native addon is mapped into `electron.exe` (PID 4109), the repo's own Electron terminal preview (`preview/main.js`). On Windows, a loaded DLL/`.node` image cannot be deleted while a process has it mapped, so npm's rm step is rejected. This is a workspace-state issue (a running process from this repo), not an npm or environment defect.

**Smallest safe remediation**

Stop the Electron preview that holds the module, then rerun. Since it's the repo's own dev process, closing it is safe — nothing else depends on it, and it will just need to be relaunched afterward.

```powershell
# confirm it's the expected holder before killing anything
Get-Process -Id 4109 | Select-Object Id, ProcessName, Path

# close it gracefully first (lets it save state); fall back to force if it doesn't exit
Stop-Process -Id 4109
Start-Sleep -Seconds 2
if (Get-Process -Id 4109 -ErrorAction SilentlyContinue) { Stop-Process -Id 4109 -Force }

npm ci
```

Don't reach for broader fixes (running as admin, deleting `node_modules` by hand, clearing the npm cache, disabling antivirus) — none of them address the lock, and elevated rights won't let you unlink a mapped image either.

One thing to be aware of after the reinstall: the notes say the addon in place was rebuilt for the Electron ABI. `npm ci` will replace it with a build for Node 20's ABI, so the preview will likely need `electron-rebuild` (or your existing rebuild script) before it can load `pty.node` again. That's expected behavior, not a regression from this fix.

**Confirmation**

1. Nothing holds the file anymore:
   ```powershell
   tasklist /m pty.node
   ```
   should report "No tasks are running which match the specified criteria."
2. `npm ci` exits 0 with no `EPERM` in stderr.
3. `node_modules\node-pty\build\Release\pty.node` exists with a fresh timestamp, and `npm ls node-pty` shows `node-pty@1.0.0` without errors.
4. Relaunch the preview (after rebuilding for Electron if needed) and verify it starts and the terminal works.
