**Findings**

1. **`lib.rs`, `let (retry, quarantine, reject) = policy::flags(code);` — destructuring order contradicts the tuple contract.**
   `policy::flags` documents and returns `(retry, reject, quarantine)`. `lib.rs` binds position 1 to `quarantine` and position 2 to `reject`. Result: code 2 (reject) routes to `"quarantine"`, code 3 (quarantine) routes to `"reject"`. Given the stated mapping (2 = reject, 3 = quarantine), this is a behavioral bug that inverts two outcomes — a rejected upload ends up in the inspection path and a quarantined one is dropped as rejected. Blocking. Fix the binding order (or, better, remove the positional contract entirely — see #2) and add tests for codes 0–3 asserting each route string; nothing in the change exercises the two new branches.

2. **`policy.rs`, `flags` return type `(bool, bool, bool)` — hidden positional coupling.**
   The meaning of each slot lives only in a comment in a different module; the caller has no way to be told it's wrong, which is exactly how #1 happened. The three flags are also mutually exclusive by construction, so a tuple of bools misrepresents the domain (it invites the caller to reason about combinations that can't occur, and forces an arbitrary `if/else if` priority order in `route`). Require an enum:
   ```rust
   pub enum Disposition { Accept, Retry, Reject, Quarantine }
   pub fn disposition(code: u8) -> Disposition { match code { 1 => Retry, 2 => Reject, 3 => Quarantine, _ => Accept } }
   ```
   and a `match` in `route`. That makes the mapping self-describing at the use site, removes the ordering contract, and lets the compiler enforce exhaustiveness.

3. **`policy.rs`, `_ => accept` behavior is implicit.** With the tuple, any code outside 1–3 (including 0) silently becomes `"accept"`. The notes say the parser validates the range, but `flags` is `pub` and encodes no such assumption. If the enum in #2 is adopted, either make the wildcard arm explicit with a comment referencing the parser guarantee, or restrict the function to accept only validated input. Minor; would flag, not block.
