**Verdict: Block.** The change replaces a correct one-line function with an interpreter for a single hard-coded expression. Behavior is unchanged; complexity, cost, and failure surface all go up.

## Findings

**1. `label.ts` — entire diff: accidental complexity with no second use**
The original `ready ? "Ready" : "Waiting"` fully satisfies the task. The new code introduces an `Expr` type, an `operators` dispatch table, and a serialized "program" to express the same ternary. Per the reviewer notes there are exactly two fixed labels, no configurable UI rules are required, and nothing else consumes `Expr` or `operators`. An abstraction with one caller and no anticipated second caller is not an abstraction — it's indirection. Anyone reading this later must trace type → table → JSON → parse → dispatch to learn that it prints "Ready" or "Waiting". **Require:** revert to the original one-liner.

**2. `label.ts` lines 3, 5–6: `JSON.stringify` → `JSON.parse` round-trip of a compile-time literal**
The object is authored in source, serialized at module load, then re-parsed on *every* call to `label`. This adds allocation and parsing work per render, and it throws away the static type: the `as Expr` cast is unchecked, so the compiler can no longer verify that the literal actually matches `Expr` (a typo in `"choose"` or a missing `yes` becomes a runtime `undefined`/`TypeError` instead of a compile error). Even if the interpreter pattern were justified, the object should be a typed constant, not a string. **Require:** remove the serialization entirely.

**3. `label.ts` line 6: `operators[expr.op]` dispatch over a one-member union**
`Expr["op"]` has exactly one value, so the table lookup is a constant. This is dead generality — it exists only to look extensible while nothing can extend it. If a real need for multiple operators arrives, the shape will likely differ from this guess (e.g., needing context beyond `ready`), and this scaffolding will have to be reworked anyway. **Require:** none of this until a second real operator exists.

**4. Commit message — does not describe the change**
"display ready or waiting label" describes the pre-existing behavior, not the modification. The actual change is a rewrite of the implementation with no behavioral delta, and the message gives a reviewer no rationale for why. **Require:** either a message explaining the motivation (there isn't a defensible one here) or, given finding 1, no commit at all.

```ts
export function label(ready: boolean) { return ready ? "Ready" : "Waiting"; }
```
