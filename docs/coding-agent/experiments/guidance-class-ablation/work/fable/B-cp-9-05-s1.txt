*What's wrong:* The original errors carried the job id, the failing stage (`parse` vs `store`), and the underlying error's Display text. The new code discards all three (`|_|`) and returns the constant string `"job failed"` for every failure.

*Why it matters:*
- The task is to report failures at the job boundary *with useful diagnostic context*. This diff removes the only context that existed. Since the supervisor logs only the returned error and no lower layer logs these failures, every worker failure will now appear in logs as an undifferentiated `"job failed"` — no job id to correlate, no way to tell a malformed payload from a storage outage, no error category to alert on. This is exactly the "swallowing failures / converting them into ambiguous states" the guideline warns against.

- Operationally, an incident like "store backend is down" becomes indistinguishable from "one bad payload," which degrades triage and can mask a systemic fault behind what looks like sporadic noise.
- The commit message ("standardize error text") doesn't match the stated task, suggesting the change was motivated by cosmetic uniformity rather than the requirement.
