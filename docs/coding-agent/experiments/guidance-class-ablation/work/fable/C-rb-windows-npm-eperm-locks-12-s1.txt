## Cause

Not a permissions, cache, lockfile, or registry problem — those all check out (probe file create/delete beside the module succeeds, no ACL denial, lock is synchronized). This is a Windows file lock: `npm ci` deletes `node_modules` before reinstalling, and it cannot unlink `sharp\build\Release\sharp-win32-x64.node` because a running process has that native addon mapped as a loaded DLL. Windows refuses `unlink` on a mapped image (EPERM, errno -4048).

The holder is identified: `tasklist /m sharp-win32-x64.node` → `node.exe` PID **4114**, the thumbnail watcher launched from `C:/work/npm-lock/workers/thumbnails.js`. It's a repo-owned dev process, so it's safe to stop.

Note this is the second holder in a row (previous attempt: `better_sqlite3.node`, PID 4113, since cleared). The repo evidently runs multiple workers that each load a different addon, so expect to clear them one at a time — or check for all of them before the next retry.

## Smallest safe remediation

1. Stop the thumbnail watcher gracefully — via whatever started it (its terminal/Ctrl+C, the task runner, or its own stop script). Don't kill all `node.exe`; don't run npm as Administrator or hand-delete `node_modules` (neither bypasses a mapped-image lock).
2. Only if it won't exit: `taskkill /PID 4114 /F` — after re-confirming 4114 is still the PID shown by `tasklist /m sharp-win32-x64.node`.
3. Before retrying, run `tasklist | findstr node` and stop any other repo workers still running out of `C:\work\npm-lock`, so a third addon doesn't fail the next attempt.
4. Retry the original command: `npm ci`.

## Confirmation

- `tasklist /m sharp-win32-x64.node` reports `INFO: No tasks are running which match the specified criteria.`
- `npm ci` exits 0 with no EPERM/EBUSY in stderr.
- `node -e "require('sharp')"` from `C:\work\npm-lock` loads without error (fresh binary in place).
- Restart the thumbnail watcher afterwards and verify it comes up against the reinstalled sharp.

If `npm ci` fails again on a different `.node` path, repeat: read the new module name from the error, `tasklist /m <module>.node`, confirm repo ownership, stop, retry.
