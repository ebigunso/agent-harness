**Verdict: acceptable with two non-blocking flags.** The core contract is right — the input unit is named in the type (`scalar_index`), out-of-range is an unambiguous `None` rather than a panic or sentinel, the borrow doesn't outlive the call, and the test exercises a multi-byte scalar so a byte-offset regression would fail it. Nothing here I'd block.

**Findings**

1. **`lib.rs:1-5` — the unit contract lives in the field name and the reviewer notes, not on the public API.**
   `CharacterAt` / `CharacterResult` say "character"; the field says "scalar". Those are different things to most callers: "character" colloquially means grapheme cluster, and `"e\u{301}a"` has 2 graphemes but 3 scalars, so `scalar_index: 1` returns the combining mark, not `'a'`. The field name is a good start, but a caller reading only the struct name (or an IDE tooltip on `select`) has no doc stating that indexing is by Unicode scalar value, not grapheme and not byte, and that lookup is O(n). Since the task is literally "make units explicit," the explicitness should be in `///` docs on the pub items, not in the commit message. Require: doc comments on `CharacterAt::scalar_index` and `select` stating "Unicode scalar value index (as yielded by `str::chars()`); not a byte offset, not a grapheme cluster index; `None` if `scalar_index >= text.chars().count()`." Optionally rename to `ScalarAt` to remove the character/scalar tension, but the doc is the essential part.

2. **`lib.rs:8-9` — test literal depends on source-file normalization form.**
   `"éa"` only proves the byte-vs-scalar distinction if `é` is precomposed (U+00E9, 2 bytes, 1 scalar). If an editor, git attribute, or copy-paste normalizes the file to NFD, the string becomes `e` + U+0301 + `a`, index 1 yields `'\u{301}'`, and the test fails for a reason unrelated to the code under test. Require: `"\u{e9}a"` so the test's premise is pinned in the source, and consider adding a decomposed case (`"e\u{301}a"`, index 1 → `Some('\u{301}')`) to document that graphemes are *not* the unit — that turns the contract in finding 1 into an executable assertion.
