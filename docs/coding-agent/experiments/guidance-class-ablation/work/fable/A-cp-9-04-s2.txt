**Verdict: block.** The change retries, but it does so unconditionally and forever, which is worse than the original behavior for the permanent-failure case and unsafe for the transient case.

**Findings**

1. **`src/inventory.mjs`, catch block — unbounded retry, no termination.**
   There is no attempt counter, no overall deadline, and no exit condition other than eventual success. If the backend is down, the caller hangs indefinitely (each attempt only has a per-attempt timeout, so this is an unbounded sequence of timeouts, not a tight loop). Callers have no way to get a failure out of this function. The recursion also builds an ever-growing chain of pending promises. Require: a maximum attempt count (e.g. 3) and/or an overall time budget, after which the last error is rethrown.

2. **Same location — retries non-retryable errors.**
   `catch (error)` catches everything, including the permanent `ValidationError` for an invalid SKU. Combined with (1), a bad SKU now never returns; previously it failed fast with a useful error. Require: inspect the error and retry only `TransportError` (and any other explicitly transient classes); rethrow everything else immediately.

3. **Same location — no backoff between attempts.**
   Retries fire immediately on failure. During an outage every caller will hammer the inventory service back-to-back, extending the outage. Require: delay between attempts, preferably exponential backoff with jitter, capped.

4. **Same location — error is discarded.**
   `error` is captured and never used: not rethrown, not logged, not attached as a cause. Once attempts are bounded, the final failure must surface the last underlying error (e.g. rethrow it, or wrap with `{ cause: error }`) so callers and operators can see why the fetch failed.

5. **Missing tests.**
   The diff adds retry semantics with no coverage. Require tests for: transient `TransportError` succeeds on a later attempt; `ValidationError` is rethrown without retry; retries stop after the limit and the last error propagates; backoff delays are applied.

**Suggested shape** (illustrative, not prescriptive): a loop over `maxAttempts`, `try { return await api.inventory(sku) } catch (e) { if (!(e instanceof TransportError) || attempt === maxAttempts) throw e; await sleep(backoff(attempt)); }`.
