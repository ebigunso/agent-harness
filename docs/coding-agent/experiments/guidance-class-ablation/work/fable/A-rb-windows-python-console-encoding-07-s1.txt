**Cause**

Rendering succeeded; the failure is at `print()`. Because stdout is a pipe (not a Windows console), CPython 3.12 uses the ANSI code page for the stream encoding — here cp1252 — and UTF-8 mode is off (`sys.flags.utf8_mode = 0`). Cyrillic `Ж` (U+0416) has no cp1252 mapping, so `charmap_encode` raises `UnicodeEncodeError`. This is an environment/encoding configuration issue, not a template or Jinja2 bug.

**Smallest safe remediation**

Set stdout to UTF-8 for the invocation without touching the script:

```powershell
$env:PYTHONUTF8 = "1"; python templates.py
```

(Equivalent one-off: `python -X utf8 templates.py`, or narrower `$env:PYTHONIOENCODING = "utf-8"`.) This is reversible and affects only this process. If the script must be robust regardless of caller environment, the in-code equivalent is `sys.stdout.reconfigure(encoding="utf-8")` before printing — but prefer the env var first, since changing the script's output encoding is a behavior change for every consumer of the pipe.

**Confirmation**

```powershell
$env:PYTHONUTF8 = "1"
python -c "import sys; print(sys.stdout.encoding, sys.flags.utf8_mode)" | Out-String
# expect: utf-8 1
python templates.py | Out-String
# expect exit 0 ($LASTEXITCODE -eq 0) and the line "User Ж" present, no traceback
```

Optionally verify the bytes on the pipe are UTF-8 (`python templates.py > out.txt` then check `Ж` is encoded as `D0 96`) so the downstream reader decodes it consistently.
