**Cause:** Working-directory drift in the persistent shell. A prior `Set-Location` moved the shell's cwd to `C:/work/orders/src/main/resources`, which contains only `application.properties`. Maven resolves the POM from the cwd, found none there, and exited 1 with "there is no POM in this directory." The project itself is fine — `C:/work/orders/pom.xml` exists, and nothing else (code, branch, PATH, deps, config, permissions) changed. This is not a workspace or build problem; it's the shell cwd being out of sync with the tool's remembered root.

**Smallest safe remediation:** Run Maven from the project root rather than relying on inherited cwd. Either:

```powershell
Set-Location -LiteralPath 'C:/work/orders'
mvn test
```

or, without touching shell state:

```powershell
mvn -f 'C:/work/orders/pom.xml' test
```

No file, config, or environment changes are needed.

Since the only difference between the failing and passing runs is the explicit navigation, the diagnosis is confirmed.

**Preventive note:** In a persistent shell, don't assume the cwd matches the tool's displayed root; prefix Maven invocations with an explicit `Set-Location` to the base or use `-f` with an absolute POM path.
