**Cause**

This is not a pipeline-unrolling or workspace problem, and the reference note about `-is [array]` / `-NoEnumerate` does not apply. The script already does the right thing: it validates framing on the raw serialized string (`Trim()`, `StartsWith('[')`, `EndsWith(']')`), not on the parsed object. The assertion failed because the input genuinely is not an array — `$raw` is `{"id":7}`, a single JSON object with `{`/`}` framing. `ConvertFrom-Json` succeeded (the payload is valid JSON), so the only thing wrong is the shape of the data versus the contract the probe enforces. Exit code 1 and the `throw` at line 8 are the probe working as designed.

**Smallest safe remediation**

Leave the assertion alone — it is correct and the one you actually want (raw framing, not post-pipeline type). Fix the input to match the contract. In this script the payload is a hardcoded literal, so the change is the framing on line 3:

```powershell
$raw = '[{"id":7}]'
```

If in the real flow `$raw` comes from a producer (file, API, another command), the fix belongs at that producer: it must emit an array (`[...]`) even for one element. Don't "fix" this by wrapping in the consumer (`"[$raw]"`) or by relaxing the check to accept objects — that would hide the very cardinality drift this probe exists to catch.

If instead the contract is wrong and a bare object is acceptable, then the correct change is to the probe's requirement, not the data — but that's a spec decision, not a bug fix, and nothing in the diagnostics suggests it.
