**Finding 1 — `config.ts` lines 1–2: importing the preset mutates global state as a side effect (blocking)**

`locale.current = "fr-FR";` runs at module top level, so merely importing `config.ts` silently changes what `format()` returns for every caller in the process. Per the reviewer notes, the formatter is used both before and after the preset is dynamically imported, and importing settings is expected to expose values only. As written, the same `format(1234.5)` call yields `"1,234.5"` before the import and `"1 234,5"` after it, purely as a function of module-evaluation order. That's action at a distance: nothing at the call site indicates the locale changed, the behavior is non-deterministic across code paths that do/don't touch `config.ts`, and it's also unconditional — anyone importing `theme` gets French formatting whether they wanted it or not. Tests that import `config.ts` will also leak the mutation into other tests.

This also means the change doesn't actually deliver a "preset": `config.ts` exports nothing French — it exports `theme` and hides the locale choice inside a side effect.

Required instead: make the preset a value and make application explicit, e.g.

```ts
// config.ts
export const frenchPreset = { locale: "fr-FR" } as const;
export const theme = "light";
```

and have the consumer apply it deliberately (`applyPreset(frenchPreset)` / `setLocale(frenchPreset.locale)`), or thread the locale into `format(n, locale)`. No top-level statements with observable effects in a settings module.

**Finding 2 — `locale.ts` line 1: exporting a mutable shared object invites exactly the above (flag, fix alongside)**

`export const locale = {current: "en-US"}` exposes writable global state to every importer, which is what made the silent mutation in `config.ts` possible. Require either a setter with a single, explicit entry point (`export function setLocale(l: string)`) so changes are greppable and intentional, or pass the locale as a parameter to `format` and drop the module-level mutable state entirely.

Not blocking on its own: `format` constructs a new `Intl.NumberFormat` per call, which is relatively expensive; cache per locale if this is on a hot path.
