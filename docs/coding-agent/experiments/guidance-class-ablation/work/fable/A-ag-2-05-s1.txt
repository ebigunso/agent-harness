**Verdict: block.** The change solves the task in the wrong layer.

## Findings

**1. `core.rs` — HTTP dependency introduced into a transport-agnostic crate**
`use axum::http::StatusCode;` pulls `axum` (or at minimum `http`) into core. Core is consumed by the CLI, which now has to compile an HTTP stack it never uses, and every future consumer inherits the same coupling. The fix belongs at the boundary: keep core returning `RuleError` and convert in the HTTP crate, e.g. `impl IntoResponse for RuleError` (or `impl From<RuleError> for StatusCode`) in the axum handler module, with `Rejected => StatusCode::FORBIDDEN`. That's the standard axum 0.8 pattern and needs zero changes to core.

**2. `core.rs` — `allow()` signature change breaks the CLI caller**
`allow` now returns `Result<(), StatusCode>`; any existing CLI code matching on `Err(RuleError::Rejected)` no longer compiles, and the CLI would have to interpret HTTP status codes to render a message. The diff touches only core, so the CLI is either broken or was never checked. Require: signature stays `Result<(), RuleError>`; all callers of `allow` across the workspace verified to build.

**3. `core.rs` — `RuleError` left as dead code**
The enum is still declared but nothing constructs or consumes it. If the author's intent were to keep it, it's now unused (and will warn); if the intent were to replace it, it should have been removed — either way it signals the design wasn't thought through. With finding 1 applied this resolves itself: `RuleError` remains the sole error type.

**4. Semantics: lossy mapping**
Collapsing a domain error into a bare `StatusCode` discards the reason. Today there's one variant, so it looks harmless, but the moment `RuleError` grows a second variant the HTTP layer can't distinguish them and the CLI can't report them. Keeping the domain enum and mapping to status at the edge preserves the information and lets each transport choose its own representation (403 for HTTP, exit code / stderr text for CLI).

## What I'd accept instead

- Revert `core.rs` entirely.
- In the HTTP crate: `impl IntoResponse for core::RuleError { fn into_response(self) -> Response { match self { RuleError::Rejected => StatusCode::FORBIDDEN.into_response() } } }` and have the handler return `Result<_, RuleError>` (or `?` it).
- A handler test asserting 403 on rejection, and a CLI build/test run to prove nothing regressed.
