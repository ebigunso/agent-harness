**Cause**

Not a workspace problem — it's a runtime output-encoding issue. Rendering finished (`"# Weather ☃"` was built), and the crash happened at `print(markdown)` on line 31. Because stdout is a pipe rather than a console, CPython 3.12 on Windows fell back to the locale code page (`sys.stdout.encoding = cp1252`, `utf8_mode = 0`). cp1252 has no mapping for U+2603 (☃, "position 10" of the string), so `charmap_encode` raised `UnicodeEncodeError`.

**Partial-effect check before rerun**

Safe to rerun: stdout is empty (nothing partially emitted), and the script made no file writes. Rerunning has no cleanup prerequisite.

**Smallest safe remediation (command-scoped, no code change)**

```powershell
$env:PYTHONIOENCODING = 'utf-8'; python md_report.py; Remove-Item Env:\PYTHONIOENCODING
```

Equivalent single-invocation form: `python -X utf8 md_report.py` (enables UTF-8 mode for that process only).

Make sure whatever consumes the pipe decodes it as UTF-8 (e.g. in PowerShell 7: `[Console]::OutputEncoding = [Text.Encoding]::UTF8` or `$OutputEncoding`), otherwise you'll get mojibake instead of a traceback.

**If you own the script (durable fix)**

Add near the top of `md_report.py`:

```python
import sys
sys.stdout.reconfigure(encoding="utf-8")
```

And if it ever writes the report to disk, use `open(path, "w", encoding="utf-8")` — don't rely on the default.

**Confirmation**

1. Rerun with the override: exit code 0, no traceback, stdout is `# Weather ☃` (bytes `E2 98 83` for the snowman).
2. Sanity check the stream encoding in the same piped setup: `python -c "import sys; print(sys.stdout.encoding)" | cat` should print `utf-8` (with `PYTHONIOENCODING` set or `-X utf8`) versus `cp1252` without.
