**Findings**

1. **`Checkout.tsx`, `Checkout` component body (`const eligible = days >= 365; const price = cents - (eligible ? 100 : 0);`)** — The loyalty discount rule is re-implemented inside the React view instead of being obtained from `applicationPrice`, which already exists in the same file and is the shared policy the API and mobile channels call. This is UI-layer policy duplication: the moment the threshold or discount amount changes (the notes say changes are upcoming), the API and mobile will follow `applicationPrice` while web checkout silently diverges and shows a different price to the customer. It also makes the rule untestable at one point and invites further copies. Required: the component must not compute the discount. Either accept the already-computed price as a prop (keep the original `{price: number}` signature, with the caller invoking `applicationPrice(days, cents)` in the app/domain layer), or, at minimum, call `applicationPrice(days, cents)` directly rather than inlining `days >= 365` / `100`. Preferred is the former, since the component should render a result, not own inputs to policy.

2. **`Checkout.tsx`, props change `{price}` → `{days, cents}`** — The public signature of `Checkout` is changed from "render this price" to "here are the raw inputs, work out the price yourself," which relocates responsibility from the application layer into the view. The diff does not show any callers being updated, and no plan/owner mapping was given for what this move implies for existing call sites or for whether the API/mobile pricing path stays the single source of truth. Required: keep `Checkout` as a presentational component taking the final price; if the prop change is retained for some reason, the PR must list the affected callers and explain why the view now owns pricing inputs — which, per the layering guidance, it should not.

Not flagged: `applicationPrice` itself is unchanged and remains the correct home for the rule; the `cents >= 100` and validated-days invariants mean no additional guard is needed here.
