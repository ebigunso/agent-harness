**Cause**

Not a bug in the report logic — the summary was computed fine (`'Summary \u2014 complete'`). The failure is at output time: stdout is a pipe, not a console, so CPython 3.12 with `utf8_mode = 0` picks the process ANSI code page (cp932) for `sys.stdout`. Python's cp932 codec maps Shift_JIS 0x815C to U+2015 (HORIZONTAL BAR), not U+2014 (EM DASH), so the em dash in position 8 is unencodable and `print()` raises `UnicodeEncodeError`. Exit 1, nothing printed.

**Partial effects before rerunning**

None to clean up: the summary is read-only, no files are written, stdout is empty. Rerunning is safe.

**Smallest safe remediation (command-scoped, no code change)**

Force UTF-8 for this invocation only. Note PowerShell has no `VAR=value cmd` inline syntax — `$env:X = ...` persists for the session — so the cleanest command-scoped form is the interpreter flag:

```powershell
python -X utf8 report.py
```

If you specifically want the `PYTHONIOENCODING` route from the runbook, scope it explicitly:

```powershell
$env:PYTHONIOENCODING = 'utf-8'
try { python report.py } finally { Remove-Item Env:PYTHONIOENCODING }
```

(Or `cmd /c "set PYTHONIOENCODING=utf-8 && python report.py"`.)

If `report.py` owns its stdout and this should be permanent, the durable fix is at the top of the script:

```python
import sys
sys.stdout.reconfigure(encoding="utf-8")
```

and `encoding="utf-8"` on any `open()` for writing, should the script later write files. Don't set `PYTHONIOENCODING`/`PYTHONUTF8` machine-wide as the "fix" — that silently changes behavior for every Python process on the box.

**Confirmation**

1. Rerun with the override; expect exit code 0 and stdout `Summary — complete`, stderr empty.
2. Check the effective encoding in the same captured-stream setup:
   `python -X utf8 -c "import sys; print(sys.stdout.encoding, sys.flags.utf8_mode)"` → `utf-8 1`.
3. Verify the bytes, since the pipe consumer must also decode UTF-8: `python -X utf8 report.py > out.txt; Format-Hex out.txt` should show `E2 80 94` for the dash. If PowerShell displays mojibake for the native command's output, that's the reader side — set `[Console]::OutputEncoding = [System.Text.UTF8Encoding]::new()` in that session, not another Python change.
4. Record for the ticket: the original error (`cp932`, `'\u2014'`, position 8), the override command used, and the successful output.
