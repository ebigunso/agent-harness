## Findings

### 1. BLOCK — `poller.py`, `logger.debug("poll payload: %r", payload)`: unbounded debug volume evicts fatal records from the shared retention sink

**What's wrong:** `poll()` runs every 10 ms and the payload is ~64 KiB. `%r` serializes the entire payload on every call, so this line emits roughly 100 records/s × 64 KiB ≈ 6.4 MB/s of DEBUG into the same bounded sink that holds ERROR/fatal records. Retention is finite; at that rate the sink turns over in seconds, and any rare fatal record written before the next rotation is gone by the time someone looks for it.

**Why it matters:** The sink exists so that the *rare* fatal outcomes survive long enough to be diagnosed. This change makes the common, uninteresting case crowd out the rare, critical one. The debug output is not merely noisy — it actively destroys the diagnostic value the sink was there to provide. Payload sensitivity is not the concern (they're synthetic and non-sensitive); volume is.

**What I'd require instead** (any one, preferably the first plus one of the others):
- Do not log the payload body. Log a small summary — e.g. length, type, a sequence counter, or a short digest — which is what you actually need to see that polling is alive and returning something. A single ~64 KiB `repr` is not useful debug output anyway; nobody reads it.
- Rate-limit or sample the debug line (e.g. every Nth poll, or at most once per second), so the steady-state rate is bounded regardless of poll frequency.
- Route poller DEBUG to a separate sink/handler with its own bound so it cannot displace ERROR records. If the logger is a stdlib `Logger`, this is a handler-level filter, not something `poll()` should have to know about, but the commit must not land against the shared sink as-is.
- If the intent is truly ad-hoc debugging, gate it behind an explicit opt-in (config flag or a dedicated `poller.payload` child logger that is off by default), and say so in the commit message.

Note that lazy `%r` formatting is already correct — the repr is only computed if DEBUG is enabled — so this does not help here because the reviewer notes state DEBUG *is* accepted by the sink.

### 2. Nit — formatting

`payload=read()` and `"...%r",payload` are missing spaces around `=` and after `,`. Not blocking, but fix it while you're in the line; the rest of the file follows PEP 8.

---

**Verdict:** Not acceptable as-is. Finding 1 must be addressed before merge. The commit message ("add polling debug output") also understates the operational impact; whatever mitigation is chosen (summary/sampling/separate sink) should be mentioned so the next reader knows the retention interaction was considered.
