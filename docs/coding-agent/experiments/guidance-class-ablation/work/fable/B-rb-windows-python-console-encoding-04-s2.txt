## Cause

`audit.py` did its work — the file `C:/reports/🧪.txt` was opened and inspected successfully (Windows filesystem APIs are UTF-16, so the emoji in the filename is fine). The crash is purely at the output site: `print(path)` at line 40 tries to encode `U+1F9EA` (🧪) with the `cp932` codec, which cannot represent it.

One correction to the reference note's framing: stdout here is a **pipe, not an interactive console**, so this isn't the console code page being inherited. When stdout is not a console and UTF-8 mode is off (`sys.flags.utf8_mode = 0`), CPython on Windows falls back to the locale/ANSI code page (`locale.getpreferredencoding(False)`), which on a Japanese-locale machine is cp932. That is why `sys.stdout.encoding = cp932` even in a captured stream. Same remediation family, different mechanism — worth knowing because "use a UTF-8 terminal" would *not* fix this case.

This is an environment/encoding configuration problem, not a data or workspace-content problem. Nothing in the repo or the reports directory is broken.

## Smallest safe remediation

Rerun with the I/O encoding overridden, no code change:

```powershell
$env:PYTHONIOENCODING = 'utf-8'; python audit.py
```

(Equivalent alternative: `$env:PYTHONUTF8 = '1'; python audit.py`, which enables UTF-8 mode for all default encodings, not just stdio. Either is fine; `PYTHONIOENCODING` is the narrower change.)

**Side-effect check:** the audit is read-only per the observations, and the exception fired during `print`, so there is nothing partial to clean up. No rollback needed.

**If you own `audit.py`** and want it to stop depending on the caller's environment, add near the top:

```python
import sys
sys.stdout.reconfigure(encoding="utf-8")
```

Optionally `errors="backslashreplace"` if you'd rather never crash on output even under a hostile encoding. Any file writes should likewise pass `encoding="utf-8"` explicitly.

## Confirmation

1. Rerun with the override; expect exit code 0 and `C:/reports/🧪.txt` (or however `path` is formatted) on stdout with no traceback.
2. If you want to verify the mechanism rather than just the symptom: `$env:PYTHONIOENCODING='utf-8'; python -c "import sys; print(sys.stdout.encoding)"` piped the same way should print `utf-8` instead of `cp932`.
3. If you applied the `reconfigure` fix, run `python audit.py` **without** the env var, still through the pipe, and confirm it succeeds — that proves the script is self-sufficient.

Evidence to keep: the original `UnicodeEncodeError ... '\U0001f9ea' ... cp932` line and the successful rerun command.
