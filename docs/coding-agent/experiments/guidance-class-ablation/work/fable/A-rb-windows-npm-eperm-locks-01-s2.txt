**Cause**

`npm ci` deletes `node_modules` before reinstalling. On Windows, a native addon (`better_sqlite3.node`) that is loaded into a running process is locked by the OS and cannot be unlinked, so npm gets `EPERM`/errno `-4048`. This is not a permissions or workspace-config problem: the lockfile is in sync, the directory is writable, the probe file works, and there's no ACL denial. `tasklist /m` shows exactly one holder — PID 4101, the repo's own Express/TypeScript dev server (`src/server.ts`), which loaded the addon from this project's `node_modules` and is still running in its original terminal.

**Smallest safe remediation**

Stop that dev server, then rerun the install. Prefer a graceful stop (Ctrl+C in its terminal) since it's your own process and may hold an open SQLite database; only fall back to `Stop-Process -Id 4101` if it won't exit. Do not delete `node_modules` by hand, run as admin, or disable antivirus — none of those address the lock, and the message's antivirus hint is a red herring here.

```powershell
# in the dev server's terminal: Ctrl+C
# if it doesn't exit:
Stop-Process -Id 4101

npm ci
```

**Confirmation**

1. `tasklist /m better_sqlite3.node` returns "No tasks are running which match the specified criteria" (or at least no PID holding this repo's path).
2. `npm ci` exits 0 with no `EPERM`.
3. `Test-Path node_modules\better-sqlite3\build\Release\better_sqlite3.node` is `True`, and `node -e "require('better-sqlite3')"` loads without error (the binary is a source build for this host runtime, so a rebuild step during `npm ci` should succeed the same way it did before).
4. Restart the dev server and verify it comes up normally.
