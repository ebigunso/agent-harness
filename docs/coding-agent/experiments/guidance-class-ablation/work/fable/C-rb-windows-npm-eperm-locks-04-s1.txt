**Cause:** This is a workspace problem, not an npm/registry/permissions defect. `npm ci` deletes `node_modules` before reinstalling, and the `unlink` of `@parcel\watcher\build\Release\watcher.node` fails with EPERM (errno -4048) because a running process has that native addon mapped. `tasklist /m watcher.node` identifies exactly one holder: `node.exe` PID 4104, which is this repository's own Parcel/Vue watch script (`scripts/watch.js`), detached from its original shell. Windows cannot unlink a loaded DLL/.node, so npm aborts. Everything else checks out (lockfile in sync, ACLs fine, probe file writable, registry reachable), so nothing besides the holder needs changing.

**Smallest safe remediation (in order):**

1. Stop the watcher gracefully first. Its shell is gone, so send a normal termination rather than a forced one:
   ```powershell
   taskkill /PID 4104
   ```
   Give it a moment, then check whether it exited:
   ```powershell
   tasklist /m watcher.node
   ```
2. Only if PID 4104 is still listed, force it — this is safe because the process is confirmed to be the repo's own dev watcher, not an editor or unrelated tool:
   ```powershell
   taskkill /PID 4104 /F
   ```
3. Retry the original command unchanged:
   ```powershell
   npm ci
   ```

Do not delete `node_modules` by hand, change ACLs, run as admin, or disable antivirus — none of those address the actual cause and the observations already rule them out.

**Confirmation:**

- `tasklist /m watcher.node` returns "No tasks are running which match the specified criteria." (no rows) before the retry.
- `npm ci` exits 0 with no EPERM/unlink output, and `node_modules\@parcel\watcher\build\Release\watcher.node` exists afterwards (rebuilt for Node 20.18.0, since 2.4.1 is a source build).
- Restart the dev watcher (`node scripts/watch.js`) after the install and confirm it loads the new addon without error.

**If the retry still fails:** re-check the new module named in the error and run `tasklist | findstr node` to find any other holder; another watch/test/editor process could have been started in between.

**Record for the log:** original command `npm ci` → `EPERM unlink ...\@parcel\watcher\build\Release\watcher.node` (errno -4048); holder from `tasklist /m watcher.node`: `node.exe` PID 4104 (`scripts/watch.js`, repo-owned); PIDs terminated: 4104 (note whether graceful or `/F` was needed); retry result of `npm ci`.
