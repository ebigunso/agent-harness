**Cause**

Not a bug in the script's logic and not a workspace/file problem — it's a stream-encoding mismatch in the runtime environment.

When stdout is a pipe rather than an interactive console, CPython on Windows doesn't use the console's UTF‑8 path; it falls back to the locale ("ANSI") code page for `sys.stdout`. On this machine that is `cp932` (Japanese), confirmed by `sys.stdout.encoding = cp932` and `utf8_mode = 0`. `🧪` (U+1F9EA) has no representation in cp932, so `print(status)` raises `UnicodeEncodeError`. `flush=True` is irrelevant — the failure happens while encoding, before anything is written, which is why stdout is empty.

**Smallest safe remediation**

Fix it at invocation, without touching the script, and scope the change to the stdio streams only:

```powershell
$env:PYTHONIOENCODING = 'utf-8'
python progress.py
```

Why this rather than `-X utf8` / `PYTHONUTF8=1`: UTF‑8 mode also changes the default encoding for `open()`. The script scans files read-only; if any of those are cp932-encoded and opened without an explicit `encoding=`, UTF‑8 mode would trade the encode error for a `UnicodeDecodeError`. `PYTHONIOENCODING` only affects stdin/stdout/stderr, which is exactly the thing that's broken.

If you'd rather fix it in code, the equivalent minimal change is one line at the top of `progress.py`:

```python
sys.stdout.reconfigure(encoding="utf-8")
```

**Confirmation**

1. Same captured-stream setup: `$env:PYTHONIOENCODING='utf-8'; python -c "import sys; print(sys.stdout.encoding)" | Out-String` → prints `utf-8`.
2. Re-run `python progress.py` piped/redirected (e.g. `python progress.py > out.txt`); expect exit code 0 and `out.txt` containing `Working 🧪` (verify with `Get-Content out.txt -Encoding utf8`).
3. Confirm the read-only scanning still works on the same files (no new decode errors), since the fix deliberately left `open()` behaviour untouched.

One caveat on display, not correctness: PowerShell decodes native-command output using `[Console]::OutputEncoding`. If that is also cp932 on this host, the bytes will be written correctly but may render as mojibake in the terminal; set `[Console]::OutputEncoding = [System.Text.Encoding]::UTF8` in the session if you need it to display properly. That doesn't affect the exit code or the piped bytes.
