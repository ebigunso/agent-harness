**Findings**

1. **`archive.py`, `extract()` — path traversal (Zip Slip) via untrusted `member`.** Blocking.
   - `Path(root) / member` performs no containment check. `member = "../../etc/cron.d/x"` resolves outside `root`, and an absolute member (`"/etc/cron.d/x"`, or `"C:\\..."` on Windows) makes `Path.__truediv__` *discard* `root` entirely, so the write lands wherever the attacker names. The stated invariant — "writes must stay below root" — is neither enforced nor documented here; the function silently trusts input at the trust boundary.
   - The `mkdir(parents=True)` call makes it worse: even if the final write were caught later, a traversing member creates directories outside `root` before any write happens. So validation must precede `mkdir`, not just `write_bytes`.
   - Require: anchor the root once (`root = Path(root).resolve()`), build the target, and reject before touching the filesystem if it does not stay under root. Given the stated "no symlinks" precondition a lexical check is sufficient, but resolving is cheap and also covers `..`:
     ```python
     root = Path(root).resolve()
     target = (root / member).resolve()
     if target == root or not target.is_relative_to(root):
         raise ValueError(f"archive member escapes destination: {member!r}")
     ```
     Additionally reject absolute member names explicitly (`Path(member).is_absolute()` / `PurePosixPath`/`PureWindowsPath` as appropriate) so the error names the actual problem rather than relying on `resolve()` incidentally catching it. Add a test for each of `../x`, `a/../../x`, `/abs`, and a drive-letter path.

2. **`archive.py`, `extract()` — degenerate member names produce wrong or unhelpful behavior.** Flag (folded into the same fix).
   - `member = ""` or `"."` yields `target == root`; `write_bytes` then fails with an opaque `IsADirectoryError` after `mkdir` has already run on `root.parent`. `member = "dir/"` (a directory entry) has its trailing slash stripped by `Path` and is written as a *file* named `dir`, which then blocks later members under `dir/`. Neither case is "fail early with an actionable error."
   - Require: reject empty/`.` members with a clear `ValueError` (the `target == root` check above covers it), and decide explicitly how directory entries are handled — either skip/`mkdir` them when `member.endswith("/")`, or reject them — rather than letting `Path` normalization silently change semantics.

No other issues: the reviewer preconditions (fresh private dir, no symlinks, no concurrent writers, per-member size already capped) take TOCTOU/symlink-swap and size-bomb concerns out of scope for this change, and I'm not raising them.
