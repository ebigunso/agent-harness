**Cause**

This is a workspace/cwd problem, not a PHP or project problem. The persistent shell's working directory was `C:/work/php-app/docs` (left there by the earlier `Set-Location ... docs`), so the relative path `bin/console` resolved to `C:/work/php-app/docs/bin/console`, which doesn't exist (the `docs` listing shows only `README.md`). PHP therefore reported `Could not open input file: bin/console` and exited 1. The tool UI's remembered root (`C:/work/php-app`) is separate from the shell's actual cwd, which is why the mismatch was easy to miss.

**Smallest safe remediation**

Return the shell to the intended base before running the command:

```powershell
Set-Location -LiteralPath 'C:/work/php-app'
php bin/console cache:clear
```

Nothing else needs to change — no code, dependencies, PATH, permissions, or config were involved. If you want to avoid depending on shell state at all, the equivalent one-shot form is `php C:/work/php-app/bin/console cache:clear`, but re-basing the cwd is the cleaner fix since other relative-path commands in this shell will have the same issue.

**Confirmation**

- `pwd` prints `C:/work/php-app`.
- `Test-Path -LiteralPath 'bin/console'` returns `True`.
- `php bin/console cache:clear` exits 0 with `[OK] Cache for the "dev" environment (debug=true) was successfully cleared.` on stdout and an empty stderr.

The captured comparison already shows exactly this: the unchanged command succeeded (status 0, `[OK]` message) once the cwd was `C:/work/php-app`, so the diagnosis is confirmed.
