**Verdict: not acceptable as-is — one blocking defect, a couple of flags.**

1. **`timeout.ts`, `schedule()` — unit mismatch (BLOCK).**
   `setTimeout(done, config.timeoutSeconds)` passes a seconds value where the DOM API expects milliseconds. A wire value of `30` fires after 30 ms, not 30 s; the max legal value `3600` fires after 3.6 s instead of an hour. Every timer scheduled through this function is ~1000× too short. Require `setTimeout(done, config.timeoutSeconds * 1000)`. (3600 s × 1000 = 3,600,000 ms, well under the 2³¹−1 ms `setTimeout` ceiling, so no clamping is needed once the conversion is correct.) Add a test that asserts the delay passed to `setTimeout` — this would have been caught immediately by a fake-timers test.

2. **`Timeout.java` — no enforcement of the stated wire contract / missing-field behaviour (flag, would require before merge).**
   The reviewer notes say the field is required and constrained to `0 ≤ timeoutSeconds ≤ 3600`. The record accepts any `int`, and with default Jackson settings a JSON body that omits `timeoutSeconds` deserializes to `0` rather than failing — a silently-immediate timeout. Require a compact constructor that rejects out-of-range values, and mark the field required (`@JsonProperty(required = true)` on the component, or confirm `FAIL_ON_MISSING_CREATOR_PROPERTIES` is enabled in the configured mapper). The same range check is absent on the TS side; at minimum `schedule` should reject negative/NaN/non-integer input rather than handing it to `setTimeout`, which coerces garbage to `0`.

3. **`timeout.ts` — `Timeout` type not exported (minor).**
   `schedule` is exported but its parameter type isn't, so callers can't declare a variable of that type or build adapters against it. Export the type. Also consider a more specific name (`ServerTimeout`) — `Timeout` is a common identifier and will collide with local names in consuming code.

4. **Scope vs. commit message (question).**
   The message says the timeout is "exposed in the browser adapter", but the diff only adds an unused type and a helper; nothing in an adapter consumes them. Either the adapter wiring is missing from this change or the message overstates it. Clarify which, and add a caller/test so the helper isn't dead code.
