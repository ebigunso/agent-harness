   Business rule (30‑day eligibility) is hardcoded inside the data-access class, duplicating `RefundPolicy.eligible`. This is policy in the data layer: the repository now decides eligibility instead of retrieving purchase facts, and the threshold exists in two places that will drift independently (change the policy to 45 days and the repository still says 30). Blocking. Require: the repository exposes facts only — e.g. `get(db, purchase_id)` returning the row (or raising `LookupError` if absent) — and the application layer computes `RefundPolicy.eligible(age_days)` after confirming the purchase exists. Delete the `<= 30` from the repository entirely; do not "fix" it by calling `RefundPolicy` from inside the repo, which still leaves the decision in the wrong layer.
