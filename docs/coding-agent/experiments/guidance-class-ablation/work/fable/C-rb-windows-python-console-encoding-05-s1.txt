**Verdict: not a workspace problem.** The script and the source CSV are fine; the failure is the output stream's encoding.

## Cause

`sys.stdout` is a pipe, so CPython 3.12 (UTF-8 mode off, `sys.flags.utf8_mode = 0`) falls back to the Windows locale codec, cp1252. `csv.writer(sys.stdout)` writes text through that codec, and `'日'` (U+65E5) has no cp1252 mapping — hence `charmap ... maps to <undefined>` at position 5 (right after `date,`). This is a Windows-specific stream-encoding limitation, not a bug in `csv_preview.py` or the data.

## Partial effects before rerunning

None to clean up:
- stdout is empty — the exception fired while encoding the very first row, before anything was flushed.
- The script only writes to stdout, never to the source CSV, so no file was touched.

Safe to rerun as-is.

## Smallest safe remediation

Override the stdio encoding for that one invocation only:

```powershell
$env:PYTHONIOENCODING='utf-8'; python csv_preview.py
```

(`-X utf8` also works — `python -X utf8 csv_preview.py` — but it's broader: it changes the filesystem encoding and `open()` default too. `PYTHONIOENCODING` touches only stdin/stdout/stderr, which is the actual problem.)

If you own the script and want it robust regardless of caller environment, add at the top of `csv_preview.py`:

```python
sys.stdout.reconfigure(encoding="utf-8")
```

Side note, not the cause of this failure: because the dialect emits CRLF and Windows text stdout also translates `\n`→`\r\n`, rows come out as `\r\r\n`. `sys.stdout.reconfigure(encoding="utf-8", newline="")` fixes both at once (the same reason `csv` docs say to open files with `newline=""`). Any file writes elsewhere should likewise use `open(..., encoding="utf-8", newline="")`.

## Confirmation

1. Rerun with the override; expect exit code 0 and `date,日` on stdout with no traceback.
2. Verify the stream setting actually took effect in the captured-pipe context:
   ```powershell
   $env:PYTHONIOENCODING='utf-8'; python -c "import sys; print(sys.stdout.encoding)" | Out-String
   ```
   Should print `utf-8` (previously `cp1252`).
3. Verify bytes, not just glyphs, since the consumer is a pipe: redirect to a file and check that `日` is `E6 97 A5`:
   ```powershell
   $env:PYTHONIOENCODING='utf-8'; python csv_preview.py > out.csv
   Format-Hex out.csv | Select-Object -First 3
   ```

Record for the ticket: error `UnicodeEncodeError: 'charmap' codec can't encode character '\u65e5'`, override command above, and the successful `date,日` output.
