**Findings**

1. **metrics.go — unrelated change bundled into the auth commit (blocking).**
   The import swap `metricsold` → `metricsnew` has nothing to do with rejecting inactive accounts. Per the notes, the metrics replacement has its own release ticket and the auth change must be independently revertible. As proposed, reverting "reject inactive authentication accounts" would also revert the metrics migration (and vice versa), and the two packages write to independent sinks, so this commit silently redirects `LoginCount()` data to a different backend under a commit message that never mentions it. Anyone bisecting a metrics gap would not look at a commit titled "reject inactive authentication accounts."
   **Require:** drop the `metrics.go` hunk from this commit entirely. Land it as a separate commit/PR under the metrics ticket with its own message and rollback plan.

2. **metricsold/counter.go, metricsnew/counter.go — stub packages should not be in this diff.**
   The reviewer notes say both packages are already installed, yet the diff adds new `counter.go` files defining `Counter() int { return 0 }` in each. Either these are duplicate definitions that will collide with the installed packages, or they are placeholder stubs that would replace real counters with a hard-coded zero. Neither belongs in an auth change.
   **Require:** remove these files from the commit. If the metrics migration genuinely needs new files, that belongs with the metrics ticket per finding 1.

3. **auth.go — no test accompanies the behavior change (minor, would flag not block).**
   `Allowed` goes from always-true to returning `active`. This is the entire point of the task and is a security-relevant gate; a two-case table test (`active=true` → allowed, `active=false` → rejected) would pin the behavior and catch a regression back to `return true`.
   **Require (recommended):** add the test alongside the change.

**Verdict:** The `auth.go` change itself is correct and minimal, and I would approve it on its own. The commit as proposed is **not acceptable** because it smuggles an unrelated, separately-ticketed metrics migration (plus stub packages) into an auth commit, breaking the independent-rollback requirement. Split the metrics work out and resubmit.
