## Cause

Not a workspace or service problem. The failure is loopback address resolution on the Docker Desktop for Windows host.

- `localhost` resolves to `::1` first; the failed channel dialed `[::1]:50051`.
- Docker Desktop's IPv6 port proxy accepted the TCP connect but never delivered HTTP/2 frames, so the gRPC channel sat at the transport layer until the 2 s deadline → `DEADLINE_EXCEEDED`. The service interceptor log confirms the request never reached the container.
- The REST sibling on `localhost:50080` works because it's HTTP/1.1, which the proxy handles fine — that's exactly the asymmetry the reference describes.
- The address-only comparison (`127.0.0.1:50051`, everything else identical) succeeds in-deadline with `pong` and `invoked=true completed=true`. That isolates the variable to the target address.

One side note on the exit code: the probe exited 2 (per its contract, and shown by `exit status 2` on stderr); `go run` then exited 1 because it always reports a non-zero child as exit 1. That's `go run` behaviour, not a second fault.

## Smallest safe remediation

Use the IPv4 loopback literal in the local connection string:

```powershell
go run ./cmd/probe --target 127.0.0.1:50051 --timeout 2s
```

and make `127.0.0.1` the default/configured target for gRPC clients hitting Docker Desktop published ports on this Windows host (config file, env var, or script — whichever the workspace uses). Don't touch the service, port mappings, or container; they're healthy. No need to disable IPv6 system-wide or edit the hosts file — that's a broader change than the problem warrants.

## Confirmation

1. Run the probe against `127.0.0.1:50051` with the same 2 s timeout: expect exit 0, stdout `pong`, empty stderr (already observed once; repeat a few times to rule out a one-off).
2. Check the service log shows the call: `invoked=true completed=true` for `unary Echo` over `h2c`.
3. Optionally re-run against `localhost:50051` once more to confirm it still hangs — that demonstrates the fix is the address, not timing or a transient.
4. If you want the true exit code rather than `go run`'s wrapper, `go build -o probe.exe ./cmd/probe` and run the binary directly; `$LASTEXITCODE` should be 0 on success.

If `127.0.0.1` ever also fails, only then move to service/port-publish/container-health investigation.
