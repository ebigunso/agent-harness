Core change (`app/lines.py`, `parse`): `text.replace("\r\n", "\n").split("\n")` is sound against the stated contract.
- Normalization happens once, in the shared parser, so both `cli` and `scheduled` get it for free — no per-caller compensation, no duplicated logic. This is the origin fix, not a symptom patch.
- `str.replace` is a single non-overlapping pass, so a standalone CR immediately before a CRLF is retained: `"a\r\r\nb"` → `"a\r\nb"` → `["a\r", "b"]`. Bare `\r` elsewhere is untouched. Trailing empty record is kept (`"a\n"` → `["a", ""]`, `""` → `[""]`). No trimming, no `splitlines` (which would have silently added `\r`, `\x0b`, `\x0c`, `\x1c`… and dropped the trailing empty record). Equivalent to `re.split(r"\r?\n", text)`; either is fine.
