**Cause — a script bug, not a workspace/environment problem.**

`ConvertFrom-Json -NoEnumerate` does return the one-element array intact, but the script then pipes that result through `| Write-Output`. Piping unrolls the array into the pipeline, and for a single-element array the sole item (`"north"`, a `System.String`) is what gets assigned to `$parsed`. So the `-NoEnumerate` protection is immediately undone on the same line, the type check sees a string, and the `throw` fires (exit 1). PowerShell, the runtime, the file, and execution policy are all fine — the evidence is that the script ran to line 10 and printed exactly what it computed.

**Smallest safe remediation — drop the redundant `| Write-Output` on line 5:**

```powershell
$parsed = $raw | ConvertFrom-Json -NoEnumerate
```

(`Write-Output -NoEnumerate` or `$parsed = ,(...)` would also work, but removing the no-op pipe is the minimal, clearest change and doesn't alter behavior for the empty and multi-element cases.)
