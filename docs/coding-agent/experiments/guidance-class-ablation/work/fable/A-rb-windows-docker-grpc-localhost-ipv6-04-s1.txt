**Cause**

This is a workspace/host-networking problem, not a probe or service bug.

`localhost` resolves to `::1` first, so grpc-java's channel connects to `[::1]:50051`. Docker Desktop's port proxy accepts the TCP connection on the IPv6 loopback, but nothing is delivered to the container's service (which is reachable via IPv4 — the `127.0.0.1` comparison succeeds in milliseconds and shows up in the interceptor log; the `localhost` call never appears there). Because the TCP connect *succeeds*, grpc-java does not fall over to the next resolved address (`127.0.0.1`); it just waits for HTTP/2 SETTINGS/response headers that never come, and the 2s deadline fires → `DEADLINE_EXCEEDED`, exit 2. The sibling `curl` on 50080 isn't a valid counter-example: curl does happy-eyeballs fallback to `127.0.0.1` on its own, which masks the same asymmetry.

Raising `--timeout` would not help — the `::1` path is a black hole, and the working call completes in ~12 ms.

**Smallest safe remediation**

Address the working endpoint explicitly rather than relying on `localhost` resolution:

```powershell
java -jar probes/grpc-probe.jar --target 127.0.0.1:50051 --timeout 2
```

That's a one-token change to the invocation, touches no code, no JVM flags, no Docker or service config, and is already demonstrated to work. If you later need `localhost` to work across the board, the broader fixes are `-Djava.net.preferIPv4Stack=true` on the JVM, or publishing the port so the IPv6 loopback either forwards correctly or isn't listened on (`-p 127.0.0.1:50051:50051`) — but those are wider changes than the task calls for.

**Confirmation**

1. Run the command above: expect exit code 0, stdout `pong`, empty stderr.
2. Check the service interceptor log for a new entry: `probe method="unary Echo" transport=h2c invoked=true completed=true`.
3. Optionally re-run with `--target localhost:50051` once more to confirm it still fails identically (exit 2, no interceptor entry) — that isolates the target address as the only variable and rules out a transient service issue.
