**Findings**

1. **`Order.java` — domain record now imports `jakarta.servlet.http.HttpServletRequest`.**
   The reviewer notes state `Order` is a transport-independent domain type reused by batch jobs. Adding a servlet import couples the domain to the web layer: batch jobs (and any other non-web consumer, tests, shared libs) now need the Servlet API on their classpath merely to load the `Order` class, and the domain can no longer be reasoned about independently of HTTP. This is a layering violation, not a style nit — it's exactly the dependency direction the "transport-independent" constraint exists to prevent.
   **Require:** keep `Order` free of servlet types. Do the extraction at the web boundary — e.g. a controller/adapter helper `OrderRequestMapper.from(HttpServletRequest)` (or a `@ModelAttribute`/`HandlerMethodArgumentResolver` in Spring) that reads the `"tenant"` attribute and calls `new Order(tenant)`. `Order` itself stays `public record Order(String tenant) {}` (optionally with a null/blank guard in a compact constructor).

2. **`Order.from(...)` — unchecked cast and no null handling of `request.getAttribute("tenant")`.**
   The notes say middleware guarantees a validated String, but that guarantee holds only on routes where the auth filter actually runs. If `from` is ever called on an unauthenticated/misconfigured path, `getAttribute` returns `null` and you silently construct an `Order` with a null tenant — a tenant-scoping bug that can leak or misroute data rather than fail fast. A wrong-type attribute produces a bare `ClassCastException` with no context.
   **Require:** at the boundary, fail explicitly: `Object t = request.getAttribute("tenant"); if (!(t instanceof String s) || s.isBlank()) throw new IllegalStateException("authenticated tenant missing");` (or return 401/403 via the framework's exception mapping). Given the security significance of tenant selection, this should not rely on an implicit assumption.

3. **Magic string `"tenant"` duplicated between middleware and consumer.**
   The attribute key is now defined in (at least) two places with no shared constant; a rename on either side breaks tenant selection silently (returns `null`, see #2).
   **Require:** reference a single shared constant owned by the auth middleware (e.g. `TenantAuthFilter.TENANT_ATTRIBUTE`).

**Verdict:** Not acceptable as-is. Finding #1 is blocking — the change contradicts the stated architectural constraint that `Order` is transport-independent. Move the servlet-to-domain mapping into the web layer, and add explicit failure on a missing/invalid tenant attribute there.
