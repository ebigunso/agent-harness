**Verdict: block.** The change inverts the dependency direction and removes the seam it was supposed to use.

## Findings

### 1. `domain/price.go` — domain now imports the vendor SDK
**What:** `import "example.test/app/vendorcloud"` and `(vendorcloud.Client{}).Quote()` inside `Price()`.
**Why it matters:** `vendorcloud` is the volatile external quote API facade; `domain` is the stable core. Pointing the core at the vendor package means any change to the vendor client (auth, transport, error shape, rate limits, replacement provider) now ripples into pricing logic, and `domain` can no longer be compiled or tested without the vendor package. This is exactly the outer→inner rule being reversed.
**Require:** Remove the import. `domain` must not reference `vendorcloud` at all. The vendor client should be consumed from an outer package (composition root / adapter) and passed in through the port.

### 2. `domain/price.go` — the existing `Quote` port is bypassed and orphaned
**What:** `Price(q Quote)` became `Price()`. The `Quote` interface is still declared but no longer used by anything.
**Why it matters:** The interface was the stable injection seam; the diff hard-wires a concrete `vendorcloud.Client{}` construction in place of it. Callers can no longer substitute a fake, a cached source, or a different vendor, and the interface is now dead code that misleads readers into thinking a seam exists.
**Require:** Keep `func Price(q Quote) int { return q.Quote() + 10 }`. If the task genuinely needs a "fetch" entry point, add it outside `domain` (e.g. an app/adapter layer that does `domain.Price(vendorcloud.Client{})`), or add a thin adapter type in an outer package that satisfies `domain.Quote`. `vendorcloud.Client` already satisfies the interface structurally, so no changes to `domain` are needed.

### 3. `domain/price.go` — public API break with no migration
**What:** `Price(q Quote)` → `Price()` changes the exported signature.
**Why it matters:** Any existing caller passing a `Quote` breaks at compile time; any test injecting a stub breaks. The commit message ("fetch a quote for domain pricing") gives no indication a breaking signature change was intended.
**Require:** Preserve the signature (follows from #2). If a signature change were truly warranted, it needs to be called out in the commit message and callers updated in the same change.

### 4. `vendorcloud/client.go` — new package has no edge documentation
**What:** The package introduces a boundary to a volatile external API with zero doc comments (`package vendorcloud`, `Client`, `Quote` all undocumented).
**Why it matters:** This is the one place in the module where an external system is modelled; readers need to know it's the vendor seam, that it's volatile, and that it should only be consumed via the `domain.Quote` port from outer layers. Without that, the mistake in #1 will be repeated.
**Require:** Package-level doc stating this is the external quote-API facade and the expected wiring (`vendorcloud.Client` → `domain.Quote` → `domain.Price` from the composition root), plus doc comments on `Client` and `Quote`. Minor on its own; I'd flag but not block solely on this.

## What I'd accept instead

```go
// domain/price.go — unchanged from before the diff
package domain

type Quote interface{ Quote() int }

func Price(q Quote) int { return q.Quote() + 10 }
```

```go
// vendorcloud/client.go
// Package vendorcloud is the facade over the external quote API.
// It is volatile and must only be consumed by outer layers via domain.Quote.
package vendorcloud

type Client struct{}

func (Client) Quote() int { return 100 }
```

and, wherever the fetch is actually triggered (an `app`/`cmd` package, not shown): `domain.Price(vendorcloud.Client{})`. That satisfies "fetch a quote for domain pricing" with the dependency arrow pointing vendor→domain instead of domain→vendor, and keeps the existing port intact.
