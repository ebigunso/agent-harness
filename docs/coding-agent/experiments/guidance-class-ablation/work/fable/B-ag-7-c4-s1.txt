What I checked, against the gate:

- **Outcome signal is unsampled; debug is sampled.** The sampling counter only gates `debug`, never `outcome`. If a sink ever violated that contract and threw, the poll would be double-counted (success then failure). If that contract is ever relaxed, move the success signal out of the `try` (capture `value`, then signal, then return). As written, with nonthrowing sinks, it's fine.
