**Cause**

This is an environment/encoding mismatch, not a defect in the workspace files. On Windows, when Python's stdout is a pipe rather than an interactive console, `sys.stdout` is opened with the locale ANSI code page — here `cp932` (Japanese), as confirmed by `sys.stdout.encoding = cp932` and `utf8_mode = 0`. The summary string contains U+2014 (EM DASH). Python's `cp932` codec has no mapping for U+2014 (the 0x815C byte pair maps to U+2015, HORIZONTAL BAR, not U+2014), so the write fails with `UnicodeEncodeError` at `print(summary)` on line 18. The computation itself succeeded; only the output step failed, and nothing was written to disk.

**Smallest safe remediation**

Make the process's stdio UTF-8 for this invocation only, with no code change and no persistent environment change:

```powershell
python -X utf8 report.py
```

(equivalently `$env:PYTHONUTF8 = '1'` for the session, or the narrower `$env:PYTHONIOENCODING = 'utf-8'`, which affects only stdin/stdout/stderr). `-X utf8` is process-scoped and reversible; since the script writes no files, its effect on default file encoding is irrelevant here.

Whatever consumes the pipe must decode it as UTF-8. If the consumer is PowerShell itself, ensure `[Console]::OutputEncoding` / `$OutputEncoding` are UTF-8 so the em dash isn't mojibake'd on the receiving side.

If you want the script robust regardless of caller environment, the minimal code fix is a `sys.stdout.reconfigure(encoding="utf-8")` near the top of `report.py` — but that's a code change and goes beyond the smallest remediation for this failure.

**Confirmation**

1. Sanity-check the encoding in the same piped context:
   `python -X utf8 -c "import sys; print(sys.stdout.encoding)" | Out-String` → should print `utf-8`.
2. Rerun `python -X utf8 report.py` under the same pipe capture: exit code `0`, no traceback on stderr, stdout contains `Summary — complete` (bytes `E2 80 94` for the dash if you inspect raw output, e.g. `python -X utf8 report.py | Format-Hex`).
3. Rerun without the flag to verify the failure reproduces, confirming the encoding setting was the variable that changed.
