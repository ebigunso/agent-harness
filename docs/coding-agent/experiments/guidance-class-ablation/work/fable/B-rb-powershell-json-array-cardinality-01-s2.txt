**Cause — script logic, not the workspace.** The environment, raw JSON, and runtime are fine. `$raw | ConvertFrom-Json` returns the one-element array through the pipeline, which unrolls it, so `$parsed` is the bare element (`System.Int64` 7, exactly as the stdout shows). The `-isnot [array]` check then fails even though the wire value `[7]` is a properly framed array. The probe is a false negative; it would also misfire on `[]` (unrolls to nothing → `<null>` → throws), so it currently violates the contract's "accept empty and singleton arrays" clause.

**Smallest safe remediation.** On PowerShell 7.4.6, add `-NoEnumerate` on line 5 and don't re-pipe the result:

```powershell
$parsed = $raw | ConvertFrom-Json -NoEnumerate
```

That's the only change. With `-NoEnumerate`, `[7]` and `[]` come back as `System.Object[]`, while a scalar wire value like `7` still parses to `Int64` and is correctly rejected by line 10.

If this probe must also run under Windows PowerShell 5.1 (no `-NoEnumerate`), assert framing on the raw string instead:

$t = $raw.Trim()
if (-not ($t.StartsWith('[') -and $t.EndsWith(']'))) { throw 'Expected JSON array' }
