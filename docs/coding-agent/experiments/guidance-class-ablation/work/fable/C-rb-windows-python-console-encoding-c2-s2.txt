## Diagnosis

**This is not the encoding scenario in the reference material.** The traceback is a `PermissionError: [Errno 13]`, not a `UnicodeEncodeError`. The `open(...)` call already requested `encoding='utf-8'` and stdout is UTF-8 (`sys.stdout.encoding = utf-8`), so `PYTHONIOENCODING` / `reconfigure()` remedies are irrelevant here — applying them would change nothing and would mask the real issue.

**Cause:** The process cannot open `report.txt` for writing because the file's ACL denies write access to the current user. The failure occurred at the `open()` call, *before* any write or truncation, so:
- There are **no partial effects** to clean up (the existing `report.txt` is untouched).
- The parent directory and input data are fine; this is purely a write-permission problem on the target file.

## Smallest safe remediation

Grant the current user write (modify) permission on the specific file. From PowerShell in `C:/work/py-report`:

```powershell
icacls report.txt /grant "$($env:USERNAME):(M)"
```

Notes on scope/safety:
- This edits only `report.txt`, not the directory or other files.
- If the ACL contains an explicit **Deny** entry (deny overrides allow), the grant alone won't help — remove the deny with `icacls report.txt /remove:d "$env:USERNAME"` first, then re-grant.
- Do **not** delete/recreate the file or run elevated as a first move; those are larger-blast-radius actions than a targeted ACL fix, and deletion could discard content you may want.

## Confirmation

1. Check the effective ACL now shows write/modify for the user:
   ```powershell
   icacls report.txt
   ```
   Expect an entry like `USER:(M)` (or `(W)`), and no `(DENY)` line for that user.
2. Rerun the original command through the same captured pipe:
   ```powershell
   python export_report.py
   ```
   Expect **exit code 0** and `report.txt` populated with the expected report content (verify size/contents, e.g. `Get-Item report.txt` / `Get-Content report.txt`).

If the command still fails with `[Errno 13]` after the grant, suspect an inherited/explicit Deny ACE or an external hold not captured here (e.g., a scanner/backup lock, or the file being owned by another principal), and re-inspect with `icacls` / `Get-Acl` before escalating.
