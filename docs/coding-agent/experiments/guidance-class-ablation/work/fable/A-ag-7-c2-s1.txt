**Verdict: not mergeable as-is — mostly hygiene, one semantic question. Logic is correct and label cardinality is bounded.**

1. **metrics.go, whole file — not gofmt'd.** Everything is jammed onto lines with `;` separators (`import ("context"; "errors"; "time")`, three statements per line). It compiles, but any `gofmt -l` / `go vet` gate in CI will reject it, and it's unreviewable diff-wise going forward. Require: run `gofmt -w` (and `goimports`) before merge.

2. **metrics.go — no tests for a new package.** Zero coverage for the three branches (success / deadline / other), for the wrapped-error case (`fmt.Errorf("...: %w", context.DeadlineExceeded)` → `"deadline"`), for error propagation, and for "observe is called exactly once with a non-negative duration". These are five-minute table tests. Require them; the whole point of this helper is the classification, and it's untested.

3. **metrics.go:4-6 — `observe` is skipped if `run` panics.** `run()` is called inline; a panic bypasses `observe`, so the slowest/worst downstream calls are exactly the ones that never get recorded. If the intent is "every call to `Call` produces one observation," wrap it: `defer func(){ observe(category, time.Since(start)) }()` with `category` decided in a recover-aware path, or explicitly document that panics are not observed. I'd want either the defer or a comment stating it's deliberate.

4. **metrics.go:5 — "deadline" only matches `context.DeadlineExceeded`.** Net-level I/O timeouts surface as `os.ErrDeadlineExceeded` (e.g. `net.Conn` deadlines, some `net/http` transport paths), not `context.DeadlineExceeded`, so those land in `"other"`. If "downstream" means network calls, the deadline bucket will undercount. Require: either `errors.Is(err, context.DeadlineExceeded) || errors.Is(err, os.ErrDeadlineExceeded)` (same fixed category, so cardinality is unchanged) or a comment that only context deadlines are meant to be counted.
