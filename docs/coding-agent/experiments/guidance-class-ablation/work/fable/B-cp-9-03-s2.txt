**Finding 1 — `src/PaymentClient.java`, `catch (GatewayTimeout timeout)` block**

*What's wrong:* On a gateway timeout the code calls `store.markPaid(order.id())` and returns `ChargeStatus.PAID`. A timeout means the outcome of the remote capture is *unknown* — the reviewer notes confirm it can occur before or after the gateway actually captured funds. The catch block collapses that ambiguity into a definite "paid" and persists it. The commit message ("complete checkout on gateway timeout") makes the intent explicit, and the intent is wrong.

*Why it matters:* This is precisely the misreporting the task asked to prevent. If the timeout happened before capture, the order is marked paid and checkout completes with no money taken — goods ship / services provision against a non-existent payment, and nothing in the system will ever notice because the stored state says PAID. It also swallows the failure entirely: the timeout is not logged, not surfaced, and not distinguishable from a genuine success, so there is no signal for ops or reconciliation to act on. The fallback is neither safe, observable, nor bounded.

*What I'd require instead:* Treat the timeout as an indeterminate state. Given the notes (stable `paymentKey`, gateway idempotency works, pending + reconciliation supported), the acceptable shapes are:

- Record the order as pending (`store.markPending(order.id())` or equivalent), return `ChargeStatus.PENDING`, log the timeout with order id / payment key, and let the reconciliation job query the gateway by `paymentKey` to resolve it to PAID or FAILED; **or**
- Since idempotency is in place, do a bounded retry of `gateway.charge(...)` with the same `paymentKey` (which will return the existing result if the first attempt actually captured), and only fall through to pending/reconciliation if retries are exhausted.

In either case, `markPaid`/`PAID` must only be reached after the gateway has affirmatively confirmed capture. Also remove the duplicated `markPaid`/`return PAID` in the catch — it's a symptom of the same mistake, and once the timeout path returns PENDING the duplication disappears naturally.
