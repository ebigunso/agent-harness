**Findings — I would block this change.**

1. **`Reset.scala`, line 5 — raw reset token written to the log.**
   `log(s"query failed sql=$sql token=$resetToken")` emits the secret bearer value verbatim. Reset tokens are single-use credentials that grant account takeover; logs are typically retained longer than the token's validity, replicated to aggregators, and readable by people who have no business seeing user credentials. This is exactly the Gate 7 anti-pattern "logging sensitive payloads as a convenience," and it turns a diagnostic aid into a credential leak on every failure. The task ("log failed reset-token queries") does not require the token's value to be logged — it requires the *failure* to be logged.
   **Require:** never log the token. Either omit it entirely, or log a non-reversible correlator (e.g. a truncated SHA-256 of the token, or a request/attempt ID passed in by the caller) so operators can correlate the failure to a specific attempt without possessing the secret. Something like:
   ```scala
   catch { case error: SQLException =>
     log(s"reset-token query failed sql=$sql tokenRef=${fingerprint(resetToken)} sqlState=${error.getSQLState} code=${error.getErrorCode} msg=${error.getMessage}")
     throw error
   }
   ```

2. **`Reset.scala`, line 5 — the exception's diagnostic content is dropped from the log line.**
   The log records that something failed but not *what*: no `SQLState`, vendor error code, or message. The exception is rethrown, so the information isn't lost to the caller, but the log entry — the artifact this change exists to produce — is not independently actionable ("query failed" tells an on-call engineer nothing about timeout vs. constraint violation vs. connection loss). Including `getSQLState`/`getErrorCode`/`getMessage` (as shown above) makes the entry useful. Note the SQL statement (`$sql`) is fine to log since, per the reviewer notes, it contains only placeholders; the driver message should be checked to confirm it does not echo bound parameter values for this driver.

3. **Minor / non-blocking — `Reset.scala`, line 5 style.**
   The `try`/`catch` and the two statements in the handler are crammed onto single lines. Not a defect, but split it across lines for readability once the handler carries more fields.

Finding 1 alone is a blocker; the current diff makes the system's security posture worse than having no logging at all.
