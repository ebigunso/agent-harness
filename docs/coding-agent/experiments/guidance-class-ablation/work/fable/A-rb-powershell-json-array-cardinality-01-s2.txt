## Cause

This is a workspace (script) problem — a bug in the probe, not a runtime or environment fault.

`ConvertFrom-Json` **enumerates its output into the pipeline**. When the JSON is a single-element array like `[7]`, the one element is emitted as a scalar and assigned to `$parsed`, so `$parsed` becomes an `Int64` (value `7`) rather than an array. The stdout confirms this: `parsed type=System.Int64`. The `-isnot [array]` guard therefore correctly fires and throws.

The JSON is valid; the checker just unwrapped the collection. Note the contract says empty and multi-element arrays must pass — those would happen to work (`[]` → array/`$null`-ish, `[1,2]` → `Object[]`), but the singleton case breaks, which is exactly the edge this probe hit.

## Smallest safe remediation

Preserve the array by telling `ConvertFrom-Json` not to enumerate. Change line 5:

```powershell
$parsed = ConvertFrom-Json -InputObject $raw -NoEnumerate
```

(`-NoEnumerate` exists in PowerShell 7.4, so this is safe on your runtime.) This is the minimal change; the assertion logic itself is fine.
