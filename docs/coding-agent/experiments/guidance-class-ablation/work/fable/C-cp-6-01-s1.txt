**Verdict: block.** The core defect is a unit mismatch that makes every timeout fire ~1000× too early; the rest are contract-enforcement gaps.

1. **`timeout.ts`, `schedule()` — seconds passed to a millisecond API.**
   `setTimeout(done, config.timeoutSeconds)` treats the wire value as milliseconds. A server value of `30` fires after 30 ms, not 30 s. This is a silent semantic coercion across the Java→JSON→TS boundary — the field name says seconds, the record says seconds, the DOM timer consumes milliseconds. Require `setTimeout(done, config.timeoutSeconds * 1000)` (or convert at the adapter boundary into a local `timeoutMs` and keep the wire field name intact). Add a test that asserts the delay passed to `setTimeout` for a known input.

2. **`timeout.ts` — no validation of the wire contract on the consuming side.**
   The type is `{timeoutSeconds: number}`, which admits `NaN`, negatives, fractions, and values > 3600, none of which are legal per the stated contract (nonnegative integer ≤ 3600). `setTimeout` will happily accept `NaN` (fires immediately) or a huge value (clamped/overflowed by the browser). Since this is data coming off the wire, require a parse/guard at the adapter boundary (`Number.isInteger`, `0 <= v <= 3600`) that rejects or fails loudly, rather than trusting a structural TS type that provides no runtime guarantee.

3. **`Timeout.java` — record does not enforce the invariant it defines.**
   `record Timeout(int timeoutSeconds)` accepts any `int`, so the producing side can serialize `-1` or `999999` and the invariant lives nowhere. Require a compact constructor that throws on out-of-range values so the wire contract has a single authoritative enforcement point on the server.

4. **`timeout.ts` — `Timeout` type is not exported.**
   The task is to *expose* the timeout in the adapter, but only `schedule` is exported; callers cannot name the config type they're required to pass. Export it (and, if this is the wire shape, keep it in sync with the Java record — note the field name `timeoutSeconds` must match Jackson's output exactly; it does today, but there's nothing pinning that, so a serialization test on the JSON shape is warranted).

5. **Ambiguity: `timeoutSeconds = 0`.** The contract allows `0`. With the fix in (1), `setTimeout(done, 0)` fires on the next tick. If `0` is meant to mean "no timeout / disabled," that needs explicit handling; if it genuinely means "immediate," document it. Not blocking on its own, but clarify before merge since the two readings have opposite behavior.
