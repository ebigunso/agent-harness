**1. `src/Item.tsx` — `Detail` debounce does not address the root cause (out-of-order responses).**
The stale-item bug originates in `selectItem`: `setSelectedId(B)` can be followed by `setItem(A)` when A's fetch resolves last, and `state.setItem` has no generation check. A 200 ms timer in `Detail` just re-reads `state.item` later; if A's response is the last write, `visible` becomes A after 200 ms. The symptom is only hidden when both responses happen to land inside the same 200 ms window. Require: discard stale results at the source, once, e.g.

```ts
export async function selectItem(id: string) {
  selection.setSelectedId(id);
  const item = await api.fetchItem(id);
  if (selection.getSelectedId() !== id) return; // or check item.id
  selection.setItem(item);
}
```
(or enforce the invariant in `state.setItem`: ignore items whose `id !== selectedId`). Either way it's one guard where the race originates, and both subscribers get the fix for free.
