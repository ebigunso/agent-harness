**Cause**

This is a workspace problem, not an npm/registry/lockfile problem. `npm ci` must delete `node_modules` before reinstalling, and the unlink of `@parcel\watcher\build\Release\watcher.node` fails with EPERM (errno -4048) because a running process has that native addon mapped. `tasklist /m watcher.node` identifies it: `node.exe` PID 4104, a Parcel/Vue watch script launched from `C:/work/npm-lock/scripts/watch.js` — i.e. this repo's own detached watcher. Permissions, ACLs, package/lock sync, cache, and registry were all verified fine, so nothing else needs fixing.

**Smallest safe remediation**

1. Stop the watcher. Since it has detached from its original shell, there's no terminal to Ctrl‑C, so terminate the identified PID (it is confirmed as this repo's own watch task, not an unrelated process):

   ```
   taskkill /PID 4104 /F
   ```

2. Re-run the install:

   ```
   npm ci
   ```

Do not delete `node_modules` manually, disable antivirus, or change file permissions — none of those address the cause, and the first would fail on the same locked file anyway.
