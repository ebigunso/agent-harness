**Verdict: not a workspace/server problem — the probe's assertion is wrong.**

**Record**
- Raw JSON: `[{"state":"ok"}]` (matches the independent capture; HTTP 200, `application/json`)
- Element count: 1
- Parse: `$parsed = $raw | ConvertFrom-Json`
- Assertion: `if ($parsed -isnot [array]) { throw 'Expected JSON array' }`

**Cause**
`ConvertFrom-Json` produces a 1-element array, but because it is used in a pipeline, PowerShell enumerates that array when assigning to `$parsed`. A single-element array unrolls to its one element, so `$parsed` is the `PSCustomObject`, not an array. `-isnot [array]` is therefore true and the script throws. The server honored the contract; the check produced a false negative. (Note the same check would also mis-fire on a legitimate empty array `[]`, which unrolls to `$null`.) Post-pipeline `-is [array]` cannot prove wire framing.

**Smallest safe remediation**
Assert on the raw wire text, not the unrolled object. Replace line 10 with:

```powershell
$t = $raw.Trim()
if (-not ($t.StartsWith('[') -and $t.EndsWith(']'))) { throw 'Expected JSON array' }
```

This is a framing check, not a syntax validator (JSON validity is already established by the parse on line 5). It works on both pwsh 7.x and Windows PowerShell 5.1.

Optional (pwsh 7.4 only, for the type print to be meaningful): `$parsed = ConvertFrom-Json -InputObject $raw -NoEnumerate` — keep it out of a downstream pipeline, or it unrolls again. Not required for the fix.

**Confirmation**
1. Re-run `pwsh -NoProfile -File probes/cardinality.ps1` against the same producer: expect exit 0, stdout still shows `raw=[{"state":"ok"}]` and `wire elements=1`, no throw.
2. Contract sweep by swapping the producer body: `[]` → pass, `[{"state":"ok"},{"state":"ok"}]` → pass, `{"state":"ok"}` and `"ok"` → `Expected JSON array`, exit 1.
3. `$LASTEXITCODE` is 0 for the array cases and 1 for the scalar cases.
