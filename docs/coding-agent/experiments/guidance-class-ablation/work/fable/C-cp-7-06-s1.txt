## Findings

### 1. Evidence does not cover the risk surface (blocking)
**Location:** submission evidence — `cargo fmt --check` only.

The task is a change to a *persisted* format. The two things that can actually go wrong are (a) existing on-disk JSON with only `id` failing to deserialize, and (b) the new field not surviving a write→read round-trip. `cargo fmt --check` verifies neither; it doesn't even prove the crate compiles.

The change *looks* correct (`#[serde(default)]` on `Option<String>` yields `None` when the key is absent, and serde derive already treats missing `Option` fields as `None`, so the attribute is belt-and-braces), but "looks correct" is not evidence for a compatibility contract.

**Require:** a compile (`cargo build`/`cargo test`) plus two deterministic tests through the serde seam, added in this diff, not run ad hoc:
- `serde_json::from_str::<Record>(r#"{"id":"abc"}"#)` → `label == None` (old-data read).
- `Record { id, label: Some("x") }` → `to_string` → `from_str` → equal (new-data round-trip).

These need no fixtures, no filesystem, no globals — `serde_json::from_str`/`to_string` is the seam.

### 2. Serialized shape of `None` is an unstated format decision (flag, non-blocking)
**Location:** `record.rs`, `label` field attributes.

With only `#[serde(default)]`, a record with `label: None` now serializes as `"label": null`, so every re-saved record changes shape. That's fine for readers that ignore unknown/null fields, but it should be a conscious choice. If the intent is "absent means none" (keeps old and new files byte-identical for unlabeled records, and avoids surprising any consumer that distinguishes missing vs. null), add `#[serde(skip_serializing_if = "Option::is_none")]`.

**Require:** either confirm `null` is the intended wire form or add `skip_serializing_if`; whichever is chosen, the round-trip test in #1 should assert the exact serialized string for the `None` case so the decision is pinned.

The code diff itself is correct as far as it goes; the blocker is that nothing submitted demonstrates the compatibility property the commit message claims.
