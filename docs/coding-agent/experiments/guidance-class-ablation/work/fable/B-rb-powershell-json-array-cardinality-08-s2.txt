**Cause**

Not an environment/runtime problem — it's a logic bug in the probe itself. Line 5 does the right thing (`ConvertFrom-Json -NoEnumerate` keeps `[{"id":9}]` as a one-element `object[]`) and then immediately undoes it by re-piping through `ForEach-Object { $_ }`. That second pipeline stage enumerates the array, so the single `PSCustomObject` is emitted and `$parsed` ends up as the bare element. The `-isnot [array]` check at line 10 then correctly reports a scalar and throws. The stdout (`parsed type=System.Management.Automation.PSCustomObject`) confirms exactly this: the wire framing was an array, the pipeline unrolled it.

**Smallest safe remediation**

Delete the re-pipe on line 5 and assign the `-NoEnumerate` result directly:

```powershell
$parsed = $raw | ConvertFrom-Json -NoEnumerate
```

(or equivalently `ConvertFrom-Json -InputObject $raw -NoEnumerate`). Nothing else needs to change; `-NoEnumerate` is available on the installed PowerShell 7.4.6. This also satisfies the stated contract: `[]` → empty `object[]` (passes), singleton/multi → `object[]` (passes), scalar wire value such as `9` or `{"id":9}` → not an array (throws).

If this probe must ever run under Windows PowerShell 5.1, `-NoEnumerate` won't exist; in that case replace the type check with a raw-framing assertion (`$raw.Trim()` starts with `[` and ends with `]`). That is not needed for the described environment.

2. Spot-check the contract edges by temporarily substituting `$raw`:
