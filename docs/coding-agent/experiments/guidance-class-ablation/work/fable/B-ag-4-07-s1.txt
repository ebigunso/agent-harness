**Findings**

1. **`lib.rs`, `after_prefix` — unit mismatch at the `at_scalar` boundary (blocking).**
   `at_scalar` is documented/used downstream as taking a *Unicode scalar* index, but `after_prefix` passes `prefix.len()`, which is the UTF-8 *byte* length. These only coincide for ASCII, which is why the examples passed. For any non-ASCII prefix the index is too large:
   - `after_prefix("éa", "é")` → `prefix.len() == 2` → `at_scalar("éa", 2)` → `None`, expected `Some('a')`.
   - `after_prefix("日本語", "日本")` → `len == 6` → `None`, expected `Some('語')`.
   This is exactly the silent contract violation Gate 4 warns about: no panic, no error, just a wrong `None` that is indistinguishable from "no character after prefix". Require the index be expressed in the callee's unit, e.g. `at_scalar(text, prefix.chars().count())`, or bypass the index entirely (see 2). Add tests with a multibyte prefix (and one where the prefix ends at the last char, and one where prefix is empty).

2. **`lib.rs`, `after_prefix` — the "prefix is a validated prefix of `text`" precondition is implicit and unchecked (flag).**
   Nothing in the signature or body enforces that `prefix` actually prefixes `text`; the function silently returns whatever char sits at that scalar offset, so a caller that violates the precondition gets a plausible-looking `Some(..)` rather than a failure. The contract lives only in call-site assumptions. Prefer making it explicit and self-enforcing:
   ```rust
   pub fn after_prefix(text: &str, prefix: &str) -> Option<char> {
       text.strip_prefix(prefix)?.chars().next()
   }
   ```
   This fixes finding 1 as well (no index arithmetic at all, so no unit to get wrong), is O(prefix) instead of O(text), and returns `None` for "not a prefix" instead of a bogus character. If "not a prefix" must be distinguishable from "prefix consumes whole text", return a `Result`/enum instead of `Option` — but at minimum the precondition should be documented on the function if it stays unchecked.

Change is not acceptable as-is due to finding 1.
