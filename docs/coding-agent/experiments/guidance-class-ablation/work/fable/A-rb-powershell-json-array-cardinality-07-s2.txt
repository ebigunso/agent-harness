**Cause — a script bug, not a workspace/environment problem.**

`ConvertFrom-Json -NoEnumerate` does return the one-element array intact, but the script then pipes that result through `| Write-Output`. Piping sends the array *through the pipeline*, which unrolls it; `Write-Output` receives and emits the single element `"north"`. So `$parsed` ends up as `System.String`, exactly as the stdout shows, and the `-isnot [array]` check throws. Nothing in Windows/PowerShell 7.4.6/the profile/cwd is at fault; the JSON is valid and the parser behaved correctly.

**Smallest safe remediation** — remove the redundant pipe in `probes/cardinality.ps1` line 5:

```powershell
$parsed = $raw | ConvertFrom-Json -NoEnumerate
```

(Equivalent alternative if the pipe must stay: `| Write-Output -NoEnumerate`.) No other lines need to change; `-NoEnumerate` on `ConvertFrom-Json` already handles the empty/singleton/multi-element cases the contract requires.
