**Cause:** Not a workspace problem — the probe script's own logic is wrong. Line 5 wraps the parse in the array subexpression operator: `$parsed = @($raw | ConvertFrom-Json)`. `@(...)` unconditionally coerces its contents into `System.Object[]`, so `$parsed -is [array]` is `$true` for every input, including the scalar `7`. The assertion on line 10 therefore fires and `throw` exits 1. The `parsed type=System.Object[]` line in stdout confirms the wrapping, not the parser's output (`'7' | ConvertFrom-Json` on PS 7.4 yields `System.Int64`). The JSON, the runtime, execution policy and the cwd are all fine.

**Smallest safe remediation:** Remove the `@()` wrapper and let `ConvertFrom-Json` report shape itself. Because the pipeline would otherwise enumerate a JSON array into its elements (breaking the positive cases the contract also wants: `[]`, `[x]`, `[x,y]`), add `-NoEnumerate` so arrays come back as `Object[]` and scalars come back as scalars:

```powershell
$parsed = $raw | ConvertFrom-Json -NoEnumerate
```
