## Diagnosis

**This is not a workspace problem.** The command behaved exactly as designed; exit 3 with `UNIMPLEMENTED: unknown method Absent` is the correct, expected outcome for the input given.

### Cause
The RPC method name is wrong. The deployed descriptor exposes **`Ping`**, not `Absent`. Every piece of evidence points to a clean transport reaching a healthy server that then rejected an unknown method:

- Transport succeeded (h2c on 50051), and the server access logs recorded the `Absent` call — so the request was delivered and answered, not dropped.
- Both `127.0.0.1:50051` and `localhost:50051` return the identical, prompt `UNIMPLEMENTED` — no address asymmetry, no resolution/timing issue.
- The 2s default deadline was never in play (no `DEADLINE_EXCEEDED`, response was prompt).
- The HTTP sibling on 50080 returns 200 — infrastructure is up.
- The probe maps `UNIMPLEMENTED` to exit 3, which is what you got.

So the failure is a user/input error (calling a method the service doesn't implement), not a build, network, TLS, port, or environment fault.

### Smallest safe remediation
Call the method that actually exists:

```powershell
dotnet run --project probes/GrpcProbe -- --target 127.0.0.1:50051 --method Ping
```

No config, code, container, or environment change is warranted.

### How to confirm it worked
Expect:
- **Exit code 0**
- **stdout** containing the `Ping` response values (the probe only prints on a successful call)
- **empty stderr** (no `UNIMPLEMENTED`)

If you want to independently confirm the method set rather than guessing, list the service's advertised methods via reflection (e.g., `grpcurl -plaintext 127.0.0.1:50051 list <service>`) and verify `Ping` is present and `Absent` is not — this explains the original result without relying on the probe.
