**Cause:** Stale working directory in the persistent shell, not a workspace/code problem. An earlier command in the same shell had already run `Set-Location 'C:/work/shop/web'`, so the shell's cwd was `C:/work/shop/web` while the tool UI still displayed the remembered root `C:/work/shop`. The failing command `cd web && npm run build` was written relative to the root, so `cd web` resolved to `C:\work\shop\web\web`, which does not exist. `Set-Location` failed (status 1) and, because of `&&`, `npm run build` never launched. Nothing about the code, dependencies, PATH, config, or permissions was at fault; the build target (`package.json`, `src/index.ts`) exists and is readable.

**Smallest safe remediation:** Normalize the cwd once with an explicit absolute path to the intended base, then rerun the original command unchanged:

```powershell
Set-Location -LiteralPath 'C:/work/shop'
cd web && npm run build
```

Do not stack further relative `cd` calls, and do not edit the command or the workspace. (Equivalently, `Set-Location -LiteralPath 'C:/work/shop/web'; npm run build` would work, but resetting to the base and rerunning the command verbatim keeps the diagnosis clean.)

**Confirmation (as recorded):**
- Before: `pwd` → `C:/work/shop/web`; `cd web && npm run build` → status 1, `Set-Location: Cannot find path 'C:\work\shop\web\web'`.
- Normalize: `Set-Location -LiteralPath 'C:/work/shop'` → status 0; `pwd` → `C:/work/shop`.
- Retry (unchanged command): status 0; stdout `> web@1.0.0 build` / `> tsc`; stderr empty.
- Final `pwd` → `C:/work/shop/web`.
- Status: **resolved**. The identical command succeeded with only the starting cwd changed, which confirms the cwd drift was the sole cause.

**Going forward:** In this persistent shell, either issue relative commands from a known base (reset with an absolute `Set-Location` first) or use absolute/`-LiteralPath` targets so the UI's remembered root and the shell's actual cwd can't diverge silently. Had the normalized retry still failed, the next step would be to look elsewhere (npm/tsc errors, package.json scripts, node_modules integrity) rather than continuing to adjust cwd.
