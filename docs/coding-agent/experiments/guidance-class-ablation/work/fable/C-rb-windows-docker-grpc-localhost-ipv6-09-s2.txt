**Cause:** Not a workspace/code problem. `localhost` resolves to `::1` first on this host; the Ruby probe connects to `[::1]:50051`, where Docker Desktop's published-port proxy accepts the TCP connection but never returns HTTP/2 response headers, so the plaintext h2c stream stalls until the 2 s deadline (exit 2, `DEADLINE_EXCEEDED`). The server was never reached — the interceptor log shows no invocation. The REST sibling on 50080 works because HTTP/1.1 over the same proxy is not affected; the 127.0.0.1 retry of the identical RPC succeeds and *does* appear in the service log (`invoked=true completed=true`), isolating the fault to the IPv6 loopback path, not the service, port mapping, container health, or the probe.

**Smallest safe remediation:** Use the IPv4 loopback address for the local gRPC target — `--target 127.0.0.1:50051` (or set the equivalent in local config/env so the probe/client stops relying on `localhost` resolution). Do not change the service, port mappings, timeouts, or Docker settings; nothing there is broken.
