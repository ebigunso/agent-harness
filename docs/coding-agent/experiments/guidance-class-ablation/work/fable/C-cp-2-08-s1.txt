**Verdict: block.** The change fixes the symptom in three call sites, leaves the fourth broken, and moves the bug's origin nowhere.

**Findings**

1. **`lib/amounts.rb` — `serialize` is the defect and is untouched.**
   `{ dollars: invoice.cents }` puts an integer cent count under a key whose contract (per the notes) is a decimal dollar amount. Every consumer of `serialize` inherits that lie. The diff compensates in three consumers instead of correcting the value at the point where the unit is mislabeled. Required: make `serialize` honor its own contract —
   ```ruby
   def serialize(invoice)
     { dollars: BigDecimal(invoice.cents) / 100 }
   end
   ```
   — and revert the three presenter edits so they go back to `serialize(invoice)[:dollars]`.

2. **`lib/amounts.rb` — `accounting_amount` still returns cents labeled as dollars.**
   The task explicitly names accounting exports. After this diff, cents=1234 yields `12.34` on web/email/receipt and `1234` in the accounting export — the presenters now disagree with each other, which is arguably worse than the uniform bug they replaced (a reconciliation between a receipt and the ledger will now fail by a factor of 100). Fixing `serialize` per finding 1 resolves this automatically; if the author insists on per-caller conversion, `accounting_amount` must be included, but that path should be rejected in favor of finding 1.

3. **`lib/amounts.rb` — conversion logic triplicated.**
   `BigDecimal(serialize(invoice)[:dollars].to_s) / 100` copy-pasted three times is exactly the "compensating logic" pattern: it encodes knowledge that `serialize` is wrong into every caller, and any new caller of `serialize` (or any existing one the author missed, e.g. finding 2) silently gets cents. Once `serialize` is fixed, this duplication disappears; no separate helper is needed.
