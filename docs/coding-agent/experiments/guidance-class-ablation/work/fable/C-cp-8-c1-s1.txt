Reasoning against the review criteria:

- **Abstraction is justified by real use.** `Amount` has two live callers (`Csv`, `Text`), both confirmed active. This is exactly the point at which factoring out a shared helper pays for itself — it prevents the two exporters from drifting on precision, rounding, or culture.
- **Scope is correct.** Only the thing that is genuinely common — decimal-to-string formatting — is shared. The CSV header and the `Total:` label stay in their respective exporters rather than being pushed into a generic "exporter template," which would have been accidental complexity.
- **No dependency problems.** Single static class, private helper, no cycles, no new external dependencies.
- **`CultureInfo.InvariantCulture` is the right call.** A CSV numeric column and an invoice total must not pick up a locale-specific decimal separator (`1,50`) from the host thread; the invariant culture guarantees `.` and no group separators with `"0.00"`. Negative values render with a leading `-`, which is fine for both formats.
- **Visibility is appropriate.** `Amount` is private to `Export`; nothing forces callers to depend on the formatting detail.
