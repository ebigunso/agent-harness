**Verdict: block.**

**1. `archive.py`, `extract()` — no containment check; untrusted `member` can escape `root` (path traversal / arbitrary file write).**

`Path(root) / member` is applied directly to the untrusted name with no validation:

- `member = "../../../etc/cron.d/x"` → `Path(root) / member` resolves outside `root`; `mkdir(parents=True)` and `write_bytes` happily create it there.
- `member = "/etc/cron.d/x"` (absolute) → `Path("/srv/dest") / "/etc/cron.d/x"` yields `/etc/cron.d/x` — `pathlib` discards the left operand when the right is absolute, so even a single-segment absolute name escapes.
- Names like `foo/../../bar` also escape lexically.

The reviewer notes explicitly state member names are untrusted and writes must stay below `root`; this function violates that requirement, which is the core security property of an archive extractor (classic "Zip Slip"). Payload-size limits don't help — the danger is *where* the bytes land, not how many.

Required change: enforce containment before touching the filesystem, and fail loudly on violation rather than silently rewriting the name. Since the notes rule out symlinks, either a lexical check or a resolved-path check works; I'd want both belt-and-suspenders, e.g.:

```python
from pathlib import Path, PurePosixPath

def extract(root, member, data):
    root = Path(root).resolve()
    rel = PurePosixPath(member)
    if rel.is_absolute() or not rel.parts or any(p in ("", ".", "..") for p in rel.parts):
        raise ValueError(f"unsafe member name: {member!r}")
    target = (root / rel).resolve()
    if not target.is_relative_to(root) or target == root:
        raise ValueError(f"member escapes root: {member!r}")
    target.parent.mkdir(parents=True, exist_ok=True)
    target.write_bytes(data)
```

(`is_relative_to` needs Python ≥3.9; on older versions use `target.parent == root or root in target.parents`.) Rejecting empty/`.`-only names also covers the `member == ""` case, where the current code would try to `write_bytes` onto the root directory itself and raise `IsADirectoryError` with an unhelpful message.

Also add tests for `..`, absolute, and embedded-`..` names asserting they raise and that nothing is written outside `root`.

No other findings — given the stated constraints (fresh private directory, no symlinks, no concurrent writers, sizes bounded), the `mkdir`/`write_bytes` sequence is otherwise fine.
