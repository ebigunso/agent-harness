**Cause**

`npm ci` must delete `node_modules` before reinstalling, and the `unlink` of `node_modules\better-sqlite3\build\Release\better_sqlite3.node` is refused with EPERM (errno -4048). This is not a permissions or lockfile problem — the probe file beside the module can be created/removed, ACLs are clean, the cache and registry are fine, and package.json/package-lock.json are in sync. The binary is simply mapped into a running process: `tasklist /m better_sqlite3.node` shows `node.exe` PID 4101, which is this repository's Express/TypeScript dev server (launched from `C:/work/npm-lock/src/server.ts`) and is still running in its original terminal. Windows won't let a loaded native addon (`.node` DLL) be unlinked while it's in use.

So this *is* a workspace problem, and specifically a self-inflicted one: the repo's own dev server is holding the lock.

**Smallest safe remediation**

Stop the dev server, then retry. Prefer a graceful stop over `taskkill /F` since you own the terminal:

1. In the terminal running the dev server, press `Ctrl+C` (or stop the task in your editor if it's editor-launched).
2. Only if it doesn't exit: `taskkill /PID 4101 /F` — the PID is confirmed to be this repo's server, so force-killing it is acceptable as a fallback, but not the first move.
3. Re-run: `npm ci`

Don't delete `node_modules` manually with elevated rights, don't disable antivirus, and don't `npm install --force`; none of those address the lock and the last one can desync the lockfile.

**Confirmation**

- Before retrying, verify the lock is gone:
  `tasklist /m better_sqlite3.node` should print "No tasks are running which match the specified criteria" (or at least no `node.exe` entry).
  Optionally `tasklist | findstr node` to confirm no other stray node processes from this repo.
- `npm ci` exits 0 with no EPERM/EBUSY lines in stderr.
- `node_modules\better-sqlite3\build\Release\better_sqlite3.node` exists post-install (fresh from the prebuilt binary or rebuilt for Node 20.18.0).
- Restart the dev server and confirm it loads the addon (no `MODULE_NOT_FOUND` / `was compiled against a different Node.js version` errors on startup).

**Evidence to keep**: the original `npm ci` stderr above, the `tasklist /m` output showing PID 4101, how it was stopped (Ctrl+C vs `taskkill`), and the exit code of the retry.
