**Verdict: this is a workspace/environment problem (stream encoding), not a bug in the scan logic.**

**Cause**

`print(status, flush=True)` tries to write `"Working 🧪"` to `sys.stdout`. Because stdout is a pipe (not a console) and `sys.flags.utf8_mode = 0`, CPython 3.12 picks the locale ANSI code page for the stream — here `cp932` (Japanese). `\U0001f9ea` (🧪) has no cp932 representation, so the codec raises `UnicodeEncodeError` at position 8 (the emoji, right after `"Working "`). The `flush=True` you added is irrelevant: encoding happens before flushing, and the failure is deterministic for that character on that codec.

**Partial-effects check before rerunning**

- stdout is empty, so nothing was emitted before the crash.
- The script scans files read-only, so there is no partially-written output, temp file, or state to clean up. Rerunning is safe.

**Smallest safe remediation (command-scoped, no code change)**

Override the I/O encoding only for this invocation:

```powershell
& { $env:PYTHONIOENCODING = 'utf-8'; python progress.py }
```

(Equivalent: `python -X utf8 progress.py`, which enables UTF-8 mode for that process.) Both leave the session's environment and the script untouched.

If you want the script to be self-sufficient because it owns its stdout, the durable fix is at the top of `progress.py`:

```python
import sys
sys.stdout.reconfigure(encoding="utf-8")
```

and, for any file writes the script later adds, `open(path, "w", encoding="utf-8")`. I would not replace the emoji with ASCII unless you'd rather not depend on the consumer being UTF-8-aware.

**Confirmation**

1. Rerun with the override; expect exit code 0 and `Working 🧪` on stdout with no traceback.
2. Because stdout is being captured, make sure the consumer decodes UTF-8 too, otherwise you'll see mojibake rather than an error — in PowerShell 7: `[Console]::OutputEncoding = [System.Text.Encoding]::UTF8` before capturing (`$out = python progress.py`), then check `$out -eq 'Working 🧪'`.
3. Optionally verify the stream state inside the fixed process: `python -c "import sys; print(sys.stdout.encoding)"` under the same override should print `utf-8`.
