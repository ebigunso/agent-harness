**Cause**

Not a data or environment problem — the probe's assertion is measuring the wrong thing. `$raw | ConvertFrom-Json` produces a one-element array, but the pipeline enumerates it on the way out, so `$parsed` receives the bare element (`System.Int64` 7, exactly what stdout shows). `$parsed -isnot [array]` then reports "scalar" even though the wire value `[7]` is correctly framed as an array. This check would pass for `[7,8]` and fail for `[7]` and `[]`, so it can't serve as a cardinality-stable framing test.

**Smallest safe remediation**

You're on PowerShell 7.4.6, so `-NoEnumerate` is available. Change line 5 only:

```powershell
$parsed = $raw | ConvertFrom-Json -NoEnumerate
```

and don't pipe `$parsed` anywhere afterwards (that would unroll it again). With `-NoEnumerate`, `[7]` becomes `Object[]` of length 1 and `[]` becomes `Object[]` of length 0, so both satisfy the `-is [array]` check; a scalar wire value like `7` still parses to `Int64` and is still rejected, which matches the contract.

If the probe ever needs to run under Windows PowerShell 5.1 (no `-NoEnumerate`), assert framing on the raw string instead:

```powershell
$t = $raw.Trim()
if (-not ($t.StartsWith('[') -and $t.EndsWith(']'))) { throw 'Expected JSON array' }
```
