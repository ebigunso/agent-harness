**Cause**

`npm ci` starts by removing `node_modules`. The unlink of `node_modules\node-pty\build\Release\pty.node` fails with `EPERM` (errno -4048) because the DLL is mapped into a running process: `electron.exe` PID 4109, the repository's own Electron terminal preview (`preview/main.js`), which has `pty.node` loaded. Windows will not let you delete a loaded image, so npm reports EPERM even though there is no permissions problem — the probe file beside the module can be created/removed, ACLs are clean, the lockfile is in sync, and the registry is reachable. This is not a workspace/config defect; it's a file-in-use conflict with a process the repo started.

**Smallest safe remediation**

1. Stop the preview gracefully — close the Electron window, or Ctrl+C / stop the dev script that launched `preview/main.js`. Do not `taskkill` first; a clean shutdown lets node-pty tear down its conpty handles.
2. Confirm the holder is gone:
   ```powershell
   tasklist /m pty.node
   ```
   Expected: `INFO: No tasks are running which match the specified criteria.`
3. Re-run the original command:
   ```powershell
   npm ci
   ```
4. Only if the process refuses to exit, and after re-checking that PID 4109 is still `electron.exe` holding this exact module path:
   ```powershell
   taskkill /PID 4109 /F
   ```
   then repeat steps 2–3.

**Confirmation**

- `tasklist /m pty.node` shows no holders before the retry.
- `npm ci` exits 0 with no `EPERM`/`EBUSY` lines.
- `node_modules\node-pty\build\Release\pty.node` exists after install.
- If it fails again, read the new `npm error path` (it may be a different module) and run `tasklist | findstr node` / `tasklist /m <newmodule>.node` to find the next holder.

**Follow-up to avoid a second failure**

`npm ci` wipes `node_modules`, so the node-pty addon that was rebuilt for the Electron ABI is gone; the fresh install is built for Node 20.18.0. Before relaunching the preview, re-run the Electron rebuild step the project uses (e.g. `npx electron-rebuild -f -w node-pty` or the repo's postinstall/script), otherwise the preview will fail with a `NODE_MODULE_VERSION` mismatch and it will look like a new bug.
