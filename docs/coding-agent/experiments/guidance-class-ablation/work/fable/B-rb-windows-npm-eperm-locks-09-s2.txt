**Cause**

`npm ci` is a workspace problem, not an npm/registry/permissions issue: the lockfile is in sync, the registry responds, the cache and project dirs are writable, and a probe file beside the module can be created and deleted. The unlink fails only on `node_modules\node-pty\build\Release\pty.node` because that binary is mapped into a running process. `tasklist /m pty.node` identifies it: `electron.exe` PID 4109, the repo's own Electron terminal preview (`preview/main.js`). Windows won't let npm delete a loaded DLL/`.node`, so `npm ci`'s node_modules wipe aborts with EPERM (-4048).

**Smallest safe remediation**

1. Stop the preview process gracefully first — close the Electron preview window / stop whatever task launched `preview/main.js` (it's owned by this repo, so it's safe to stop; nothing else is holding the file).
2. Only if it doesn't exit: `taskkill /PID 4109 /F`.
3. Re-run `npm ci`.

Don't reach for `rm -rf node_modules`, cache cleans, or running as admin — none address the lock and the evidence rules those causes out.

**Confirmation**

- `tasklist /m pty.node` returns "No tasks are running which match the specified criteria" (and `tasklist | findstr /i electron` shows no stray preview instances).
- `npm ci` exits 0 with no EPERM/EBUSY; `node_modules\node-pty\build\Release\pty.node` has a fresh timestamp.

**One follow-on caveat**

The current `pty.node` was rebuilt for the Electron ABI. `npm ci` will rebuild node-pty from source against Node 20's ABI, so before relaunching the preview you'll need to re-run your Electron rebuild step (e.g. `electron-rebuild` / `@electron/rebuild`), otherwise the preview will fail with a `NODE_MODULE_VERSION` mismatch. That's expected, not a regression of this fix.
