**Findings**

1. **`src/documents.rs` — `load()` still does not decompress.**
   The task is to restore reading gzip-compressed inputs. The reviewer notes say decompression previously lived in the shared loader (`flate2::read::GzDecoder`) and was removed by a prior change. The diff leaves `load()` as a raw `fs::read`, so every caller still receives compressed bytes. This is the root cause, and it is untouched.

   The UTF-8 errors the author was seeing arise because the bytes are gzip data, not text. Switching to lossy decoding makes `preview` "succeed" by rendering the gzip header/deflate stream as a wall of U+FFFD and stray ASCII — that is not "rendering the document." It also throws away the error signal for genuinely corrupt inputs, which the original strict `from_utf8` correctly reported as `InvalidData`. Once `load()` decompresses, this line change is unnecessary.
   *Require:* revert this hunk to the strict `String::from_utf8(...)` mapping. If lossy preview rendering is actually wanted as a product behavior, that is a separate change with its own justification, not part of a "restore gzip support" fix.

3. **`src/documents.rs` — `index()` is still broken.**
   `index` just returns `load(path)`, so it continues to hand compressed bytes to the index API, which per the notes performs strict UTF-8 validation and will reject them. The change therefore fixes neither of the two consumers named in the task ("preview and indexing"); it only hides the failure in one of them. Fixing `load()` (finding 1) resolves this without touching `index` at all.
