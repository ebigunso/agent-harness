**Findings**

1. **`locale/en/LC_MESSAGES/django.po` — heading hardcodes "USD"**
   The translation is changed from `"Invoice"` to `"Invoice (USD)"` in the same change that introduces a per-invoice `currency` field. The moment any invoice has `currency != "USD"`, its heading will be wrong. The msgstr is a static string; it can't reflect the row's currency. Either leave the heading as `"Invoice"` or make it a format string (e.g. `msgstr "Invoice (%(currency)s)"`) and interpolate `invoice.currency` at the render site. I would block on this — it's a visible correctness bug introduced by the feature it's meant to support.

2. **Commit scope — unrelated schema/UI changes bundled under "report malformed import rows"**
   The commit message and task cover only `importer.py`, but the diff also adds a model field, a migration, and a locale change. Bundling a schema migration into a commit labeled as an importer error-message tweak makes it easy to miss in review (as the hardcoded-USD issue above shows), and makes revert/bisect painful. Even if the currency work is separately approved, it should land as its own commit with its own message. I'd require the split.

Note it does not catch `TypeError` for non-string input; given the stated contract is integer syntax only, that's acceptable.
