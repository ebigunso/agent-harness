## Cause

This is a **script bug, not a workspace problem**. The raw JSON `["north"]` is a valid single-element array, but the line

```powershell
$parsed = $raw | ConvertFrom-Json
```

pipes the parse result through the pipeline. `ConvertFrom-Json` (without `-NoEnumerate`) emits array elements one at a time, and the pipeline **unrolls** the single-element array into its lone member — the string `"north"`. So `$parsed` is captured as a `System.String`, not an array, and `-isnot [array]` is true → the `throw` fires.

The stdout confirms this: `parsed type=System.String`. Nothing on disk or in the environment is wrong; the assertion is measuring a post-pipeline value that can never prove wire framing for a singleton.

## Smallest safe remediation

Preserve the array by parsing without enumerating, and avoid re-piping. On 7.4.6 `-NoEnumerate` is available:

```powershell
$parsed = ConvertFrom-Json -InputObject $raw -NoEnumerate
```

Using `-InputObject` (rather than `$raw | ConvertFrom-Json -NoEnumerate`) sidesteps the pipeline entirely, so there is no chance of re-enumeration. This is the minimal change — the assertion line is left untouched.

(If you must stay compatible with Windows PowerShell 5.1, which lacks `-NoEnumerate`, don't rely on the type at all: assert on raw framing instead — trimmed `$raw` starts with `[` and ends with `]` — and derive element count from the parsed value defensively, e.g. `@($parsed).Count`.)

## Confirmation

Re-run the exact command:

```
pwsh -NoProfile -File probes/cardinality.ps1
```

Expect:

- **Exit code 0** (no thrown error, empty stderr).
- stdout `parsed type=System.Object[]` instead of `System.String`.
- The `-isnot [array]` branch does not execute.

To confirm the fix honours the whole contract (empty, singleton, multiple; reject scalars), temporarily drive `$raw` through the boundary cases and check that `@($parsed).Count` reports `0`, `1`, `N` for `[]`, `["north"]`, `["north","south"]`, and that a scalar wire value like `"north"` still parses to a non-array and is correctly rejected. Also verify `$raw` trimmed still starts `[`/ends `]` so the count reflects genuine wire framing, not a post-pipeline artifact.
