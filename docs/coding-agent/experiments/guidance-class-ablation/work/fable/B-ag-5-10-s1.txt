## Findings

### 1. `Source.kt` — data model cannot represent the full truth table; unknown and conflicting inputs are silently classified as trusted-external

`classify` takes two independent booleans, which yields four input states. The output is a single `Boolean`, so two of those states are collapsed into the wrong bucket:

| internalEvidence | externalEvidence | Intended class | `isInternal` produced | Result |
|---|---|---|---|---|
| true | false | trusted-internal | `true` | correct |
| false | true | trusted-external | `false` | correct |
| false | false | **unknown** | `false` | **misclassified as trusted-external** |
| true | true | **conflicting** | `false` | **misclassified as trusted-external** |

Why it matters: this is a trust classification. A record with no evidence, or with contradictory evidence, is granted a *trusted* label by default. Any consumer doing `if (source.isInternal) … else treatAsExternal(…)` has no way to detect the ambiguous cases — the information is destroyed at the boundary where it should be enforced. That's an invariant ("trusted-* only when evidence is unambiguous") that is not merely unenforced but unrepresentable. The `&& !externalEvidence` guard also reads as though conflict is handled, which will mislead future readers into thinking it's covered.

Required instead:

- Replace the `Boolean` with an explicit closed type covering all four outcomes, e.g.

  ```kotlin
  enum class SourceTrust { TRUSTED_INTERNAL, TRUSTED_EXTERNAL, UNKNOWN, CONFLICTING }

  fun classify(internalEvidence: Boolean, externalEvidence: Boolean): SourceTrust =
      when {
          internalEvidence && !externalEvidence -> SourceTrust.TRUSTED_INTERNAL
          !internalEvidence && externalEvidence -> SourceTrust.TRUSTED_EXTERNAL
          internalEvidence && externalEvidence  -> SourceTrust.CONFLICTING
          else                                  -> SourceTrust.UNKNOWN
      }
  ```

  (or a sealed class if the conflicting case needs to carry the evidence). A `when` over an enum forces every consumer to handle the ambiguous cases rather than falling through to a trusted branch.
- Add a unit test that enumerates all four `(internalEvidence, externalEvidence)` combinations and asserts the expected classification. The bug here is exactly the kind a four-row table test catches, and the absence of one is how it shipped.
- If callers already consume `Source.isInternal`, do not keep it as a convenience accessor that maps the new type back to a boolean — that would reintroduce the same collapse one layer up.

No other findings; the remaining code is trivial and the issue above is the entire change.
