**Findings**

1. **`refund.py`, `PurchaseRepository.refundable` — business rule duplicated into the data access layer.**
   The repository re-implements the 30-day eligibility rule inline (`return age_days <= 30`) instead of delegating to `RefundPolicy.eligible`. This is exactly the Gate 1 anti-pattern "data access layer deciding domain policy": there are now two independent owners of the refund window, and when the policy changes (e.g. 45 days, per-category windows), the repository copy will silently diverge. The reviewer notes explicitly state `RefundPolicy` owns eligibility and the repository should only retrieve purchase facts.
   **Require:** the repository must not contain the eligibility rule. Either (a) have the repository expose a fact-retrieval method (e.g. `exists(db, purchase_id)` / `get(db, purchase_id)` raising `LookupError` when missing) and have the caller/application layer combine it with `RefundPolicy.eligible(age_days)`, or (b) at minimum replace the literal with `return RefundPolicy.eligible(age_days)`. Option (a) is preferred, since "is refundable" is an application/domain decision, not a persistence concern.

2. **`refund.py`, `PurchaseRepository.refundable` — method name/signature encodes a domain decision in the repository.**
   Even with the literal fixed, a repository method named `refundable` that accepts `age_days` (a value it doesn't read from the database) is a cross-layer smell: the repository is taking a domain input it has no use for solely to answer a policy question. The task framing ("read refund eligibility") and reviewer notes describe the repository's role as retrieving purchase facts.
   **Require:** narrow the repository API to persistence facts about the purchase (existence / row lookup). Keep eligibility computation out of its signature.

**Not blocking, but note for the author:** the diff has no planning note identifying which boundary the behavior change belongs to, which is what let the rule leak into the repository. A one-line note ("eligibility computed in RefundPolicy; repository only checks existence") would have caught this before review.

The change is **not acceptable as-is** — finding 1 is a hard block.
