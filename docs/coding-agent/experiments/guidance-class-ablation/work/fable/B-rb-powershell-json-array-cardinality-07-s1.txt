**Cause:** The script defeats its own `-NoEnumerate`. `ConvertFrom-Json -NoEnumerate` does return the one-element array, but the result is then re-piped through `| Write-Output`, and that second pipeline stage unrolls the collection. `$parsed` receives the bare element (`System.String` "north"), so `-isnot [array]` throws. The JSON, the runtime (pwsh 7.4.6 supports `-NoEnumerate`), and the environment are all fine — this is a defect in the probe script, not a workspace/config problem. It only shows up at exactly one element: `[]` and multi-element arrays would have passed even with the re-pipe.

**Smallest safe remediation:** Drop the re-pipe on line 5 so the `-NoEnumerate` result is assigned directly:

```powershell
$parsed = $raw | ConvertFrom-Json -NoEnumerate
```

(If the probe also needs to run under Windows PowerShell 5.1, where `-NoEnumerate` doesn't exist, assert framing on the raw string instead — `$raw.Trim()` starts with `[` and ends with `]` — but that isn't required for this pwsh 7.4.6 scenario.)
