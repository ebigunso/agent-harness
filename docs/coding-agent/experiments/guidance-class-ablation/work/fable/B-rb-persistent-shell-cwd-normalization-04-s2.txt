**Cause**

Persistent-shell cwd drift. A prior `Set-Location -LiteralPath 'C:/work/orders/src/main/resources'` moved the shell into a subdirectory, and that state carried over to the next command. `mvn test` was then invoked from `C:\work\orders\src\main\resources`, which contains only `application.properties`, so Maven found no `pom.xml` and refused to run ("there is no POM in this directory"). The tool UI's remembered workspace root (`C:/work/orders`) did not reflect the shell's actual cwd, which is why the mismatch was easy to miss.

This is a workspace/cwd problem, not a code, dependency, Java/Maven, PATH, or permission problem — nothing else changed between attempts, and the identical command succeeded once the cwd was corrected.

**Smallest safe remediation**

Navigate explicitly to the intended base and rerun the command unchanged:

```powershell
pwd
Set-Location -LiteralPath 'C:/work/orders'
mvn test
```

No edits to the project, environment, or command itself are needed. Avoid stacking further `cd ... && ...` chains on top of the drifted state; a single explicit `Set-Location` to `C:/work/orders` is sufficient.
