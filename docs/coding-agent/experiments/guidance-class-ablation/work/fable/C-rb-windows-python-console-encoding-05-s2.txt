**Verdict:** Not a workspace problem. The script read the data and built the row correctly; it died only at the output-encoding step. Nothing in `C:/work/py-report` needs changing to make it run.

**Cause**
`sys.stdout` is a pipe, not a console, and UTF-8 mode is off (`sys.flags.utf8_mode = 0`), so CPython 3.12 on Windows falls back to the ANSI code page for stdout → `cp1252`. `cp1252` has no mapping for `'日'` (U+65E5), so `codecs.charmap_encode` raises `UnicodeEncodeError` on the first row containing it. The traceback line (`encodings\cp1252.py`) and the observed `sys.stdout.encoding = cp1252` agree.

**Partial effects before rerunning**
None to clean up. stdout is empty (the failure was on the first non-ASCII row), and the script writes only to stdout, never to the source CSV, so no file was truncated or half-written. Safe to rerun.

**Smallest safe remediation (command-scoped, no code change)**
```powershell
$env:PYTHONIOENCODING = 'utf-8'; python csv_preview.py; Remove-Item Env:PYTHONIOENCODING
```
This overrides only the stdio encoding for that invocation. (`python -X utf8 csv_preview.py` also works, but it additionally changes the default for `open()` and the filesystem encoding, which could alter how the *source* CSV is read if that `open()` has no explicit `encoding=` — so it's a slightly larger change than needed.)

**If you own the script (durable fix)**
Add before the first write:
```python
sys.stdout.reconfigure(encoding="utf-8", newline="")
```
`encoding="utf-8"` fixes the crash; `newline=""` is what the `csv` module expects, otherwise the CRLF dialect on a Windows text-mode stdout gets translated to `\r\r\n`. If the script's `open()` of the source CSV lacks `encoding="utf-8"`, add it too.

**Confirmation**
1. Rerun the override command; expect exit code `0` and a non-empty stdout containing `date,日`.
2. Check the bytes rather than the rendered text, because PowerShell decodes native output with `[Console]::OutputEncoding`, which may still be cp1252/437 and show mojibake even when Python emitted correct UTF-8:
   ```powershell
   $env:PYTHONIOENCODING='utf-8'; python csv_preview.py > out.csv; Remove-Item Env:PYTHONIOENCODING
   Format-Hex out.csv   # expect E6 97 A5 for 日, and 0D 0A line endings
   ```
   Or `python -c "import sys; print(sys.stdout.encoding)"` under the same env var prints `utf-8` (vs `cp1252` without it).
3. Record: the failing character (`U+65E5`, `cp1252`, `charmap` codec), the exact override command, and the successful output/exit code.
