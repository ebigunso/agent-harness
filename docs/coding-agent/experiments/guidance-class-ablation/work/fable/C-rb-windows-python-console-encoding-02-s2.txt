**Cause**

This is a stream-encoding problem, not a workspace problem. The script ran to completion: the JSON input decoded, `data == {"label": "🚀"}`, and `json.dumps(..., ensure_ascii=False)` returned a string containing the raw U+1F680. The failure is at the `print()` boundary. Because stdout is a pipe (not a Windows console) and UTF-8 mode is off (`sys.flags.utf8_mode = 0`), CPython 3.12 encodes stdout with the ANSI code page — here `cp932` (Japanese locale). cp932 has no mapping for U+1F680, so `print` raises `UnicodeEncodeError` and the process exits 1 with nothing written.

Partial effects before rerunning: none. stdout is empty and the script does no file writes, so a rerun is safe and idempotent.

**Smallest safe remediation**

Command-scoped, no code change:

```powershell
$env:PYTHONIOENCODING = 'utf-8'; python json_report.py; Remove-Item Env:\PYTHONIOENCODING
```

(Equivalent, and truly per-invocation: `python -X utf8 json_report.py`.)

If `json_report.py` is yours and this output is meant to be consumed by other tools, make the script own its stdout encoding so it doesn't depend on the caller's environment — add near the top, before any `print`:

```python
import sys
sys.stdout.reconfigure(encoding="utf-8")
```

Any file output the script grows later should likewise use `open(..., encoding="utf-8")`. Dropping `ensure_ascii=False` would also stop the crash, but it changes the output to `"\ud83d\ude80"` escapes — only do that if the consumer prefers ASCII JSON.

**Confirmation**

1. Rerun with the override; expect exit code 0 and stdout `{"label": "🚀"}`.
2. Verify the bytes are actually UTF-8 (not just "no error"), since the capturing side decides how to interpret them:
   ```powershell
   $env:PYTHONIOENCODING='utf-8'; python json_report.py | python -c "import sys; print(sys.stdin.buffer.read())"
   ```
   Expect `b'{"label": "\xf0\x9f\x9a\x80"}\r\n'`-style output (`F0 9F 9A 80` is the UTF-8 encoding of U+1F680).
3. If PowerShell itself is the consumer (e.g. `$out = python json_report.py`), also set `[Console]::OutputEncoding = [Text.UTF8Encoding]::new()` in that session; otherwise PowerShell will decode the correct UTF-8 bytes as cp932 and you'll see mojibake rather than an error.

Record for the ticket: error `UnicodeEncodeError: 'cp932' codec can't encode character '\U0001f680'`, environment `sys.stdout.encoding = cp932`, `utf8_mode = 0`, remediation command above, and the successful `{"label": "🚀"}` output.
