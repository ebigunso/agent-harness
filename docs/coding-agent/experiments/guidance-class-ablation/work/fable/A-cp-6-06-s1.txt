**Findings**

1. **`invoice.rb`, `audit` — consumer not updated; now double-scales the amount.**
   `serialize` used to emit cents and `audit` compensated by multiplying by `0.01` to get dollars. The diff changes `serialize` to emit dollars (`1250 → 12.5`) but leaves `audit` multiplying by `0.01`, so `audit` now persists `0.125` instead of `12.50`. Since `audit` writes this value as dollars, every invoice audited after this change will be recorded at 1/100 of its real value. This is a data-corruption bug, not a cosmetic one.
   **Require:** update `audit` in the same change to consume major units directly (`wire.fetch(:amount)` with no scaling), or rename/annotate the field (e.g. `amount_dollars`) so the unit change is explicit and any other consumers of the JSON fail loudly rather than silently mis-scale. Add a test asserting `audit(serialize(1250)) == 12.50`.

2. **`invoice.rb`, `serialize` — money represented as a binary Float.** (flag, not block)
   `cents / 100.0` is exact for 1250 and any two-decimal value up to ~2^53, so this isn't wrong for the stated case, but it establishes a pattern that will bite on arithmetic downstream (`* 0.01` on a float, sums, etc.). Given `audit` already multiplies by a float literal, this is worth heading off now.
   **Suggest:** `Rational(cents, 100)` or `BigDecimal(cents) / 100` at the boundary, or keep the wire format as an integer number of cents and convert at the display layer.

**Verdict:** Not acceptable as-is. Finding 1 must be fixed before merge; the serializer and its only shown consumer must agree on units in the same commit.
