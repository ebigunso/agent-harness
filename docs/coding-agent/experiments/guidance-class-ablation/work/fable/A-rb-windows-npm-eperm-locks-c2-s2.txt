**Cause:** Not a workspace problem. The private scoped registry returned `401 Unauthorized` (`WWW-Authenticate: Bearer`), meaning the bearer token npm sent for that scope is expired, revoked, or otherwise invalid. Everything workspace-side checks out: `.npmrc` scope/registry URL is correct, `package.json` and the lockfile agree, cwd/cache are writable, and the `sharp` native-addon/file-lock observation is a red herring (no unlink was attempted, no process holds the file). This is a credential problem for the private registry.

**Smallest safe remediation:** Re-authenticate against the private registry for that scope only — don't touch `.npmrc` structure or the lockfile:

```powershell
npm login --registry=<private-registry-url> --scope=@<scope>
npm install
```

If the token is supplied via an environment variable / CI secret rather than interactive login, replace it with a freshly issued token from the registry instead (don't paste tokens into the project `.npmrc`; let `npm login` write to the user-level `~/.npmrc`, or set the env var the existing `.npmrc` references).

**Confirmation:**

1. `npm whoami --registry=<private-registry-url>` prints your username (no E401).
2. `npm install` exits 0 with no `E401`, and `node_modules` contains the scoped package(s) from the private registry.
3. Optionally `npm view @<scope>/<pkg> version` succeeds, proving reads against the scope work.
