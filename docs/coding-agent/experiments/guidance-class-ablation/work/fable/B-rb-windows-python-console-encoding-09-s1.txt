**Cause**

Not a failure of the checks — all read-only checks passed. The crash is at print time: `check.py` line 15 prints `'PASS ' + symbol` where `symbol` is U+2713 CHECK MARK, and `sys.stdout` is encoding as `cp1252`, which has no mapping for U+2713.

One nuance vs. the reference note: stdout here is a **pipe, not an interactive console**, so this isn't the console/OEM code page — with `utf8_mode = 0`, CPython falls back to the locale (ANSI) code page for non-console streams, which on this machine is cp1252. Same failure class, slightly different source of the encoding. It is an environment/config problem (Python's default stream encoding on Windows), not a workspace-content problem, and nothing was partially written: the script only prints, and the traceback is the first output.

**Smallest safe remediation**

Rerun with the I/O encoding override, no file changes:

```powershell
$env:PYTHONIOENCODING = 'utf-8'; python check.py
```

(Equivalent: `python -X utf8 check.py`.) Because output is captured through a pipe, the consumer must also decode it as UTF-8 — if PowerShell itself is the consumer, `[Console]::OutputEncoding = [Text.UTF8Encoding]::new()` beforehand avoids mojibake on the receiving side.
