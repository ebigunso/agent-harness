**Verdict: not a workspace/cwd problem.** Do not apply the CWD normalization runbook here.

**Cause**

`git rev-parse --verify missing-branch` exits 128 with `fatal: Needed a single revision` because the ref `missing-branch` does not exist in the repository. That is the documented behavior of `--verify` when the argument cannot be resolved to a single object. The evidence rules out every workspace hypothesis:

- `pwd` = `C:/work/repo` before and after; `Set-Location` succeeded.
- `.git` and `README.md` resolve at `C:/work/repo`.
- `git rev-parse --show-toplevel` succeeds and prints `C:/work/repo`, so git found the repo and cwd is inside it.
- `git branch --list` shows only `main`; `git show-ref` has no `missing-branch`.

If cwd drift were the cause you would see `fatal: not a git repository` or a wrong `--show-toplevel`, not `Needed a single revision`.

**Smallest safe remediation**

This depends on intent, so pick one — none of them involve changing cwd:

1. If the branch name is a typo / stale assumption: correct the ref (e.g. `main`) in the calling command or script.
2. If the branch is expected to exist but wasn't fetched/created: create or fetch it (`git fetch origin missing-branch` or `git switch -c missing-branch`) — only if that is actually the intended state; don't create a branch just to silence the error.
3. If the command is an existence check by design (common in scripts): the 128 is the correct signal, not a failure. Handle it explicitly, e.g.
   `git rev-parse --verify --quiet missing-branch` (suppresses the fatal message, still non-zero) or `git show-ref --verify --quiet refs/heads/missing-branch`, then branch on the exit code.

**Confirmation**

- After fixing the ref name: `git rev-parse --verify <correct-ref>` exits 0 and prints a SHA.
- After creating/fetching: `git show-ref refs/heads/missing-branch` lists the ref, then rerun the original command unchanged → exit 0.
- If treating it as an existence probe: rerun with `--quiet`, confirm exit code 1/128 with empty stderr, and confirm the caller handles that path.

**Evidence to record**

- Failing command + `fatal: Needed a single revision` (128)
- cwd before/after: `C:/work/repo` (unchanged, verified by `--show-toplevel`)
- `git branch --list` → `main` only; no `missing-branch` in `git show-ref`
- Root cause: nonexistent ref, not cwd drift. Status: resolved once the ref is corrected/created, or reclassified as expected behavior if this was a probe.
