**Cause:** Wrong target port. The probe was pointed at `localhost:50052`, but nothing listens there — Docker publishes only `50051/tcp` (gRPC) and `50080/tcp` (health). The kernel refuses the TCP connect immediately, grpc-js reports `UNAVAILABLE`, and the probe maps that to exit 2. This is an invocation error (a typo/config slip in the port), not a workspace, Docker, DNS, or gRPC problem:

- `127.0.0.1:50052` fails identically → not a `localhost` → `::1` vs IPv4 resolution issue.
- Sibling `localhost:50080` returns 200 in 12 ms → Docker port forwarding and host networking are fine.
- Correctly targeted 50051 probes are healthy → server, h2c setup, and probe code are fine.
- The failure is "connection refused," not a deadline → the 2 s timeout is irrelevant and never elapsed.
- No server invocation log entries → the request never reached the container, consistent with no listener.

**Smallest safe remediation:** Fix the port in the command — no code, config, or container changes needed:

```powershell
node probes/unary.mjs --target localhost:50051 --timeout 2
```
