**Verdict: block.** The change does not implement bounded transient-retry; it implements an unconditional infinite retry that turns permanent failures into a hang.

**Findings**

1. **`src/inventory.mjs` — retries on every error, including permanent ones.**
   The `catch` has no classification. `api.inventory` rejects invalid SKUs with a permanent `ValidationError`; this code will retry that forever. A bad SKU now never resolves and never rejects — the caller hangs instead of getting an actionable error. Required: only retry on `TransportError` (or an explicit `isTransient(error)` predicate); rethrow everything else immediately and unchanged.

2. **`src/inventory.mjs` — no attempt limit and no overall time budget.**
   The reviewer notes confirm there is no external scheduler and only a per-attempt timeout. With this diff, a persistent network outage yields an unbounded sequence of attempts; the "per-attempt timeout" just becomes the loop period. The recursive `return fetchInventory(...)` also builds an unbounded promise chain, so memory grows for as long as the outage lasts. Required: a fixed `maxAttempts` (e.g. 3) and/or a total deadline, implemented as an iterative loop rather than recursion, after which the function rejects.

3. **`src/inventory.mjs` — no backoff between attempts.**
   Retries fire immediately on rejection, so during a transport failure every caller hammers the inventory service in a tight loop, worsening the very condition being retried. Required: delay between attempts (exponential backoff with jitter is the standard here).

4. **`src/inventory.mjs` — failure is swallowed with no diagnostic surface.**
   The caught `error` is discarded; nothing is logged, and because the function never rejects, no failure is ever visible to the caller or to monitoring. When retries are exhausted the function must rethrow the last error (ideally with attempt count / elapsed time attached), and each retried failure should be observable (log/metric) so a degraded backend is diagnosable rather than appearing as latency.

**Sketch of what I'd accept**

```js
export async function fetchInventory(api, sku, { maxAttempts = 3, baseDelayMs = 100 } = {}) {
  let lastError;
  for (let attempt = 1; attempt <= maxAttempts; attempt++) {
    try {
      return await api.inventory(sku);
    } catch (error) {
      if (!(error instanceof TransportError)) throw error;
      lastError = error;
      if (attempt < maxAttempts) {
        await sleep(baseDelayMs * 2 ** (attempt - 1) * (0.5 + Math.random()));
      }
    }
  }
  throw new Error(`fetchInventory(${sku}) failed after ${maxAttempts} attempts`, { cause: lastError });
}
```

Plus tests covering: `ValidationError` not retried; `TransportError` retried then succeeds; `TransportError` retried to exhaustion and rejects with the original as `cause`.
