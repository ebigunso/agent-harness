**Verdict: this is a workspace file-permission problem, not the Unicode/code-page issue in the reference material.**

## Cause

`export_report.py` line 25 opens `report.txt` for writing and the OS refuses: `PermissionError: [Errno 13]`. The diagnostic confirms the ACL on `report.txt` denies write access to the current user. Nothing else is wrong:

- No `UnicodeEncodeError` occurred; `sys.stdout.encoding` is already `utf-8` (piped stream), and the file open explicitly requests `encoding='utf-8'`. `PYTHONIOENCODING` / `reconfigure()` would change nothing here.
- The failure happened at `open()`, before any write or truncation, so the existing `report.txt` is intact and there are no partial side effects.
- No process lock is involved — it's a static ACL deny, so retrying won't help.

## Smallest safe remediation

Fix the ACL on the one file; don't touch the script or the parent directory.

```powershell
cd C:\work\py-report
icacls report.txt                                   # inspect: expect a (DENY) or missing W/M for this user
icacls report.txt /grant "$env:USERNAME:(M)"        # grant Modify
```

If there is an explicit deny entry, remove it (`icacls report.txt /remove:d "$env:USERNAME"`), since deny overrides grant. If you don't own the file and the grant fails, either take ownership (`takeown /f report.txt` from an elevated shell) or — if the file is just stale output nobody needs — have the script write to a different path (e.g. `report.out.txt`) and leave the locked file alone. Prefer the ACL fix; changing the output path is a workaround, not a repair.

Do **not** run the script elevated as a fix — that hides the permission issue and produces an admin-owned file that will fail the same way next run.

## Confirmation

1. `icacls report.txt` shows `(M)` or `(F)` for the user and no `(DENY)`.
2. Rerun `python export_report.py` → exit code 0, no traceback.
3. `Get-Item report.txt | Select LastWriteTime, Length` shows a fresh timestamp and non-zero size; `Get-Content report.txt -Encoding utf8 | Select -First 5` shows expected report content (including any em-dashes/smart quotes rendering correctly, which also confirms the UTF-8 file encoding is fine).
