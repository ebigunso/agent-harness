**Findings**

1. **`fee.py`, `fee()` — randomness is hard-wired to the global `random` module inside the function.**
   What's wrong: The promo selection (`random.choice([False, True])`) is fused with the fee arithmetic. There is no seam to control the selection, so the exact formula (20 vs 10) and the threshold (`cents >= 100`) cannot be validated deterministically — which the notes explicitly require. It also depends on process-global RNG state, so any caller or test that seeds `random` elsewhere silently changes this function's behavior.
   Why it matters: The two things that actually carry the money risk — the discount amount and the threshold boundary — are exactly the things you can't assert exactly.
   Require: Separate the pure computation from the random decision, e.g. `fee(cents, selected)` (or `fee(cents, *, rng=random)` / an injected `select_promo` callable) with a thin production wrapper that supplies the random choice. Production keeps its randomness; tests pass `selected=True/False` directly.

2. **`fee.py`, `test_average` — the only test is statistical and doesn't check what the task specifies.**
   What's wrong: It averages 1000 random calls at `cents=100` and asserts `13 < average < 17`. That never asserts the fee is exactly 10 or 20, never exercises the threshold (99 vs 100, 0), and would still pass for several wrong implementations (e.g. a 5-cent discount always applied, a threshold of 50, or a `> 100` off-by-one — no wait, `> 100` would fail here, but `>= 50` or `>= 1` would not). It also depends on 1000 draws from unseeded global state, so it is a probabilistic check standing in for a correctness check.
   Why it matters: Evidence is mismatched to the surface: the wide-band average can't catch the defects most likely to ship (wrong discount, wrong boundary), and it's fragile setup by construction.
   Require: Once the seam from (1) exists, replace with deterministic cases: `fee(100, selected=True) == 10`, `fee(100, selected=False) == 20`, `fee(99, selected=True) == 20`, `fee(0, selected=True) == 20`, `fee(150, selected=True) == 10`. If you want to cover the wrapper, one test with an injected stub RNG/callable showing it delegates is sufficient — no loop over random draws.

3. **`fee.py` — test code lives in the production module.**
   What's wrong: `test_average` is defined alongside `fee`, so the test ships with the library and the module's import graph includes test concerns.
   Why it matters: Minor, but it muddles the module's surface and makes the tests harder to discover/organize as this grows.
   Require: Move tests to `test_fee.py` (or the repo's test directory).

Not blocking, noting for completeness: input validation for the "nonnegative integer cents" contract is absent; if callers are trusted that's fine, otherwise a guard would be appropriate.

**Verdict:** Not acceptable as-is. Items 1 and 2 are blocking — they go directly against the stated requirement that the formula and threshold be validated deterministically.
