**Cause**

This is not a workspace or file problem — the read-only audit already opened `C:/reports/🧪.txt` successfully. The failure is purely in printing the path.

Because stdout is a pipe rather than a Windows console, CPython 3.12 does not use the UTF‑8 console writer; it falls back to the locale/ANSI code page for the stream, which on this machine is cp932 (`sys.stdout.encoding = cp932`, `utf8_mode = 0`). `print(path)` therefore tries to encode U+1F9EA (🧪) as cp932, which has no mapping for it, so `UnicodeEncodeError` is raised at `audit.py:40` with the default `errors='strict'`. The filesystem side is unaffected (Windows filesystem encoding is already UTF‑8), which is why the open succeeded and only the display failed.

**Smallest safe remediation**

Make the standard streams UTF‑8 for this invocation only, without touching the script or changing `open()` defaults:

```powershell
$env:PYTHONIOENCODING = 'utf-8'
python audit.py
```

`PYTHONIOENCODING` affects only stdin/stdout/stderr, so it is narrower than `-X utf8` / `PYTHONUTF8=1` (which would also switch the default encoding of `open()` and could change how cp932‑encoded input files are read). If you'd rather fix it in the script, the equivalent minimal line near the top of `audit.py` is `sys.stdout.reconfigure(encoding='utf-8')`; using `errors='replace'` instead would suppress the crash but silently mangle path names in the report, so prefer real UTF‑8.

If the consumer of the pipe is PowerShell itself, also have it decode the bytes as UTF‑8 so the character isn't mojibaked on the way in:

```powershell
[Console]::OutputEncoding = [System.Text.Encoding]::UTF8
```

(PowerShell 7.4 decodes native-command output with `[Console]::OutputEncoding`, which defaults to the OEM code page here.)

**Confirmation**

1. Under the same piped conditions, check the stream encoding took effect:
   `python -c "import sys; print(sys.stdout.encoding)" | Out-String` → prints `utf-8`.
2. Re-run `python audit.py` through the pipe: exit code should be `0` (`$LASTEXITCODE`), stderr empty, and the output line should contain `C:\reports\🧪.txt` intact. To verify the bytes rather than trust the terminal rendering, capture to a file and inspect: `python audit.py | Out-File -Encoding utf8 out.txt`, then confirm `Select-String '🧪' out.txt` matches (or check that the byte sequence `F0 9F A7 AA` appears with `Format-Hex`).
