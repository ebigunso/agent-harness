**Cause**

This is an output-encoding problem, not a bug in the diff logic. Because stdout is a pipe (not a console) and UTF-8 mode is off (`sys.flags.utf8_mode = 0`), CPython 3.12 falls back to the ANSI code page for `sys.stdout` — here `cp932`. The diff contains an em dash (`\u2014`), which Python's cp932 codec cannot encode (cp932 maps 0x815C to U+2015, not U+2014), so `sys.stdout.write(diff)` raises `UnicodeEncodeError` after the trees were already read and compared successfully.

**Partial effects check (before rerunning)**

- The command is read-only; nothing was written to disk.
- stdout is empty, so the failed write emitted no partial bytes into the pipe.
- Safe to rerun with no cleanup.

**Smallest safe remediation**

Rerun with a command-scoped UTF-8 override; either form works in PowerShell 7.4:

```powershell
python -X utf8 tree_diff.py
```

or

```powershell
$env:PYTHONIOENCODING='utf-8'; python tree_diff.py; Remove-Item Env:PYTHONIOENCODING
```

(`-X utf8` is the cleaner one-shot: it affects only that process and doesn't linger in the shell session.)

Durable fix, since the script owns its stdout: near the top of `tree_diff.py`, before line 63,

```python
sys.stdout.reconfigure(encoding="utf-8")
```

If the script ever writes files, use `open(..., encoding="utf-8")` there too. Don't "fix" it by stripping/replacing the em dash — that silently alters the diff output.

**Confirmation**

1. Exit code is 0 and no traceback on stderr.
2. Captured stdout is `before — after\n`; checking the raw bytes shows `E2 80 94` for the dash (e.g., pipe into `Format-Hex` or read it in Python with `sys.stdin.buffer`).
3. Whatever consumes the pipe decodes it as UTF-8, so the dash renders correctly rather than as mojibake.
4. Record for the report: the failing character (`U+2014` under `cp932`) and the exact override command plus its successful output.
