**Cause:** Not a workspace or environment problem. The script hardcodes `$raw = '[1,'`, which is not valid JSON — the array is opened, one element and a trailing comma are present, then the string ends with no second value and no closing `]`. `ConvertFrom-Json` (PowerShell 5.1, backed by `JavaScriptSerializer`) correctly rejects it with `ArgumentException: Invalid array passed in, extra trailing ','`. Because `$ErrorActionPreference = 'Stop'` is set, the non-terminating error becomes terminating and the script exits 1 at line 5. The `raw=[1,` line on stdout confirms the exact bytes that reached the parser. PowerShell itself, the `-File` invocation, execution policy, and cwd are all fine.

**Smallest safe remediation:** Fix the input, not the environment. If the intent is to parse a one-element array, change line 3 to:

```powershell
$raw = '[1]'
```

If the probe's *purpose* is to demonstrate that malformed JSON is rejected before any shape assertion runs, then the current behavior is the expected outcome and the fix is to make the script express that explicitly rather than crashing:

```powershell
try {
    $parsed = $raw | ConvertFrom-Json
} catch [System.ArgumentException] {
    Write-Output ('rejected=' + $_.Exception.Message)
    exit 0
}
```

Do not change execution policy, profile, or PowerShell version — none of those are implicated.

**Confirmation:** Re-run `powershell.exe -NoProfile -File probes/parse.ps1`. For the first fix, expect exit code 0, `raw=[1]` on stdout, empty stderr, and `$parsed` holding an `Int32` `1` (in 5.1 a single-element array unrolls; check with `Write-Output $parsed.GetType().Name` if the type matters).
