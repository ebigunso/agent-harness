**Findings**

1. **`names.ts` — `names` signature is a breaking change and no call sites are in the diff.**
   `names(input)` became `names(input, locale, format)` with two new required parameters. Every existing caller now fails to compile. The diff touches only this file, so either callers are updated in a change I can't see, or this is incomplete. Require: include the caller updates in the same change (or state explicitly that there are none).

2. **`names.ts` — the `format` callback parameter is unrequested generalization that hollows out the function.**
   The task is "explicit locale." That needs `names(input, locale)` with `toLocaleUpperCase(locale)` inside. Instead the diff turns `names` into `input.map(name => format(name, locale))` and pushes the actual behavior (`upper`) out to every caller. After this change, `names` no longer tells a reader what it does — you have to look at each call site to know whether names are uppercased, lowercased, or something else — and the function itself is a one-line wrapper around `Array.prototype.map` that callers could write directly. The reviewer notes argue the callback is *safe* (sync, ordered, pure); that's not in dispute — the issue is that it isn't *needed*, and it costs intent-legibility for no stated benefit. The added comment ("Calls format synchronously in input order, once per name") is a symptom: it exists to document map semantics that the abstraction introduced. Require: `names(input: readonly string[], locale: string): string[] { return input.map(n => n.toLocaleUpperCase(locale)); }`, or a concrete second formatter that justifies the injection point.

3. **`names.ts` (minor) — `Formatter` is used in an exported signature but not exported.**
   Callers writing a formatter can't name the type; they'll re-declare it or rely on inference. If the callback survives review, export the type. If finding 2 is taken, this goes away.

Not blocking on its own: the `locale` value itself — notes say it's validated at startup, and `toLocaleUpperCase` with a valid tag is correct.
