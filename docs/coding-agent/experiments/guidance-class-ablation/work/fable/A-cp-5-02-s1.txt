**Verdict: block.** The change hands an untrusted, unbounded integer straight to the allocator. One finding is severe; the rest are secondary.

---

### 1. `upload.go` — `Handler`, `buffer := allocate(n)`: no bounds check on attacker-controlled `n`

**What's wrong:** `n` comes from `?maxBytes=` with only an integer-parse check. It is passed directly to `make([]byte, n)`. Nothing enforces the allocator's stated contract of 1..8 MiB.

**Why it matters:**
- **Negative `n`** (e.g. `?maxBytes=-1`): `make` panics with `makeslice: len out of range`. `net/http` recovers the panic per-request, but the connection is torn down and a stack trace is logged on every hit — trivially scriptable log-flooding / noise, and any middleware that doesn't expect a panic will misbehave.
- **Large `n`** (e.g. `?maxBytes=9000000000`): on 64-bit, `Atoi` happily returns it and `make` attempts a multi-GB allocation. A handful of concurrent requests OOM-kills the process. This is a remote DoS available to any authenticated user, and "authenticated" is not a meaningful barrier for a resource-exhaustion bug.
- **`n == 0`**: `Atoi("0")` succeeds, yielding a zero-length buffer, which violates the allocator's minimum and will presumably break the upload path this is meant to feed.
- The reviewer notes say the allocator *requires* 1..8 MiB. The patch neither validates at the boundary nor makes `allocate` defend itself, so the invariant lives only in someone's head.

**Require:**
```go
const (
    minUploadBuffer = 1
    maxUploadBuffer = 8 << 20
)

n, err := strconv.Atoi(q.Get("maxBytes"))
if err != nil || n < minUploadBuffer || n > maxUploadBuffer {
    http.Error(w, fmt.Sprintf("maxBytes must be an integer in [%d, %d]", minUploadBuffer, maxUploadBuffer), http.StatusBadRequest)
    return
}
```
Additionally, `allocate` should enforce the same bounds itself (return `([]byte, error)` or panic with a clear message) so future callers can't bypass the check. Add tests for `-1`, `0`, `8<<20`, `8<<20 + 1`, and a very large value.

---

### 2. `upload.go` — `Handler`: missing `maxBytes` is a hard 400, no default

**What's wrong:** An absent parameter makes `Atoi("")` fail, so every existing client that doesn't send `maxBytes` now gets a 400.

**Why it matters:** The task is "allow *configurable* buffer size," which implies the previous fixed size remains the default. As written this is a breaking API change disguised as an enhancement, and it forces clients to learn about an internal tuning knob.

**Require:** Treat an empty/absent value as the default (e.g. the previous fixed size), and only validate when the parameter is present. Document the parameter and its bounds.

---

### 3. `upload.go` — formatting / not `gofmt`-clean

**What's wrong:** Single-line semicolon-joined imports, `[]byte,n` without a space, one-line `if` bodies.

**Why it matters:** Won't pass `gofmt` check in CI; makes the diff harder to review and will generate churn on the next touch.

**Require:** Run `gofmt`/`goimports` before resubmitting.

### Not flagged
- The handler writing `buffer[:0]` and doing no real I/O is acceptable given the note that upload I/O is out of scope for this patch.
- `Atoi` overflow on 32-bit targets returns an error rather than wrapping, so that path is covered by the existing `err != nil` check once the bounds check above is in place.
