**Cause**

This is a workspace/environment problem, not a bug in the manifest logic. On Windows, when Python's stdout is a pipe rather than a real console, CPython 3.12 encodes `sys.stdout` with the ANSI code page (here cp932, Japanese locale) unless UTF-8 mode is on — and `sys.flags.utf8_mode = 0`. cp932 cannot represent U+1F680 (🚀), so the status line `print('built ' + title)` at line 46 raised `UnicodeEncodeError`. Interactively this would have worked, because console output uses a UTF-16 path that never touches cp932.

Important scoping: the failure happened *after* `os.replace` completed. The artifact `manifest.json` is complete, valid, and has the expected hash; nothing else was mutated. Only the cosmetic print and the exit status (1) are wrong.

**Smallest safe remediation**

Don't change the script; turn on UTF-8 mode for the invocation:

```powershell
python -X utf8 build_manifest.py
```

or equivalently, for the session / CI job:

```powershell
$env:PYTHONUTF8 = 1
python build_manifest.py
```

Re-running is safe: generation is deterministic, the write is atomic via `os.replace`, and there are no counters or remote side effects, so the second run rewrites byte-identical content.

(If you *must* fix it in code rather than environment, the minimal patch is `sys.stdout.reconfigure(encoding="utf-8")` near the top of the script — but that's a larger, script-level change than a flag, and the flag is enough here. Avoid `errors="replace"`; it silently corrupts output.)

**Confirmation**

1. Prove the setting takes effect under the same captured-stream conditions:
   ```powershell
   python -X utf8 -c "import sys; print(sys.stdout.encoding, sys.flags.utf8_mode)" | Out-String
   ```
   Expect `utf-8 1`.
2. Re-run `python -X utf8 build_manifest.py` through the pipe; expect exit code 0 (`$LASTEXITCODE`) and stdout `built 🚀` (bytes `62 75 69 6c 74 20 f0 9f 9a 80`).
3. Re-hash `manifest.json` and confirm it matches the pre-existing expected hash — it should be unchanged, demonstrating the rerun was idempotent.

One caveat unrelated to the crash: if PowerShell itself is capturing the pipe (e.g. into a variable or `Out-File`), set `[Console]::OutputEncoding = [Text.Encoding]::UTF8` so it decodes the UTF-8 bytes correctly; otherwise you'll see mojibake rather than 🚀, though the exit code will be 0.
