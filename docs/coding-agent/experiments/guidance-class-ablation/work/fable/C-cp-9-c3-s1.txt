Why it passes the bar:

- **Failure is not hidden.** The thumbnail error is logged with context (upload `id` + the error) and surfaced to the caller as a typed `UploadWarning::ThumbnailUnavailable` with `thumbnail: None`. Clients render the warning, so the degradation is visible end-to-end rather than silently absorbed.

One non-blocking observation (not a request for change): the warning variant carries no reason, so a client can't distinguish "timed out" from "unsupported format." The log line has the detail, and the contract is fixed, so this is fine for now — just worth keeping in mind if retry-on-client logic is ever added.
