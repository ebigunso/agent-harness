**Verdict: block.** The change does not go "through the existing vendor integration" — it goes around it, and around the SDK's own public API, via reflection.

## Findings

### 1. `Feature.scala` — `Feature.refresh` reflects into a private SDK field (`retryClient`)
**What's wrong:** `classOf[Sdk].getDeclaredField("retryClient")` + `setAccessible(true)` + cast to `Sdk.RetryClient` reaches into vendor internals that are explicitly private and not part of the supported contract. It is also unnecessary: `Sdk` already exposes a public `refresh()` that does exactly this.

**Why it matters:** This couples the core feature to a private field name, a nested class name, and the current runtime's reflective-access behaviour. Any SDK rename, inlining, obfuscation, or a move to JPMS/strong encapsulation breaks it at runtime (`NoSuchFieldException` / `InaccessibleObjectException`), not compile time. There is no error handling, so failures surface as uncaught exceptions from a quote refresh. It also does field lookup on every call.

**Require:** Delete the reflection entirely. Call the public SDK surface (`sdk.refresh()`) — and only from inside the gateway, per finding 2.

### 2. `Feature.scala` — `Feature.refresh(sdk: Sdk)` bypasses the `VendorGateway` seam
**What's wrong:** `VendorGateway`/`Gateway` is the owned adapter that isolates the domain from the vendor. `Feature` ignores it and takes the concrete vendor type `Sdk` directly.

**Why it matters:** This is exactly the dependency direction the architecture guidance forbids: a volatile vendor type now leaks into core code, `Feature` is untestable without the real `Sdk`, and the gateway abstraction becomes decorative. `fetch` goes through the seam while `refresh` doesn't, so the two paths will drift.

**Require:**
```scala
trait VendorGateway { def fetch(): String; def refresh(): String }
class Gateway(sdk: Sdk) extends VendorGateway {
  def fetch(): String = sdk.fetch()
  def refresh(): String = sdk.refresh()
}
object Feature { def refresh(gateway: VendorGateway): String = gateway.refresh() }
```
`Feature` should have no import of / reference to `Sdk`.

### 3. Commit message / task mismatch
**What's wrong:** The commit claims "refresh quote through existing vendor integration", but the existing integration (`VendorGateway`) is untouched and unused by the new code.

**Why it matters:** Misleading history; a reader trusting the message would assume the seam was extended. Fixing findings 1–2 makes the message accurate.

**Require:** Keep the message, make the code match it.

### 4. `Sdk.java` — vendor facsimile lands in main sources with no note
**What's wrong (minor):** A hand-written stand-in for the vendor SDK is added alongside production code with nothing indicating it is a facsimile/test double rather than the real dependency.

**Why it matters:** Someone will eventually treat it as the real SDK, or the real SDK will be added and the two will collide on the class name.

**Require:** Either move it to test sources / clearly mark it as a fixture, or reference the actual vendor artifact. Not a blocker on its own, but should be resolved before merge.
