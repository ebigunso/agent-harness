**Cause**

`print(markdown)` failed because `sys.stdout` was opened with the legacy Windows ANSI code page (cp1252), which has no mapping for U+2603 (☃). The traceback path (`encodings\cp1252.py`) and the observation `sys.stdout.encoding = cp1252`, `utf8_mode = 0` line up exactly. The report itself rendered fine (`# Weather ☃`); the crash is purely at the output site.

One nuance versus the reference note: this is not the *console* code page being inherited — stdout here is a pipe, not an interactive console, so CPython falls back to the locale/ANSI code page (cp1252) rather than the OEM console page. Same class of failure, same fix; it just means the problem also reproduces under CI/subprocess capture, not only in an interactive window. Because the offending character is a snowman rather than an em-dash or smart quote, this is a "prose-bearing content" case regardless of which specific legacy page is active.

This is not a workspace-content problem (the data and rendering are correct) and there is nothing to clean up: no files were written, and print-time failure leaves state untouched.

**Smallest safe remediation**

Rerun with the I/O encoding override, no code change:

```powershell
$env:PYTHONIOENCODING = 'utf-8'; python md_report.py
```

(`$env:PYTHONUTF8 = '1'` or `python -X utf8 md_report.py` also works and covers file handles too, but `PYTHONIOENCODING` is the narrowest change and matches the note's step 1.)

If you own `md_report.py`, make it self-sufficient so it doesn't depend on the caller's environment — add near the top:

```python
import sys
sys.stdout.reconfigure(encoding="utf-8")
```

Don't reach for `errors="replace"`; that silently corrupts the report instead of fixing the encoding.

**Confirmation**

1. The rerun exits 0 and stdout contains `# Weather ☃` (the previously offending U+2603 is present, not `?` or `\u2603`).
2. Optionally check in the same captured context: `python -c "import sys; print(sys.stdout.encoding)"` → `utf-8`.
3. One caveat specific to the pipe: the *consumer* must decode the bytes as UTF-8. If the output is being captured into PowerShell variables or piped to another PowerShell cmdlet, set `[Console]::OutputEncoding = [System.Text.Encoding]::UTF8` first, otherwise the Python side will succeed but the snowman may show as mojibake on the receiving end. If a file redirect (`> out.md`) is used instead, verify the bytes with `Get-Content -Encoding utf8` or a hex check (`E2 98 83` for ☃).

Evidence to keep: the original `UnicodeEncodeError ... '\u2603'` traceback and the successful override rerun.
