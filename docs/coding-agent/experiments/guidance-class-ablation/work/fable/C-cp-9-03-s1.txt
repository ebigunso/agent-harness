**Findings**

1. **`src/PaymentClient.java`, `catch (GatewayTimeout timeout)` block — blocking**

   **What's wrong:** On timeout the code calls `store.markPaid(order.id())` and returns `ChargeStatus.PAID`. A timeout means we do not know whether the remote capture happened; the reviewer notes explicitly say it can occur either before or after capture. The catch block collapses "unknown" into "success", which is the exact misreporting the task said to avoid.

   **Why it matters:** For every timeout that happened before capture, the order is recorded as paid and checkout completes with no money collected. There's no signal that anything is uncertain — the catch and the happy path are byte-for-byte identical, so the failure is hidden from the store, the caller, logs, and reconciliation. This is a silent revenue-loss bug that also makes the success path indistinguishable from the ambiguous one after the fact.

   **What I'd require instead:** Treat timeout as indeterminate, not as success:
   - Do not call `markPaid`. Record the order as pending/unknown (e.g. `store.markPending(order.id())`) with the timeout context, and return a status that reflects that (`ChargeStatus.PENDING` or equivalent) so the caller doesn't finalize checkout.
   - Hand the order to the existing reconciliation path so the actual gateway state is queried and the store is updated to PAID or FAILED once known.
   - Optionally, since `paymentKey` is stable and the gateway is idempotent, a bounded retry (e.g. one re-`charge` with the same key) before falling to pending is acceptable — but it must be bounded, and a second timeout must still land in pending, not PAID.
   - Log the timeout with order id / payment key so the ambiguity is visible.

2. **Commit message / intent — flag**

   "complete checkout on gateway timeout" describes the defect as the goal. The commit should describe the actual behavior (e.g. "mark order pending and defer to reconciliation on gateway timeout") so nobody reads the history as endorsing completing checkout on an unconfirmed charge.

The change is **not acceptable as-is**. Finding 1 must be fixed before merge.
