**Cause**

This isn't a workspace/file problem and the `flush=True` was a red herring. When stdout is a pipe (not an interactive console) on Windows, CPython 3.12 doesn't use the UTF‑8 console path; it falls back to the locale's ANSI code page. Your system locale is Japanese, so `sys.stdout.encoding` is `cp932`, and `sys.flags.utf8_mode = 0` confirms UTF‑8 mode is off. cp932 has no encoding for U+1F9EA (🧪), so `print()` raises `UnicodeEncodeError` at the first non-cp932 character (position 8 = right after `Working `). Nothing was written, hence empty stdout and exit 1.

**Smallest safe remediation**

Don't touch the file-scanning logic; fix the stream encoding. Two options, pick one:

1. No code change — enable UTF‑8 mode for the invocation:
   ```powershell
   $env:PYTHONUTF8 = 1
   python progress.py
   ```
   (`PYTHONIOENCODING=utf-8` also works and is narrower, affecting only stdio.)

2. If the script must be self-contained, one line near the top of `progress.py`:
   ```python
   import sys
   sys.stdout.reconfigure(encoding="utf-8")   # also stderr if it prints non-ASCII
   ```

Avoid stripping the emoji or using `errors="replace"` unless the downstream consumer genuinely can't handle UTF‑8 — those silently alter output.

One caveat on the consumer side: PowerShell decodes native-command output using `[Console]::OutputEncoding`, which on a Japanese Windows box is also cp932 by default. If the pipeline's reader is PowerShell itself, set `[Console]::OutputEncoding = [System.Text.Encoding]::UTF8` in that session so the bytes are decoded correctly; otherwise Python will succeed but you'll see mojibake.

**Confirmation**

- Reproduce the pipe condition and check the encoding: `python -c "import sys; print(sys.stdout.encoding)" | Out-String` → should print `utf-8` (with the env var set or after the reconfigure).
- Re-run `python progress.py | Out-String`; expect exit code 0 (`$LASTEXITCODE -eq 0`), no traceback on stderr, and the line `Working 🧪` present in the captured output.
- Optional negative check: unset `PYTHONUTF8` and run again without the code change — the original error should reappear, confirming the diagnosis rather than a coincidental fix.
