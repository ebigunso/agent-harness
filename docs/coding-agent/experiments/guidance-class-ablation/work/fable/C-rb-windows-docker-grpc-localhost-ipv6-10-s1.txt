**Cause**

The failure is not in the probe or the service — it's a local host-networking asymmetry. `localhost` resolves to `::1` first, so the gRPC channel connected to `[::1]:50051`. Docker Desktop's published-port proxy on `::1` accepts the TCP connection but never returns HTTP/2 (h2c) frames, so the client sits until its 2 s deadline and exits 2 with `DEADLINE_EXCEEDED`. The evidence is consistent:

- TCP connect to `[::1]:50051` succeeds, but no HTTP/2 response headers arrive before the deadline.
- The service interceptor log has no entry for the failed call — the request never reached the server.
- The same RPC to `127.0.0.1:50051` (same method, payload, deadline, container, config) succeeds in-deadline: exit 0, stdout `pong`, and the server logs `invoked=true completed=true`.
- The HTTP/1.1 sibling on 50080 answers in 0.012 s, so the container, the port publishing, and the host proxy are healthy; only the IPv6 proxy path for h2c stalls.

Nothing in the workspace (probe code, dependencies, service, port mappings) is broken.

**Smallest safe remediation**

Point the local gRPC target at IPv4 explicitly: use `127.0.0.1:50051` instead of `localhost:50051` in the local probe/config for this environment. Don't edit the hosts file, disable IPv6 system-wide, or change Docker Desktop settings — those are broader than needed and affect other tooling.

**Confirmation**

1. Run `php probes/unary.php --target 127.0.0.1:50051 --timeout 2` (or the same via the updated config) and check: exit 0, stdout `pong`, empty stderr, well under the 2 s deadline.
2. Check the service interceptor log for a new `probe method="unary Echo" transport=h2c invoked=true completed=true` line for that call.
3. Optionally re-run `--target localhost:50051` once to confirm it still hangs, proving the difference is address-only.
4. Record for the ticket: targets `localhost:50051` (→ `[::1]`) vs `127.0.0.1:50051`, deadline output `DEADLINE_EXCEEDED: deadline expired after 2s` / exit 2, REST timing `200 OK` in 0.012 s on 50080, and the IPv4 retry result (exit 0, `pong`, server-side invocation logged).
