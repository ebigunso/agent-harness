## Verdict: Not a workspace problem

This is an **application-level authorization rejection**, not a connectivity, configuration, or environment fault. The command did exactly what the stack is designed to do.

## Cause

The gRPC call succeeded at every layer up to policy enforcement:

- **Transport/port publishing work** — the request reached the server in 15 ms (well inside the 2 s deadline), and the service evidence confirms `invoked=true`.
- **The server itself rejected it** — `status=PERMISSION_DENIED`, `policy=role-required`. The interceptor recorded the request and then denied it because the caller lacked a required role.
- **Exit code 3 is expected** — the probe contract maps `PERMISSION_DENIED` to exit 3 with the normalized message `PERMISSION_DENIED: role required`. This is the probe reporting the server's answer faithfully, not a probe malfunction.

Ruling out the usual suspects:
- **Address asymmetry:** `localhost` and `127.0.0.1` produce identical results (exit 3, same message), so name resolution is not involved.
- **Networking/port publishing:** the HTTP/1.1 sibling on 50080 returns 200 in 12 ms, confirming the Docker port path is healthy.
- **Deadline/timing:** 15 ms response vs. a 2 s timeout — no `DEADLINE_EXCEEDED`, no `UNAVAILABLE`.
- **TLS/cert:** none in play (plaintext h2c), so not a factor.

The `Private` method requires an authorization credential/role that the probe invocation did not carry.

## Smallest safe remediation

Do **not** change addresses, ports, timeouts, or transport — they are all working. Supply the missing authorization the `Private` method requires. Concretely, either:

- Attach the required credential/role to the call (e.g., the auth token or metadata header the interceptor checks), or
- Call a method the current (unauthenticated) identity is authorized for, if you only need to verify reachability.

The credential values are out of scope here; the fix is providing valid authorization, not modifying the workspace.

## How to confirm

Re-run the same command with the required credential attached:

- **Success criteria:** exit code `0` and non-empty **stdout** (the probe prints response values only after a successful call).
- **No `PERMISSION_DENIED`** on stderr.

As a control, a call with a role that is present but insufficient should still return exit 3 / `PERMISSION_DENIED`, while a correctly authorized call flips to exit 0 — isolating the change to authorization alone. Reachability itself is already proven by `invoked=true` and the 15 ms round trip, so no transport reverification is needed.
