**Cause**

This is a file-lock problem, not a dependency, permission, or registry problem. `npm ci` deletes `node_modules` before reinstalling, and the `unlink` of `node_modules\better-sqlite3\build\Release\better_sqlite3.node` fails with `EPERM` (errno -4048) because Windows will not remove a native addon (`.node` is a DLL) that is currently mapped into a running process. `tasklist /m` and the editor test-host log both identify the holder: **Code.exe PID 4110**, the editor's extension/test host, which loaded that exact addon path in an earlier test run and is still alive. The evidence rules out the other suggested causes: lockfile is in sync, project and cache are writable, a probe file beside the module can be created/deleted, no ACL denial, and no other process or extension references the file.

**Smallest safe remediation**

Release the handle by stopping the process that holds it, rather than deleting files or changing permissions:

1. In VS Code, stop the running test session, then restart the extension host (`Developer: Restart Extension Host`) — or simply close the editor window for `C:\work\npm-lock`. This ends PID 4110 cleanly.
2. Only if that fails, terminate it directly:
   ```powershell
   Stop-Process -Id 4110
   ```
   Confirm the PID is still 4110 and still Code.exe first (`Get-Process -Id 4110`) so you don't kill an unrelated process if the PID has been reused.
3. Re-run `npm ci`.

Don't reach for `-Force` removal of `node_modules`, running as Administrator, or disabling antivirus — none of those address the mapped-DLL lock, and running the install elevated could leave root-owned artifacts.

**Confirmation**

```powershell
tasklist /m better_sqlite3.node      # expect: "INFO: No tasks are running which match the specified criteria."
npm ci                                # expect exit code 0
Test-Path .\node_modules\better-sqlite3\build\Release\better_sqlite3.node   # True (rebuilt/reinstalled)
node -e "require('better-sqlite3')(':memory:').prepare('select 1 as ok').get()"   # loads without error
```

Note that because the addon is an editor-runtime source build, once you restart the test host it will need to reload the freshly built binary; keep the test host stopped until `npm ci` finishes to avoid re-locking the file mid-install.
