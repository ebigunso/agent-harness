**Cause:** Working-directory drift in the persistent shell. The prior `Set-Location -LiteralPath 'C:/work/php-app/docs'` left the shell in `C:/work/php-app/docs` (confirmed by `pwd` and by `Get-ChildItem -Name` showing only `README.md`). The failing command uses the relative path `bin/console`, which resolves to `C:/work/php-app/docs/bin/console` — a file that does not exist. PHP therefore reports `Could not open input file: bin/console` on stderr with exit code 1. The file does exist at `C:/work/php-app/bin/console`, so this is a cwd problem, not a missing/broken script, PATH, dependency, or permission issue. The tool UI's remembered root (`C:/work/php-app`) diverged from the shell's actual cwd, which is why the command looked correct from the UI's perspective.

**Smallest safe remediation:** Navigate once, explicitly and absolutely, to the intended base, then rerun the original command unchanged:

```powershell
Set-Location -LiteralPath 'C:/work/php-app'
php bin/console cache:clear
```

No relative `cd ..` chains, no edits to code, config, or environment.
