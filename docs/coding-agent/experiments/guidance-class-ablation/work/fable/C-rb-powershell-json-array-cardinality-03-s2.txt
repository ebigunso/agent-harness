## Cause

This is a **script bug, not a workspace problem**. The raw JSON `["north"]` is a valid single-element array, and the workspace is clean (no files written, valid input).

The failure comes from line 6:

```powershell
$parsed = $raw | ConvertFrom-Json
```

Piping the result unrolls the array. A single-element JSON array `["north"]` therefore emerges as its lone element — the bare string `"north"` — so `$parsed` is `System.String`, not an array. The assertion `-isnot [array]` correctly (from the language's view) fires and throws.

Note this is exactly the "unroll" hazard: `-is [array]` after a pipeline cannot prove wire framing, and here the single-element array is silently flattened to a scalar.

## Smallest safe remediation

You are on PowerShell 7.4.6, so `-NoEnumerate` is available. Change the parse line to avoid enumeration and avoid re-piping the output:

```powershell
$parsed = ConvertFrom-Json -InputObject $raw -NoEnumerate
```

(Equivalently `$raw | ConvertFrom-Json -NoEnumerate`, since the output is assigned directly rather than re-piped — but the `-InputObject` form removes the pipeline entirely and is the least ambiguous.)

This preserves the array type for empty, singleton, and multi-element arrays while a scalar wire value (e.g. `"north"` alone) still parses to a non-array and is correctly rejected — matching the stated contract.

## Confirmation

1. Re-run: `pwsh -NoProfile -File probes/cardinality.ps1`
2. Expect **exit code 0** and stdout `parsed type=System.Object[]` (the assertion no longer throws).
3. Spot-check the contract boundaries with the same fix:
   - `$raw='[]'` → parses to an empty array, passes.
   - `$raw='["a","b"]'` → array, passes.
   - `$raw='"north"'` (bare scalar) → `System.String`, still rejected by the assertion.

If you also want the probe to *prove wire framing* rather than trust `-is [array]`, additionally assert the trimmed raw starts with `[` and ends with `]` before parsing — that guards against the case where a scalar happens to survive as a non-array but you intended array framing. But that is an enhancement; the `-NoEnumerate` change alone fixes the reported failure.
