**Verdict: not a workspace/project problem.** The probe files, dependencies, build, and service are all fine (the service answers the same RPC correctly when addressed by IPv4). This is a host-side name-resolution vs. Docker Desktop port-publishing asymmetry.

**Cause**

On this Windows host, `localhost` resolves to `::1` first, then `127.0.0.1`. grpcurl (grpc-go) dials `[::1]:50051`. Docker Desktop's WSL2 port proxy accepts the TCP connection on the IPv6 loopback, but the connection is never actually serviced by the container's h2c listener — no HTTP/2 server preface/settings frame ever comes back. Because the TCP connect *succeeds*, there's no connection-refused error to trigger a fallback to `127.0.0.1`; grpc-go just waits for the transport handshake until `-max-time 2` expires, giving `Failed to dial target host "localhost:50051": context deadline exceeded`. This happens before reflection or the `Ping` RPC is ever sent, which is why the interceptor log shows no invocation.

The evidence is unambiguous: the identical command against `127.0.0.1:50051` exits 0, returns `{"value":"pong"}`, and the service log records `invoked=true completed=true`. The curl comparison on 50080 isn't a counterexample — curl uses happy-eyeballs and completes over whichever loopback address answers, so it masks the same asymmetry.

**Smallest safe remediation**

Address the service by IPv4 loopback instead of `localhost`:

```powershell
grpcurl -plaintext -max-time 2 -d '{}' 127.0.0.1:50051 demo.Probe/Ping
```

This changes nothing in the project, container, or Docker configuration. (If you want it durable so `localhost` works for everyone, the next-smallest change is publishing the port as `127.0.0.1:50051:50051` in the compose/run mapping — but that's a config change and not required to unblock the call.)

**Confirmation**

1. Run the command above: expect exit code 0 and stdout `{ "value": "pong" }`, stderr empty.
2. Check the service interceptor log for a new line `probe method="unary demo.Probe/Ping" transport=h2c invoked=true completed=true` correlated with that run.
3. Optionally, `grpcurl -plaintext 127.0.0.1:50051 list` should return `demo.Probe` via reflection, proving the full h2c handshake and reflection path work.
4. To confirm the diagnosis rather than just the workaround, run `grpcurl -plaintext -max-time 2 -d '{}' [::1]:50051 demo.Probe/Ping` — it should reproduce the exact `context deadline exceeded` failure, isolating `::1` as the sole variable.
