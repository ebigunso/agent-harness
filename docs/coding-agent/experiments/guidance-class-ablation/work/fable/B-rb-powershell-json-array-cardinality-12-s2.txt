**Verdict:** not a workspace/environment problem. The script's assertion is measuring pipeline unrolling, not JSON framing.

**Cause**

`$parsed = $raw | ConvertFrom-Json` emits the parsed value through the pipeline. `ConvertFrom-Json` enumerates a top-level array by default, so the one-element array `[null]` is unrolled and its single element — `$null` — is what lands in `$parsed`. That's why stdout shows `parsed type=<null>` and why `$parsed -isnot [array]` throws. The wire value is a legal singleton array; the script is discarding the framing before it checks it. (Any singleton array would misfire the same way; `[null]` just makes it look like the parser returned nothing.)

**Smallest safe remediation**

You're on pwsh 7.4.6, so `-NoEnumerate` is available. Change line 5 to:

```powershell
$parsed = ConvertFrom-Json -InputObject $raw -NoEnumerate
```

(`$raw | ConvertFrom-Json -NoEnumerate` also works because the result is assigned rather than re-piped; the `-InputObject` form just removes the pipeline from the picture entirely.) Do not pipe `$parsed` anywhere afterward or it will unroll again.

Nothing else needs to change: `$null -eq $parsed` is a scalar-on-left comparison so it does not filter the array and correctly yields `False`; `.GetType().FullName` will report `System.Object[]`; `-isnot [array]` becomes false.

If this ever has to run under Windows PowerShell 5.1 (no `-NoEnumerate`), fall back to asserting on the raw string instead: `$raw.Trim().StartsWith('[') -and $raw.Trim().EndsWith(']')`.
