Reviewer notes: find_by_email returns nil only for absent rows. During replica outages the write primary can still accept creates. Calls are serialized for this fixture, and no create race is being tested. The contract reserves nil for genuine not-found.

- **`lib/customers.rb`, `find_customer` rescue clause:** Returning `nil` for `DatabaseUnavailable` violates the contract that `nil` means genuinely not found and hides the outage. Consequently, `get_or_create` may create a duplicate customer on the writable primary when the existing customer could not be looked up. Require an explicit failure at the repository boundary—propagate the exception or wrap it in a contextual repository error—and ensure `get_or_create` creates only after a successful lookup confirms absence. Verify that an outage remains diagnosable and never triggers creation.
