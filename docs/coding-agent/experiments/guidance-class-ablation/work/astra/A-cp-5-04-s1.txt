- **`Ingress.java:9` — Offset-aware timestamps are not normalized to UTC.** `OffsetDateTime.toString()` preserves the supplied offset. For example, `2026-09-09T10:00:00+09:00` must be queued as `2026-09-09T01:00:00Z`. The current output violates the queue contract and can cause downstream to schedule the wrong instant. Require conversion through `toInstant().toString()` before enqueueing.

- **`Ingress.java:8` — Naive timestamps are accepted.** The `LocalDateTime::from` fallback accepts input without an offset, such as `2026-09-09T10:00:00`, which downstream implicitly treats as UTC despite its ambiguity. Require an explicit offset and reject naive input by removing that fallback, allowing the existing transport error handling to return 400.
