Reviewer notes: Scala 2.13/JDBC. Caller owns a transaction with autoCommit=false and may roll back after DAO update. audit is an independent event sink; an Approved event means committed business approval.

codex
- **`ApprovalDao.scala:8` — Audit event precedes transaction commit.** `executeUpdate()` does not commit the caller’s transaction. The independent sink can receive `Approved` even if the caller later rolls back, violating the event’s meaning. Require publication tied to successful commit; for reliable recording, persist an outbox event in the same transaction and publish it after commit.

- **`ApprovalDao.scala:3–8` — Persistence code owns business audit policy.** A generic status-update DAO decides that `"approved"` warrants an `Approved` business event and invokes an external sink. This puts approval policy and event orchestration in the persistence layer. Require domain/application logic to decide when an approval event is warranted, with the DAO limited to persistence and commit-safe delivery handled by transaction/event infrastructure.
