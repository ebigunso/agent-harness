The cause is **PowerShell’s function-output enumeration**, a script bug rather than a workspace or permissions problem. `ConvertFrom-Json -NoEnumerate` preserves `[7]` as an array in `$items`, but the bare `$items` expression emits its elements. With one element, `$parsed` becomes `System.Int64`.

The smallest safe fix is to preserve the array at the function boundary using a unary comma:

```powershell
function Parse {
    $items = $raw | ConvertFrom-Json -NoEnumerate
    ,$items
}
$parsed = Parse
```

The comma adds an outer array for PowerShell to enumerate, leaving the original value intact. Scalar JSON still produces a scalar and fails the existing assertion. Wrapping the caller in `@(Parse)` would incorrectly make scalars pass.
