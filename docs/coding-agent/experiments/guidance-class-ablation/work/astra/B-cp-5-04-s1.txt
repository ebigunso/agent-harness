Reviewer notes: Java 17. queue stores ISO UTC instants and downstream interprets each string as UTC. Offset-aware ISO input should denote the same instant; naive input is ambiguous and must be rejected. Parsing syntax errors already return 400 in transport.

codex
- **Ingress.java:9 — Offset timestamps are not normalized to UTC.** `parsed.toString()` preserves the input offset. For example, `2026-09-09T10:00:00+09:00` must become `2026-09-09T01:00:00Z`; storing the original offset representation violates the queue’s UTC invariant and risks incorrect scheduling downstream. Require conversion to `Instant` and enqueue `instant.toString()`.

- **Ingress.java:8 — Naive timestamps are accepted.** The `LocalDateTime::from` fallback accepts input without an offset, despite the requirement to reject ambiguous timestamps. Downstream then implicitly treats that local time as UTC. Require offset-bearing input, for example through `OffsetDateTime.parse(input, DateTimeFormatter.ISO_DATE_TIME)`, so missing offsets fail through the existing parse-error-to-400 handling before anything is enqueued.
