Reviewer notes: SQLite is shared by separate service and batch OS processes. invoices.id is a primary key; collisions surface as failed creations. Existing database supports authoritative auto-generated integer IDs. There are no other writers; inputs are validated before these functions.

codex
- **`invoices/allocate.go`: `HTTPCreate` mutex and `allocate` ID generation.** The mutex only serializes HTTP calls within one process. Batch workers and separate service processes can still read the same `MAX(id) + 1` before either inserts, causing primary-key collisions and failed creations. This leaves the task’s underlying race unresolved. Require `allocate` to use the database’s authoritative auto-generated integer IDs and retrieve the ID from that insert, so both HTTP and batch creation are safe across processes. Remove the now-unnecessary HTTP mutex.
