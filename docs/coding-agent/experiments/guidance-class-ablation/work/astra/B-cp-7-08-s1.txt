codex
- **`test_limit.rb:4–16` — Parallel tests share and leak `ENV["LIMIT"]`.** `CustomLimitTest#setup` sets the process-wide limit to `"2"` without restoring it, while `DefaultLimitTest` assumes the variable is absent. With parallel execution, `permitted?(5)` can read `"2"` and fail depending on scheduling; an inherited `LIMIT` can also invalidate the default test. Require isolated configuration: preferably inject the limit or configuration source and test explicit custom and absent-value cases. If tests must modify `ENV`, serialize all tests accessing that variable, explicitly unset it for the default case, and restore its previous value afterward. Restoration alone does not prevent concurrent interference.
