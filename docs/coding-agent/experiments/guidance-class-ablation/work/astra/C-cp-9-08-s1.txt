Reviewer notes: find_by_email returns nil only for absent rows. During replica outages the write primary can still accept creates. Calls are serialized for this fixture, and no create race is being tested. The contract reserves nil for genuine not-found.

codex
- **`lib/customers.rb`, `find_customer` rescue clause:** Returning `nil` for `DatabaseUnavailable` violates the contract reserving `nil` for a genuinely absent customer. It also makes `get_or_create` attempt a create during a lookup outage; because the write primary can remain available, this can create a duplicate customer or trigger a constraint failure. Require an explicit repository-level lookup-unavailable error with operation context and the original exception preserved as its cause. Propagate that failure so `get_or_create` does not attempt creation when lookup availability is unknown.
