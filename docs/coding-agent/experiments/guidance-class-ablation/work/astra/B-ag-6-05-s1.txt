Commit message: "retry uncertain object uploads"

Reviewer notes: C# storage client honors timeout/cancellation internally and throws TimeoutException on unknown outcome. Create is idempotent only for a stable key. Retry is bounded at three; fresh key after unknown success creates extra stored objects.

codex
- **Upload.cs:7 — Retries use a new object key.** A timeout means the previous create may have succeeded. Generating a fresh GUID on each attempt defeats the storage API’s idempotency and can create up to three stored objects for one upload. Generate the key once before the retry loop and reuse it with the same data on every attempt. Require a test that simulates a successful write followed by a timeout and verifies the retry leaves exactly one object.
