### Gate 4: Explicit Interface Contracts

**Expectation**
- Boundaries between components are explicit, minimal, and stable.
- Inputs, outputs, and failure semantics are intentionally modeled.

**Evidence expectations**
- Plan states contract-impact scope (none/additive/breaking).
- Review verifies contract updates are synchronized across producers/consumers.
- Failure modes are explicit and not silently swallowed.

**Anti-patterns**
- Implicit contracts communicated only by call-site assumptions.
- Breaking contract changes shipped without migration or compatibility notes.
- Returning ambiguous success/failure signals.

Reviewer notes: Java 17. One caller passes LocalDateTime.now(UTC), but public adapter accepts timestamps from other zones with no encoded timezone contract. Queue stores UTC instants.

codex
- **`Inventory.java:4` — `schedule` silently assumes UTC for a timezone-free input.** `LocalDateTime` carries no offset or zone, so `toInstant(ZoneOffset.UTC)` misinterprets timestamps supplied in other zones and queues snapshots at the wrong instant. The existing UTC caller does not establish a contract for the public API. Require an `Instant`, `OffsetDateTime`, or `ZonedDateTime`, and update callers consistently. If local wall time is intentional, require a `ZoneId` and define handling for daylight-saving gaps and overlaps. Document the contract change and any compatibility implications.
