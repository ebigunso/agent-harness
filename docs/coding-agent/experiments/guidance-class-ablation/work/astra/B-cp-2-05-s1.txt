Reviewer notes: SQLite is shared by separate service and batch OS processes. invoices.id is a primary key; collisions surface as failed creations. Existing database supports authoritative auto-generated integer IDs. There are no other writers; inputs are validated before these functions.

codex
- **`invoices/allocate.go` — `allocate` / `HTTPCreate`: The mutex does not fix duplicate ID allocation across writers.** It serializes HTTP calls only within one process; batch calls and separate service processes can still read the same `MAX(id) + 1` before either inserts. The primary key then rejects one creation, so the reported failure remains. Require a fix in the shared `allocate` function: let the database generate the integer ID atomically during insertion and retrieve that insert’s generated ID. Remove the HTTP-only mutex once allocation is database-managed.
