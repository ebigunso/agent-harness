Reviewer notes: Producer DateTime has Kind.Utc. Consumer process runs with local zone UTC+09:00; naive datetime.astimezone uses that zone. Published createdAt field denotes a UTC instant, with second precision sufficient for this API.

codex
- **`Wire.cs`, `CreatedAt` (and `client.py:3`)**: The new format drops the UTC designator. Python parses the result as a naive datetime, so `.astimezone(timezone.utc)` interprets it in the consumer’s UTC+09:00 local zone. A creation time of `12:00:00Z` therefore becomes `03:00:00Z`, violating the published UTC-instant contract. Require an explicit UTC marker in the serialized value, such as `yyyy-MM-dd'T'HH:mm:ss'Z'` given the guaranteed `Kind.Utc`, and verify that the consumer preserves the instant when running in UTC+09:00. Dropping fractional seconds is acceptable under the stated precision requirement.
