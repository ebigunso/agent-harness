- **`lib.rs:4` — Queued-work failures are unobservable.** Dropping the `JoinHandle` discards the job’s `Result`, so an `Err` produces no inspectable failure signal. Require a retained and observed handle or a worker wrapper that reports completion/failure correlated with the safe job ID. Avoid logging payloads or arbitrary error strings that may contain sensitive data.

- **`lib.rs:3–4` — Launch is reported before it succeeds.** `spawned:{id}` is emitted before `thread::spawn`, which can fail by panicking, leaving a misleading success event. Require the launch-success signal only after successful thread creation, and an inspectable launch-failure path, for example using `thread::Builder::spawn` and handling its `Result`.
