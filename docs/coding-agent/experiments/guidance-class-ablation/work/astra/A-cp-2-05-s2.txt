Reviewer notes: SQLite is shared by separate service and batch OS processes. invoices.id is a primary key; collisions surface as failed creations. Existing database supports authoritative auto-generated integer IDs. There are no other writers; inputs are validated before these functions.

codex
- **`invoices/allocate.go` — `HTTPCreate` locking and `allocate` ID generation:** `httpMu` only serializes HTTP calls within one process. Batch calls bypass it, and separate OS processes cannot share it. HTTP and batch workers can still read the same `MAX(id) + 1`, then attempt to insert the same primary key, causing a failed creation. Require using the database’s supported auto-generated integer IDs and retrieving the ID assigned by that insert. Extending the mutex to `BatchCreate` would not resolve the cross-process race.
