A future event type such as `"refunded"` causes `handlers[type]()` to throw; inherited names such as `"toString"` can invoke an unintended function. Future types are explicitly possible, so this is a reachable failure. Require an explicit `paid`/`cancelled` switch or an own-property check before dispatch, plus a defined unsupported-event response consistent with the webhook acknowledgement contract.
