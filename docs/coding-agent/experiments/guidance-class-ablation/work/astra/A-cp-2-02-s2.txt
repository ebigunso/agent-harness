Reviewer notes: Debit and credit are in the same database; LedgerStore can transact both. CreditFailed means credit rolled back after debit committed. ScheduledTransferJob calls LedgerService.transfer directly. Inputs and balances are validated by the existing store; only the transaction boundary is at issue.

codex
- **`src/Transfers.java`, `TransferRoutes.post` catch block:** A separately committed refund does not make the transfer atomic. If the refund fails or the process stops after the debit commits, the debit remains without a credit. Require debit and credit in a single database transaction so credit failure rolls back the debit.

- **`src/Transfers.java`, `LedgerService.transfer`:** The fix applies only to HTTP requests. `ScheduledTransferJob` calls this unchanged method directly, so credit failure still leaves a committed debit. Require the transaction boundary inside `LedgerService.transfer`, shared by both callers, and remove the route-level refund once rollback handles failure.
