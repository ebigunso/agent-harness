codex
- **`lib.rs:3–5` — Resource removal leaves a stale registry entry.** `resources.remove(&id)` removes the resource while the registry still advertises it. This violates the requirement that every advertised ID resolve to a live resource; if `cleanup()` returns `Err`, `?` skips unregistration and leaves the inconsistency after the function returns. Require unregistering the ID **before** removing its resource, then running fallible cleanup, so cleanup failure cannot leave an advertised ID without a resource.
