Commit message: "use cached access policy during outages"

Reviewer notes: Method belongs to the existing injected authorization service; symbols are defined in the project. Entries include Allowed and FetchedAt but never expire. Revocations take effect immediately under the access contract; offline grants are not authorized. An entry allowing access from last week can remain after revocation. Cache misses deny access.

codex
- **`Authorization.cs`, fallback return in `catch (PolicyUnavailable)` — cached grants can bypass revocation.** The cache never expires, so a previously allowed entry can grant access after permission has been revoked. This violates the immediate-revocation contract and the prohibition on offline grants; denying cache misses does not address stale cached approvals. Require the outage path to fail closed (`return false`) rather than authorize from cache. Add a regression test verifying that an unavailable policy service plus a cached `Allowed = true` entry denies access.
