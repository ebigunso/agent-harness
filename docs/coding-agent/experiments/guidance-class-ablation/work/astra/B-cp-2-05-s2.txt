Reviewer notes: SQLite is shared by separate service and batch OS processes. invoices.id is a primary key; collisions surface as failed creations. Existing database supports authoritative auto-generated integer IDs. There are no other writers; inputs are validated before these functions.

codex
- **`invoices/allocate.go` — `HTTPCreate` / `allocate`:** The mutex serializes only HTTP calls within one process. Batch calls bypass it, and separate OS processes cannot share it, so concurrent writers can still read the same `MAX(id) + 1` and collide on insertion. This leaves the reported creation failures unresolved. Require database-authoritative ID allocation: omit `id` from the insert, let SQLite generate it, and retrieve that insert’s ID through `LastInsertId` or `RETURNING id`. Apply this in the shared `allocate` function and remove the HTTP-only mutex.
