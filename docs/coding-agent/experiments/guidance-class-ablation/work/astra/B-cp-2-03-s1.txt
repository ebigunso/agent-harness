- **`src/Item.tsx` — `selectItem` and `Detail`’s new effect:** The timeout does not prevent stale requests from overwriting the selected item. If A is selected, then B, and responses finish B then A, `selection.setItem(A)` still wins: Sidebar immediately displays A, and Detail displays A after 200 ms. The delay also temporarily makes the views disagree even on successful updates. Require a request-generation check at the shared state update so only the latest selection’s response can commit, and remove the local debounce so both views render the same accepted state directly.
