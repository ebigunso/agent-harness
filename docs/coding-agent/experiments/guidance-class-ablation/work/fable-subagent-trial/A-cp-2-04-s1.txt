Verdict: block. The change does not do the task and adds code that hides the bug it was meant to fix.

1. app/export.py, destination() (unchanged by the diff)
   What is wrong: destination() still returns Path(config.export_subdir) / name, i.e. the relative path "daily/<name>". config.export_root (/srv/exports) is never used. The task was to restore the absolute output root; this diff does not touch the line where it was dropped.
   Why it matters: With cwd /srv/app, every CLI and batch export resolves to /srv/app/daily/<name>, not /srv/exports/daily/<name>. Consumers reading from the configured root see no output; the app directory accumulates data files.
   Require: destination() must build the path from the root: Path(config.export_root) / config.export_subdir / name. That is the whole fix.

2. app/export.py, write_export() try/except FileNotFoundError + mkdir(parents=True)
   What is wrong: The FileNotFoundError being caught is the symptom of finding 1 (the parent "daily" does not exist relative to /srv/app because the real, configured directory is somewhere else). The fallback creates /srv/app/daily on demand and writes there, so the misdirected write now succeeds silently.
   Why it matters: This converts a loud failure into a quiet one. The configured /srv/exports/daily already exists and is writable, so there is no legitimate case in this codebase where write_export needs to create directories; the only thing the mkdir does is manufacture a wrong destination whenever the path is wrong. It also means any future path bug (bad config, another refactor) will again succeed into a stray directory rather than fail.
   Require: Remove the try/except and the mkdir; restore the single write_bytes call. If on-demand directory creation is genuinely wanted later, it should be a separate, explicit decision (e.g. a one-time mkdir at startup against the configured root), not an exception-driven retry.

3. Commit message "create missing export folders"
   What is wrong: Describes the workaround, not the task. Nothing in the diff or message mentions export_root or the dropped root.
   Why it matters: Anyone reading history for why exports moved will not find this commit; and the message asserts a behaviour (auto-creating export folders) that was never requested and should not be kept.
   Require: Message that states the actual change, e.g. "Restore export_root in destination()".

4. Missing regression test
   What is wrong: The root was dropped by a refactor and nothing caught it; this diff again ships without a test on the resolved path.
   Why it matters: The same regression can recur on the next refactor, and finding 2 shows how easy it is to "fix" it in a way that passes a naive smoke test.
   Require: One test asserting destination(config, "x") == Path("/srv/exports/daily/x") (or that the resulting path is absolute and starts with export_root). Test data is regenerable and writes are sequential, so a tmp-dir based write test is also cheap if the author prefers exercising write_export.
