Verdict: not acceptable. Block.

Findings

1. app/export.py, destination() (unchanged by the diff, but it is the defect the task names)
   What is wrong: destination() still returns Path(config.export_subdir) / name, i.e. the relative path "daily/<name>". config.export_root ("/srv/exports") is never used. The reviewer notes state a refactor dropped export_root here; this diff does not put it back.
   Why it matters: the task is "restore exports to the configured absolute output root for CLI and batch". With cwd = /srv/app, every CLI and batch export resolves to /srv/app/daily/<name>, not /srv/exports/daily/<name>. The stated objective is not met by this change at all.
   Require: destination() must build the absolute path from the root:
       return Path(config.export_root) / config.export_subdir / name
   (names are validated basenames, so the join is safe). Add a test asserting destination(config, "x") == Path("/srv/exports/daily/x") so the root cannot be dropped silently again.

2. app/export.py, write_export(): the try/except FileNotFoundError + mkdir fallback
   What is wrong: this does not fix the bug; it hides it. The FileNotFoundError the author saw was the symptom of writing to the wrong (relative) location. The fallback answers it by creating /srv/app/daily and writing there, so the write now "succeeds" into the wrong directory with no error, and the misplacement becomes invisible. Worse, because the path is cwd-relative, this code will mkdir and write under whatever directory the process happens to be started from.
   Why it matters: exports silently land outside the configured root; downstream consumers of /srv/exports/daily see nothing; the only signal that would have flagged the regression is suppressed. Retrying write_bytes after mkdir also double-writes on the error path for no reason.
   Require: remove the try/except entirely. /srv/exports/daily is stated to exist and be writable, so once finding 1 is fixed the original one-line write_bytes is correct. If auto-creating the output directory is genuinely wanted, that is a separate, explicitly requested change and should be a plain target.parent.mkdir(parents=True, exist_ok=True) before the write (not an exception-driven retry), and it must only ever run against the absolute root path.

3. Commit message "create missing export folders"
   What is wrong: it describes the workaround, not the task, and the folder it "creates" is the wrong one. The change it should describe is "use export_root in destination() so exports go to the configured absolute path".
   Why it matters: history will record a directory-creation feature where a path regression fix was needed, misleading anyone bisecting the misplaced-export bug later.
   Require: rewrite the commit message to describe the root-cause fix once finding 1 is applied.

No other issues: cli_export and batch_export correctly route through write_export, so fixing destination() fixes both paths at once; no change is needed in those functions.
