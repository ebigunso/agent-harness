The cause is in the workspace’s PowerShell checker. `ConvertFrom-Json` enumerates arrays by default, so assigning its singleton output produces a `PSCustomObject`; the assertion then throws. The HTTP producer and JSON are correct. [PowerShell documentation](https://learn.microsoft.com/powershell/module/microsoft.powershell.utility/convertfrom-json?view=powershell-7.4)

The smallest safe fix is to add `-NoEnumerate`:
```powershell
$parsed = $raw | ConvertFrom-Json -NoEnumerate
