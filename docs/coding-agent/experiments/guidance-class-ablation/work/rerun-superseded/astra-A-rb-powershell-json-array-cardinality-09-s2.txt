codex
The cause is a bug in `probes/cardinality.ps1`. In Windows PowerShell 5.1, `ConvertFrom-Json` preserves the array, but the trailing `Write-Output` enumerates it. Assignment captures its sole element as `System.Boolean`, causing the assertion to throw. This behavior is documented in the [PowerShell issue tracker](https://github.com/PowerShell/PowerShell/issues/3424). The JSON file and its whitespace are valid.

The smallest safe fix is to remove `| Write-Output`:

```powershell
$raw = Get-Content -Raw data.json
$parsed = $raw | ConvertFrom-Json
```

Keep the existing assertion. Wrapping the result in `@(...)` would also turn scalar inputs into arrays, violating the contract.

Also check that `[]`, `[true]`, and `[true,false]` pass, while `true`, `1`, `"x"`, `null`, and `{}` fail. I verified these type distinctions on locally installed Windows PowerShell 5.1.26100.9168; the supplied build should receive the same checks.
