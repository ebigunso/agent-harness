The cause is a script pipeline bug, not invalid JSON or a workspace/environment problem. Windows PowerShell 5.1 preserves the array from `ConvertFrom-Json`, but the trailing `Write-Output` enumerates it. Assignment then captures the singleton as a `PSCustomObject`, triggering the assertion. ([PowerShell reference](https://github.com/PowerShell/PowerShell/issues/3424))

The smallest safe fix is to remove `| Write-Output`:

```powershell
$parsed = $raw | ConvertFrom-Json
