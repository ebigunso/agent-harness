The cause is script-level array enumeration, not a workspace or execution-policy problem. `-NoEnumerate` preserves the converter’s array output, but piping the parenthesized result through `ForEach-Object` enumerates it again. Assignment receives one object, so `$parsed` becomes a `PSCustomObject` and the assertion throws. [Microsoft documentation](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.utility/convertfrom-json?view=powershell-7.4)

The smallest safe fix is to replace the assignment with:

```powershell
$parsed = $raw | ConvertFrom-Json -NoEnumerate
```

Keep the array assertion. Don’t wrap the result in `@(...)` or cast it to `[array]`: that would also turn scalar inputs into arrays, violating the contract. `$wireCount` is hard-coded and proves nothing about the parsed type.
