**Cause:** This is a script logic error, not a workspace configuration problem. In Windows PowerShell 5.1, `ConvertFrom-Json` preserves the JSON array, but the trailing `Write-Output` enumerates it. Assignment then stores its single element as a `PSCustomObject`, triggering the assertion. [PowerShell behavior reference](https://github.com/PowerShell/PowerShell/issues/3424)

**Smallest safe remediation:** Remove `| Write-Output` from the assignment:
```powershell
$parsed = $raw | ConvertFrom-Json
```
Keep the existing array assertion. Simply wrapping the original pipeline in `@(...)` would also wrap scalar inputs, incorrectly accepting them.
