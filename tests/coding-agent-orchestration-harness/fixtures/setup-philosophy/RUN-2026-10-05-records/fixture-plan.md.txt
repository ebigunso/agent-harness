# Plan: Tally names the file it could not read

- status: draft
- generated: 2026-10-05
- last_updated: 2026-10-05
- work_type: code

## Goal
- When the file is missing or unreadable, tally says so in one plain sentence that names the file, prints no number, and exits non-zero; a successful count is unchanged.

## Definition of Done
- D1: When the file given is missing or unreadable, tally writes exactly one line, `tally could not read <path>.`, where `<path>` is the argument as the user typed it (for `python tally.py notes.txt`: `tally could not read notes.txt.`).
- D2: In that case tally prints no number.
- D3: In that case tally exits non-zero.
- D4: A successful count is unchanged: the number alone on one line (the `common.md` check still gives `21` for `README.md`).

## Planner-added requirements
- P1: The failure sentence goes to standard error and standard output stays empty. Needed because: under the chosen design the count is the only thing on standard output, so a pipe reading standard output must get nothing, not the sentence, when no count was made; this keeps the current stream.

## Scope / Non-goals
- Scope: the failure message in `tally.py`.
- Non-goals:
  - N1: No sentence around a successful count; it stays the number alone (user's answer, Decision Log 2026-10-05).
  - N2: No fallback that counts the characters of the path when the file is missing (user's answer, Decision Log 2026-10-05).

## Design
- Chosen: name the file by the path exactly as given on the command line, in the existing `except` branch. Structure: no new state, no conversion of the argument. Evolution: one string changes; deletion path is reverting it. Verification: checked by running the script on a missing path and on a directory, as today's check runs it. Operation: no change. Human: the name shown is the one the user typed, so it predicts what to fix. Safety: echoes only the user's own argument, to the user's own terminal.
- Alternative: name the file by its base name only (`Path(arg).name`). Structure: adds a conversion of the argument. Evolution: same size. Verification: same checks. Operation: no change. Human: `tally could not read notes.txt.` for `drafts/notes.txt` hides which directory was tried, so two files of the same name are indistinguishable. Safety: shows slightly less of the path.
- Why chosen: the path as given tells the user exactly what tally tried to open, needs no conversion, and matches the request's example when the user types a bare file name.
